# 采样声库时值：直接控制与编辑器侧计算

2026-10-16。结论：**两个方向都有实证，但目前适合做“带约束的规划接口”，还不能把所有情况替换成一条编辑器公式。** 下文先记录系数探索与可靠性取舍，末尾记录随后实现的独立基础层。没有修改拖动实现、安装文件或用户配置，没有操作 Editor。

[数值证据](evidence/timing-coefficient-control.json)保存二进制/探针源码哈希、曲线、失败见证、素材元数据和音频 data 区哈希。[实验入口](../voicebank/tools/evec_render_harness/TimingCoefficientProbe.cs)为 `--timing-coefficient-probe`。

## 直接操作引擎已经成立

原生 NOTE 的 VEL 并非直接作为最终长度使用。当前 DSE 把它解码为浮点系数，再交给音素长度整形与目标时长分配。实测全部 128 个解码值：VEL 0–126 对应 `v / 128`，127 对应 `1.0`。这是当前哈希的实际映射，不能无条件套到其它版本。

在隔离进程中，把目标 NOTE 的提交事件分成前后两段，在提交之前设置它自己的解码系数，再继续原生规划和正常音频渲染。没有修改声库、共享素材、函数机器码或 Editor 内存。源音符最终仍为 VEL64；探针通过统一的 63→64 失效操作强制各次私有渲染，实际测试的差异来自解码后的系数。

验证覆盖 MIKU/RIN，孤立与连音，`k a`、`n a`、`s a`、`j a`、`h e`、`m a`、多音素，短音符、高音和前方休止：

- **1,792 组**普通 VEL 的完整边界列表，等于现有局部后端的对应结果。这一组的对照是既有后端，不是重新合成 1,792 份音频。
- **7,182 个**更细系数点只做规划，候选阶段 Native Start、PCM Step、Samples 均为 0，合成帧位置保持 0。
- 14 个场景中 **9 个**找到普通 128 档无法到达的新边界。各挑一个新点正常合成，**9 份最终音频的完整边界都等于无音频预测，PCM 都发生变化**。
- 每个场景有普通重渲染、拆分但不修改、写回原系数、修改后恢复四种对照，合计 **56 份 PCM 与各自参考逐字节相等**。对照统一先预热，再采用相同的失效历史。

例如 MIKU 孤立 `k a`，普通 VEL 只有 41 种不同边界；本轮 513 个系数点得到 53 种。系数 `0.00390625` 得到相对 tick `[-303, -2, 477]`，不属于普通 VEL 的结果集合，最终音频也得到同一列表。它证明可以扩展可达位置，不代表所有鼠标位置都能精确落到。

| 场景 | 普通 VEL 不同结果数 | 513 个系数点不同结果数 |
| --- | ---: | ---: |
| MIKU `k a`，孤立 | 41 | 53 |
| MIKU `k a`，连音 | 43 | 45 |
| MIKU `n a`，孤立 | 23 | 23 |
| MIKU `n a`，连音 | 22 | 24 |
| RIN `k a`，孤立 | 36 | 40 |
| MIKU `h e`，孤立 | 42 | 49 |
| MIKU `k a`，前方休止 | 37 | 40 |

**浮点控制仍受原生帧网格限制。** 当前为 44100 Hz / 256 采样，约 5.805 ms 一帧。系数更细能填补部分 VEL 跳过的帧，不会自动变成任意采样点级的音素移动，也没有证明可以分别任意移动全部音素边界。

## 可以让后端返回哪些额外信息

本轮已从私有规划结果中读出并保存：

- 过渡的真实起止帧、左右分配长度、from/to 音素与两项音素标志；
- 所选素材在当前查询会话内的身份、stage、limit、方向、bank/unit；
- 所选 stage 的左右 alignment：两侧各自的 outer 与 inner 四个坐标；
- 实际声库 PHDC 类别，持续单元及其长度。

这些是数值快照，不把原生指针放进证据或跨次查询持有。持续单元没有普通 ART 的两组 alignment，必须单独处理。

因此后端完全可以从“只给边界数组”改成“给边界、素材依据和规划解释”。但本轮取得的主要是**分配后的结果和素材原始区间**；“所有候选都适用的有效长度、约束范围、分支条件”还没有全部取得。不能把素材的 inner/outer 直接命名为可拖动的最小/最大值。

## 编辑器直接计算的实证与反例

对一个音素前后的匹配接点，原生整形存在可独立计算的规律。令 `c` 为内部系数，`O` 为两侧 outer 长度总和，类别常数为 `K`：

```text
c < 0.5 : scale = (max(K, 2O) / O) ^ (1 - 2c)
c ≥ 0.5 : scale = 2 ^ (1 - 2c)
两侧分别按单精度计算 max(1, inner × scale)，再取整。
```

当前相关分支的 K 为半元音 25、流音 18、鼻音 30、浊擦音 `2O`，其它为 55；仍须服从原生类别判断顺序和前后阶段的使能条件。这个规律及取整依据来自只读原生分析，并复核了已有合成数据验证工具，未用新曲线拟合系数。

实验模型只使用一次 VEL64 规划取出的素材区间、类别和原生帧锚点，之后只算数学，不再询问 DSE。14 个场景各对照 513 个新系数：

- **11 个场景的整条 513 点起音曲线逐 tick 相等**，包括新的半元音、鼻音、擦音、高音场景。
- 三个场景失败，合计 **1,121 个点**；所有失败均保留，没有用实际曲线补表后再声称预测通过。
- 这验证的是目标的**首个音素起点**，并非所有音素边界、采样选择或完整合成计划都能由这一公式得到。

| 失败场景 | 错误点 / 513 | 查到的原因或明确迹象 |
| --- | ---: | --- |
| MIKU 连音 `s a` | 508 | 最终分配会填入 outer 余量；VEL64 时该侧原始 inner 是 12，实际分配为 16。直接缩放 inner 遗漏后续分配。 |
| MIKU 短 `k a`，120 tick | 513 | 相邻短音符造成明显压缩；VEL0 原始整形会预测 -309 tick，实际为 -86。需要整个目标时长预算和压缩分支。 |
| MIKU `k a` 前有 120 tick 休止 | 100 | 小系数时采用 `a→k`，其它区段变为 `a→Sil` 加 `Sil→k`。单次 VEL64 的静音起音素材无法代表全曲线。 |

即使起点模型通过，整个素材计划也可能改变。例如多音素及高音场景的采样路径签名随 VEL 变化。因此不能冻结一份 VEL64 合成计划，只平移边界后直接用于全部音频。

## 性能应怎样理解

本机 Debug 隔离进程中，复用已准备的输入，直接系数规划加边界映射的各场景中位数约 **0.096–0.297 ms**，p95 约 **0.136–0.573 ms**。这不包含用于捕获输入的参考渲染、生产输入准备、上下文扩张、冷启动和 WPF 调度；不能用这些数值宣称完整拖动延迟。

只算上述局部数学模型，14 组各 20 万次的 C# 微基准约 **19–29 ns/次**；循环包含系数取值和校验和，预热后计时。这里不含模型准备、tick 转换或 UI。它说明将确定的算术移到编辑器侧有价值，**不能把尚未处理的三个反例算作可用快路径**。

513 点扫描只是研究覆盖，不建议在每次 MouseMove、每次手势甚至每个音符上直接执行这一整套扫描。本轮所有曲线均未观察到起点逆序，也不构成其它声库/表情下全局单调的证明。

## 推荐的下一步结构

建议建立一个有明确有效范围的时值计划接口，替代 UI 对 VEL 的盲目反查：

1. **准备局部上下文一次。** 继续复用已有有限窗口、整数帧原点、源 revision 和生命周期保护。输出自己拥有的数值快照，保留真实时间相位。
2. **补齐分配前的参数与分支。** 重点在整形/分配边界取得有效 inner/outer、候选范围、目标时长预算、压缩/留白标志、邻音符限制、静音与连音切换条件。部分工作对象是栈上临时值，必须在有效期内复制，不能只在规划结束后猜测或保存原生地址。
3. **形成分段规则。** 快路径只在已验证的素材路径、预算和约束区段内计算。进入未知区段时做一次局部无音频规划，建立下一段；编辑或切换上下文时使整份规则失效。末端仍由同一后端确认整组边界。
4. **预览与最终渲染共享系数。** 正常渲染在目标 NOTE 提交前应用同一份系数/规划规则。当前实验已证明系数注入能影响最终 PCM；产品接入还需要精确路由到目标渲染任务，不能把临时探针的进程级 vtable 钩子直接搬进 Editor。

产品还须解决系数的工程持久化、撤销/重做、复制/删除音符、导入导出、渲染与预测缓存失效。源 VEL 不变时原生缓存未必自动失效，本轮用私有音符的 VEL 往返强制渲染只是实验控制，不是产品设计。旧工程、未知二进制或不支持场景应继续保留已部署的 VEL 局部查询路径。

如果目标进一步扩大到“每个音素边界都能独立指定”，还需在时长分配与帧映射之间做独立实验，同时重建素材取帧、F0/表情轨迹、调度索引和 VSM score。**本轮没有验证这项能力**；仅改显示 score 或某个 row 的起止字段不足以保证声音正确。

## 可靠性取舍

2026-10-16 进一步核对运行时、失败样例和工程接入成本后，采用更保守的推进顺序：**当前产品保留局部 VEL 查询；新增控制能力优先研究“浮点系数 + 原生局部规划”；编辑器公式暂作候选计算，不独立决定显示或提交结果。** 前文的分段规则结构是研究方向，尚未具备可投入产品的有效范围判定器。

| 路径 | 当前可靠性依据 | 尚未解决的主要风险 | 取舍 |
| --- | --- | --- | --- |
| 现有 VEL + 原生局部查询 | 完整边界、正常渲染并发、取消与生命周期已有隔离验证；已部署且用户实测可接受；原生事务负责 VEL | 有限上下文的稳定判据不是普遍证明；可达位置较少；只支持核对过的二进制与配置 | 当前产品基线 |
| 直接浮点系数 + 原生局部查询/正常合成 | 原生仍处理选材、压缩、余量分配和取帧；9 个新增点有最终 PCM 与边界对照 | 提交前介入真正的宿主渲染任务，及系数持久化、撤销、缓存失效尚未接入验证 | 新能力首选，但先留在隔离后端 |
| 单次素材快照 + 编辑器公式 | 11 条完整起音曲线吻合，纯算术成本低 | 3 条曲线已出现 1,121 个错误点；没有可靠的通用范围判定；完整边界/素材路径未由公式验证 | 仅辅助选候选，显示前仍查询确认 |
| 直接重写最终调度或逐音素边界 | 可定位规划与输出层，已有相关素材映射研究 | 本轮没有完整音频对照；取帧、调度索引、音高/表情及 score 的一致性待审计 | 暂不作为产品路线 |

这里分别考虑“已能用于当前产品”和“最值得扩展的新能力”，不能把两者混为一个成熟度结论。浮点系数路线保留原生分配规则，减少另写一套声学时值规则的负担，但介入宿主渲染本身带来的工程风险仍高于当前只提交 VEL 的路径。

**仅按音素名称设公式白名单不可靠。** 同样的 `k a`，长连音可以通过，短音符和前方休止却失败。即使只缓存一个 VEL64 的素材路径签名，也检测不到尚未查询的新系数已经跨过分支。两端或少数中点吻合不能证明区间内全部吻合。取得明确的预算约束与分支条件前，不应采用“先显示公式位置，渲染后再纠正”的交互。

适合先做的优化是准备与复用局部输入、缓存已验证的系数—完整边界结果、合并最新请求，并测量准备/规划/映射各阶段的真实占比。公式可以提出一个可能接近目标的系数，原生查询确认后才作为候选显示。这样能减少盲搜，同时保留“最后显示什么就提交什么”的契约；不能把公式猜测写入已验证缓存。

现有搜索检测到已采样结果逆序会拒绝该场景，但这不等于证明未采样区间全局单调。优化搜索和判定结果准确是两件事：一次查询确认了某候选，并不自动证明它是所有候选里离鼠标最近的结果。新增系数搜索还需覆盖平台、跳变、拓扑变化和非单调反例。

版本回退也有边界：**现有局部查询和新增系数入口都依赖核对过的 native 哈希。** 未知版本不能靠切回当前局部 VEL 后端绕过校验，应停用这项扩展并保留原生编辑路径；不回退全量试算。已保存的自定义系数如果不能应用，也不能静默按普通 VEL 合成并伪装成相同结果。

浮点后端进入产品前，应至少补足：直接由源快照编码输入、无需参考渲染；同一系数驱动查询与真实合成；相邻多目标/多 Part/并发渲染的任务路由与取消；反复修改、撤销/重做、保存重开和缓存命中后的边界一致性；忙锁、源切换和关闭时无旧请求误写。性能对照必须采用相同输入与完整查询范围，不能把本轮约 0.1 ms 的已准备输入查询，与包含源准备/上下文扩张的生产查询直接比较。上述验收尚未完成，本轮没有据此修改或部署产品。

## 浮点控制基础层：输入、工程、历史与缓存

随后按“浮点系数 + 原生局部规划”实现独立基础层，入口为 [PreparedCoefficientTiming.cs](../VOCALOIDPatcher/VOCALOIDPatcher/ConsonantTiming/Backend/PreparedCoefficientTiming.cs)，隔离验收入口为 [TimingFoundationProbe.cs](../voicebank/tools/evec_render_harness/TimingFoundationProbe.cs) 的 `--timing-foundation-probe`。本节的 [数值证据](evidence/sampled-timing-foundation.json) 与前面的曲线探索分开记录，包含实现源码、原生映像与原始结果哈希。

### 输入只准备一次

`PrepareCoefficient` 直接从稳定源捕获必要上下文、节奏、音符参数和相邻已保存系数，编码 NOTE/Singer 输入；不需要先合成参考音频。每个准备对象拥有私有映射 Sequence、消息缓冲和坐标转换表，不在后续查询中读取源音符或重新编码。查询阶段只重置并调用原生规划器，返回整组音素边界；不调用音频 Start/Step，不推进合成帧。

准备窗口仍按目标前后 1、2、4、8、16 个音符扩张，每窗最多 33 个音符，最多五窗，全部预编码合计最多 67 个音符。查询满足源上下文完整或两次连续扩张边界一致才返回；这是经过样例验证的稳定判据，不是对任意声库的普遍证明。单窗限制 22 秒，最多四个存活准备对象，每个缓存最多 256 个精确浮点位模式结果，返回数组与内部缓存分离。

坐标继续保留源 Part 原点、音符原始位置及 256 采样帧内相位。每窗准备一个 4,096 项的精确 frame→相对 tick 表，提前调用源的时间转换处理 tempo 与 500 ms presend；查询先核对帧网格，再查表，不重新使用源时间轴。源 revision、取消、锁等待和对象销毁均有检查；清理后端缓存会同时销毁准备对象。隔离实验还验证了源关闭后私有快照能独立查询，**这只证明输入所有权，宿主关闭流程仍必须主动失效旧请求。**

| 验收 | 结果 |
| --- | --- |
| 五组音素，各 128 个普通 VEL 对应浮点值 | 640 组完整边界与既有局部后端一致 |
| 短音符、非零 Part 起点与 tempo、RIN、100/10,000 音符、长空白尾部等五组上下文 | 35 组完整边界与既有后端一致；候选查询 PCM 计数均为零 |
| 五组音素各三个非 VEL 网格系数的正常音频渲染 | 15 份完整边界与准备后查询一致 |
| MIKU、RIN 各自同时设置两个相邻目标，其中包含 `k a i` | 两份音频、四个目标完整边界与查询一致 |
| 缓存命中、返回数组修改、revision 变化、后端清理 | 缓存数据隔离；旧 revision 和已失效准备对象被拒绝 |

本机 Debug 隔离进程，640 次查询的中位数 **0.1649 ms**、p95 **0.4467 ms**，最大 **2.8725 ms**。五组三音符准备耗时 1.956–7.846 ms；100 与 10,000 音符源的准备分别约 9.520、12.659 ms，二者都只编码 67 个音符、五个窗口。计时不包含后端冷构造、真实宿主线程调度和鼠标搜索，不能视作最终 UI 延迟；准备时间也包含最多五窗的预编码与精确 tick 表建立。

### 保存、历史与后续控制目标

[SampledTimingPlan](../VOCALOIDPatcher/VOCALOIDPatcher/ConsonantTiming/Model/SampledTimingPlan.cs) 将存储计划与当前执行器分开。当前执行目标为 `note.coefficient`，范围 0–1。额外预留：

- `phoneme.boundary.offsetSeconds`：绑定确切音素拓扑的内部边界，索引 1…N−1；可以表达一个音符内多个元音之间的 timing 关系。
- `transition.offsetSeconds`：绑定相邻音素接点，索引 0…N；0/N 表示前后上下文接点。
- 有界的未知目标：可以原样保存、加载与参与内容指纹，供后续执行器扩展。

这两种预留目标目前只有数据语义与保存能力，**没有原生执行器，也不代表已经能独立移动元音或过渡。** `Query(plan, revision)` 是后续扩展入口；当前遇到任一未支持目标就明确拒绝执行，不能静默忽略它后按普通系数合成。索引始终绑定完整音素串，拓扑变化时拒绝旧计划，不按相似音素名称猜测重绑。

[SampledTimingDocument](../VOCALOIDPatcher/VOCALOIDPatcher/ConsonantTiming/Model/SampledTimingDocument.cs) 使用内容指纹判断保存状态，revision 始终递增。撤销到已保存内容可以变为 clean，但不能让撤销前的异步结果重新有效；另有会话唯一标识的渲染 stamp，跨文档、旧 revision 和关闭后的结果均不能发布。修改生成实现既有 `ICustomParameterHistoryEdit` 的命令。[SampledTimingSession](../VOCALOIDPatcher/VOCALOIDPatcher/ConsonantTiming/SampledTimingSession.cs) 提供显式适配入口，提交给项目现有的共享历史协调器，但尚未自动注册到 Editor。

工程扩展写入 VPR ZIP 内的 `VOCALOIDPatcher/sampled-timing.json`，schema 为 1。仅保存结构定位、音符位置/时长/音高/声库/精确音素保护字段与控制值，不保存原生指针或预测 score。写入采用同目录临时副本加原子替换，保留其它 ZIP 项，数据为空时只删除自己的项；解析有 4 MiB、深度、条目数和目标数限制。原生保存成功后才能写扩展，扩展写入成功后才标记已保存。

隔离实验实际调用 VSM 保存、包装 VPR、加入扩展、重新解包并用 VSM 打开工程，再应用恢复系数进行正常音频渲染。重开后的完整边界和 PCM 与保存前一致；自定义 A→B→撤销 A→重做 B、清除系数、保存后撤销/重做、新分支均验证内容和音频关系。原生音高编辑的撤销/重做也保留，缓存失效不增加临时 VEL 的历史项。**自定义历史实验直接重放真实的 `ICustomParameterHistoryEdit` 命令，并未加载 Editor 的共享时间线；不能据此声称混合 UI 撤销顺序已经宿主验证。**

当前地址解析采取严格保护，移动、改长、改音高、增删重排等结构变化后会拒绝旧定位；尚未实现随这些操作迁移、复制或清理自定义数据。此限制避免把保存值错误挂到另一个音符，接入宿主生命周期时仍须补齐这些行为。

### 渲染缓存验证与已保留异常

仅改变扩展值时，原生 `HasValidRenderedWave` 仍可能为 true，原缓存文件也保持不变，已通过实验复现。因此真实提交必须显式使相应渲染缓存失效；预测查询本身不做这件事。

[SampledTimingVsmBinding.InvalidateRenderedPart](../VOCALOIDPatcher/VOCALOIDPatcher/ConsonantTiming/Backend/SampledTimingVsmBinding.cs) 接收明确的 1–33 个必要上下文音符，在调用者拥有空闲源与渲染生命周期时，进行临时 VEL 往返及有范围的 score 更新，再以无历史方式提交。临时值在提交前恢复，异常时也尝试恢复。该入口没有自动调用，也不能在音频渲染同时修改真实源；正常最终渲染仍由上层任务与 epoch 调度。

100 个短音符场景仅触碰其中 33 个上下文音符，修改目标后其真实边界匹配预测，远端首尾边界不变。这里验证的是**失效操作的输入有界**，没有证明最终原生 PCM 渲染成本也严格限制在这 33 个音符内。

该场景还出现一项必须保留的对照：第一次参考与完全不改系数的正常重渲染，在约 0.998–1.004 秒处有 154 个有符号 16-bit 采样值不同，最大差 6。系数修改后恢复的整份 PCM 与这次正常对照逐字节相等，且相对首次参考的差异位置和值完全一致。现有证据排除了“恢复引入额外差异”，尚未确定首次差异的根因；不能将首次参考与恢复后的文件宣称为逐字节相等。原始哈希和差异摘要均保存在本节证据中。
