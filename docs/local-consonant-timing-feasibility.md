# 采样声库局部时值规划：可行性与性能验证

试验日期：2026-10-15；整理日期：2026-10-16。对象为本机 VOCALOID6.dll 6.13.1.1 配套的 VSM/DSE，二进制 SHA-256 见[数值证据](evidence/local-consonant-timing-feasibility.json)。本轮只修改研究工具与文档，没有部署、启动 Editor 或接回拖动功能。

后续进展：2026-10-16 已完成[独立局部查询后端](standalone-local-timing-backend.md)，移除本报告中的基线回放与 VSM 渲染启动外壳，补齐输入编码和最终 tick 边界转换。以下保留早期可行性试验及其当时限制。

再后续的[并发与生命周期验证](local-timing-concurrency.md)修正了逐窗口 Start 导致的锁等待与渲染饥饿，当前查询复用已启动会话，只重置时值规划状态；同进程原生渲染共存已通过，真实 Editor 接入仍待验证。

## 结论

**不合成音频而重新规划采样音素时值，在当前引擎版本上已得到动态验证。** 直接调用 DSE 的事件规划阶段，33 组短上下文试验的有效调度记录与正常音频渲染完全一致；候选查询的 PCM Step 调用数、PCM 输出采样数和引擎当前帧增量均为 0。

但这还不是可以接入鼠标的后端：输入仍来自各短样例的 VEL64 基线事件流，查询仍借用 VSM 创建、启动和取消私有引擎。独立的局部输入构建、通用上下文范围、调度表到音符 tick 边界的转换，以及并发和内存验收尚未完成。现阶段不能把核心规划约 1 ms 当成完整拖动延迟。

## 调用路径的区别

以下地址均为对应 DLL 的 RVA，只适用于证据文件中的哈希。

| 路径 | 观察到的行为 | 判断 |
| --- | --- | --- |
| Sequence `Commit(false)`，虚表偏移 `0x1E0` → VSM `0x8F130` | 成功提交，但不调用 DSE；音素边界仍是旧值 | 不是时值计算接口 |
| Part `BeginScoreEdit` → `UpdateScoreEdit(false, begin, end)` → `EndScoreEdit` | 局部范围和完整范围都返回成功；编辑 score 的音素几何摘要不变 | 可编辑/失效缓存，不会自行求出新辅音时值 |
| DSE 元数据推进，虚表槽 14 → `0x1D1630` → `0x168370` | 解析事件并更新调度、音高等元数据，不执行 PCM Step | 可绕开波形合成，但仍逐帧推进 |
| DSE 事件规划 `0x1B2AB0` | 处理给定时刻的 NRPN 输入，直接更新未来调度表 | 本轮验证通过的更短路径 |
| DSE PCM Step，虚表槽 15 → `0x1D1670` → `0x168940` | 进入实际合成并输出 PCM | 只用于短样例的独立真值对照 |

静态调用链与隔离动态记录互相印证：note NRPN `0x50` 的处理进入 `0x1AF080`；VEL 对应 LSB `0x03`；完成 note 消息后进入时值规划 `0x1A2DD0`。调度表在后续波形合成前已经包含未来音素区间，不必把播放帧推进到目标发声位置。

托管 `RenderPartiallyAsync` 仍属于音频路径。当前 VSM 的准备链 `0x1F960` → `0x686D0` 会经过 Part 复制函数 `0xDF6D0`，其中遍历源 Part 的音符及 controller 列表。给接口传局部 tick 范围，不能据此保证准备成本只与局部上下文有关。

## 局部提交的反例

私有三音符样例中，目标 `k a` 从 VEL64 改为 VEL32：

| 操作 | 即时读取 `GetPhonemePositions()` | 正常渲染后的真值 |
| --- | --- | --- |
| `Commit(false)` | `[-80, -2, 405]` | `[-158, -2, 405]` |
| Score edit，范围 720–1680 tick | `[-80, -2, 405]` | `[-158, -2, 405]` |
| Score edit，范围 0–2400 tick | `[-80, -2, 405]` | `[-158, -2, 405]` |

两种 score edit 的 518 帧音素几何摘要在更新前后相同，DSE Start/Step/Samples 增量均为 0。`EndScoreEdit` 后 score valid flag 可以变为 false，但“缓存失效”和“已经算出新边界”是两件事。正对照正常渲染产生 3605 次 PCM Step、922880 个输出采样，证明计数探针能观测合成路径。

本次也修正了一处历史地址识别：Part 虚表偏移 `0x298` 的 `EndScoreEdit` 对应 VSM `0xE2D90`；偏移 `0x2A0` 的 `0xE3090` 是 `CancelScoreEdit`。

## 无音频规划怎样验证

先用私有短样例的正常渲染建立独立真值，记录真实 tick 边界、送给 DSE 的事件和原生调度记录。候选路径采用同一上下文的 VEL64 基线事件，只改目标 note 的 NRPN VEL 字节，再与另行采集的候选 VEL 原生输入逐字节核对。

直接规划试验中，承载查询的私有 Part 始终保持 VEL64。VEL32/96 的结果必须由修改后的输入事件产生，不能借用承载 Part 自身的候选 VEL。每次查询启动新的引擎状态，在 Start 回调中调用事件规划并读取未来调度，随后主动取消，禁止进入 PCM Step 或发布最终 WAV。

比较的调度元组包含区间起止帧、过渡长度、前后音素索引及 bank/unit 索引，不包含指针地址。33 组对照覆盖：孤立音符、仅前邻、仅后邻、三音符连音、五音符链及其三音符裁剪、休止、短音符、EVEC 多辅音、非零 Part 起点与局部变速、MIKU/RIN 两个采样库；每种上下文测试 VEL64、32、96。

在更早的 27 组元数据推进试验中，完整推进所得调度也与正常渲染一致。仅输入至最后一条上下文事件后提前读取，全部有效调度记录已经一致。进一步直接调用事件规划后，引擎当前帧保持 0，无须逐帧处理剩余静音区。

这些试验验证的是**原生调度记录相等**。证据中的 tick 边界是正常渲染的真值；目前没有把候选调度独立转换成 `GetPhonemePositions()` 的最终 tick 列表，因此证据中的 `independentlyPredictedTickBoundaries` 明确为 null。

## 性能分账

以下为最后一轮 33 组直接规划试验的观察值，包含首例 JIT/预热影响；是不同样例的最小值、中位数和最大值，不是持续运行的 p95 基准。

| 阶段 | 最小值 | 中位数 | 最大值 |
| --- | ---: | ---: | ---: |
| 事件规划及调度读取 | 0.91 ms | 1.15 ms | 3.44 ms |
| DSE Start 初始化 | 7.60 ms | 8.74 ms | 13.49 ms |
| 当前 VSM 查询包络：启动至取消、通知与收尾 | 57.62 ms | 73.41 ms | 90.22 ms |

规划时间包含研究工具的字符串分配及摘要读取；不含样例创建、插入音符、提交、基线事件复制。VSM 查询包络还含异步通知轮询和收尾等待，不能简单减去两项核心耗时后把差值全部归于引擎。

另有 6 组开销试验：只把候选私有 Part 拉长到 130000 tick，或再添加 1000 个远处音符；真值依然只渲染原先的短上下文，长候选在 Start 阶段取消。规划仍只消费缓存的局部事件，三音符上下文各用 4 次规划调用，PCM 为 0。1000 音符候选的查询包络为 88.53–101.76 ms，空长尾为 73.76–75.06 ms。这说明当前 VSM 外壳仍有额外开销，不能把它称为已经完成的局部后端；这些数据也不构成长 Part 全渲染正确性的证明。

## 上下文裁剪的证据与限制

同样的 `k a`，VEL64 时孤立起点为 -30 tick，有前邻连音时为 -80 tick；没有后邻时末端为 477 tick，有后邻时为 405 tick。前后上下文分别影响起点与末端，不能只提交目标音符再期望结果不变。

五音符链删去更早的两个音符，保留目标及相邻音符的原始时间坐标后，三个 VEL 的目标边界均相同，分别为 `[-81,-3,404]`、`[-159,-3,404]`、`[-59,-3,404]`。这是该样例可以局部计算的证据，尚不能推出“前后各一颗永远足够”。

三音符样例移动到另一组绝对时间坐标后会出现 1 tick 级差异。局部化还必须保留原生帧栅格与 tempo 换算的取整相位，不能随意把局部起点归零。

## 接回拖动前的剩余工作

1. 从目标音符及经验证的上下文生成事件，包含必要的表达、控制器初值、声库与 tempo；首次查询不能依赖额外音频渲染。当前基线回放只用于证明引擎规划阶段可行。
2. 把规划调度映射回目标音符及完整 tick 边界，核对多辅音、连音、休止、尾音和取整；确定可检测、可扩张的上下文范围。
3. 建立独立的查询会话，移除 `StartAsyncRendering` 外壳及整 Part 准备，测量复用、失效、内存、并发与连续操作延迟。原生元数据推进在事件规划外层有互斥封装，直接调用的宿主接入必须补齐独占与生命周期约束；本轮只有私有进程内的单查询对照。不满足条件时不退回全量合成。
4. 后端通过后再接入拖动候选、跨手势缓存和单请求取消，松手只提交一次原生 VEL。
