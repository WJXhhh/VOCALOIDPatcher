## 原生 timing 的极端源帧推进

`TransitionCoverageMapping.Apply` 把选中素材的有效来源区间映射到当前分配的输出帧。当前约束保证端点可表示：来源首尾不同时至少需要两帧输出；它不保证足够的时间分辨率或音质。

`TransitionPhaseMapping.Apply` 再分别对 split 两侧使用 `u^power`，其中 `power = 2^(2×amount)`，范围为 0.25～4。它保持两侧首末来源位置，内部线性插值取来源帧。amount 为 -1 时，连续函数在入口的导数趋于无穷；为 +1 时，入口推进很慢、出口推进很快。有限帧表不会产生无穷数值，但会产生较大的相邻源位置增量。参数名 Phase 在这里表示素材进度分布，不是直接修正 PCM 的声学相位。

真实 6.13.3.1 SDK/DSE 下，共运行 248 次独立渲染，覆盖 V5 中文 `l a`、V6 中文 `l a` 的长短音符，以及 MIKU `k a`。逐条测试三个过渡的进度 ±1/±0.5、完整来源、可达端点的两个极值及其组合，另有 15 个不满足来源端点条件的候选明确拒绝。

V6 短音符 `l→a` 的结果如下。最大推进量只在同一 ART 的同一半段内计算，不把左右素材切换误算成源帧跳变。

| 设置 | 最大素材帧推进量／输出帧 | PCM16 峰值 | 全局最大相邻样本差 |
| --- | ---: | ---: | ---: |
| 原始 | 1.000 | 2427 | 474 |
| 完整来源，进度 0 | 3.182 | 2246 | 453 |
| 完整来源，进度 -0.5 | 10.553 | 2305 | 443 |
| 完整来源，进度 -1 | 19.219 | 2174 | 450 |
| 完整来源，进度 +0.5 | 6.074 | 2352 | 470 |
| 完整来源，进度 +1 | 11.095 | 2408 | 441 |

输出 hop 为 256、采样率为 44100 Hz，即每约 5.805 ms 输出可能跨过多帧素材参数。这支持“很短的区间内发生快速谱形或瞬态变化”的风险判断，但本组 PCM 的最大样本差没有随进度单调增加，尚不能据此声称已经复现咔哒声、混叠或相位失配。

248 次已消费 ART 帧的来源位置及标志均与计划一致；原生 timing/gain Failures 均为零。局部候选查询的 Starts/Steps/Samples 均为零。五组恢复原参数后的 PCM 与各自基准逐字节一致。伸长尾部静音时，规划可能超过引擎最终消费范围；探针单独记录未消费帧，不把它们算作已经验证的合成输入。

全部输出的 PCM16 满幅样本数为零，最大峰值为 3661/32768。这里没有观察到最终 PCM 满幅削波形成的平顶；输出电平低仍不能排除更早的内部非线性限幅。没有使用用户出问题的工程，因此持续蜂鸣、显示上的方形波形和真正的削波还需对应原始 PCM 分别判断。

## 修复前平滑器的窗口边缘跳变

修复前 `TransitionSmoother.SmoothJunction` 把窗口中的样本替换为：

```text
y[n] = wOut[n] × audio[n-halfFade] + wIn[n] × audio[n+halfFade]
```

旧实现有三个独立问题：

1. 窗口开始时 `wOut` 接近 1，输出立即跳到前方半个窗口的另一处波形；窗口结束后又立即回到未处理的原始波形。窗口函数虽然平滑，处理段与外部原始信号并没有连续拼接条件。
2. 函数在同一数组中顺序读写。进入窗口后半段时，左侧来源可能已经被前半段改写，形成依赖遍历顺序的反馈混合。
3. `intervene` 只控制后面的响度包络，前面的微交叉混合无条件执行。因此函数可以返回 `Intervened=false`，但已经改变 PCM。

96 组合成信号测试覆盖四种频率、连续／90 度相位阶跃、等音量／6.021 dB 音量阶跃、相位对齐开关和三种处理模式。以下是 220 Hz、峰值 0.5、相位连续、默认自动模式并开启相位对齐的结果。输入在接点过零，两段振幅不同也不会在接点本身形成幅值跳变。

| 输入 | 原始最大相邻样本差 | 处理后最大相邻样本差 | Intervened |
| --- | ---: | ---: | --- |
| 两侧等音量 | 0.01567 | 0.88876 | false |
| 左侧 0.25、右侧 0.5，名义音量差 6.021 dB | 0.01567 | 0.57861 | true |

新增大跳变位于处理窗口边缘。关闭处理时输出保持原样。这是平滑器制造脉冲型不连续的可复现数值证据，尚未做主观试听。

实际宿主的 `TransitionSmoothingHost.CollectJunctions` 还会先按名义增益差筛选接点：默认阈值为 2.5 dB。纯 timing 编辑、两侧增益都为 0 dB 时通常不会送入平滑器；因此不能把上表等音量直接调用的结果描述成宿主每次 timing 编辑都会发生的行为。带过渡音量差时则能进入这条处理路径。现有宿主候选只取 ART Begin/End，没有对每个内部源进度突变或 split 作专项检查。

## 修复方法与原生 timing 的后续范围

PCM 平滑器现先应用局部增益包络，再检测接点跳变是否明显超过两侧邻近样本变化。只有异常接点需要波形修补：从局部不可变快照读取，用凸组合向连续桥接线过渡；修补权重及其斜率在窗口边缘归零。正常连续波形不会为交叉淡化而移相，样本数和时间轴不变。零交叉只影响修补窗口中心，增益边界仍保持在请求位置。

自动模式未达名义音量阈值时逐样本透传；`Intervened` 表示实际样本是否改变，`CrossfadeDurationMs` 在仅增益处理时为零。`Splice` 复用相同处理路径，直接连接两段的完整样本，不再隐式裁剪、插零或改变总样本数。局部增益增强受到输入余量约束，通过缩小整条局部增益桥防止新增削波，不逐样本硬限幅，也不归一化主体。

WAV 写回只编码实际发生变化的样本，并使用与解码一致的整数尺度。未修改的 16/24/32 位 PCM 和浮点数据保留原字节，包括 float 缓冲无法表示的 PCM32 低位。配置校验也修正了非有限交叉淡化值回退后可能小于 MinCrossfadeMs 的情况。

原生 timing 应另做质量约束研究。候选诊断至少记录每半段的输出帧数、来源覆盖量、最大来源推进量及其变化率，结合有声／无声和瞬态判断。考虑用单调、端点连续且速度有界的重分配替代当前极端幂函数；中性映射须精确透传。旧工程进度意图、撤销和保存语义也需要兼容，不能静默裁剪已保存控制。

固定“不得少于几帧”暂时没有实验依据。完整来源跨度越大，允许的压缩程度通常越有限；保持全部来源、任意压缩和稳定音质不能仅靠事后淡化同时保证。应先用实际问题工程比较无平滑、修正后的局部去点击和受限进度三组原始输出，再决定限制策略。

Julius O. Smith 的 [Time Scale Modification](https://www.dsprelated.com/freebooks/sasp/Time_Scale_Modification.html) 将平稳参数包络的时间缩放与瞬态处理区分；[Spectral Modeling Synthesis](https://www.dsprelated.com/freebooks/SASP/Spectral_Modeling_Synthesis.html) 讨论了瞬态处的相位匹配与交叉淡化。这些是后续方案的信号处理依据，不是本轮已证明 DSE 内部发生某种相位错误的证据。
