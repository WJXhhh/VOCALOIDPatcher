# 过渡编辑后修改发音：目标生命周期与延迟映射修复

2026-10-18。针对“调整过渡后修改拼音，渲染不更新，移动音符时旧音高线留下，并阻塞其它音符渲染”的报告。本轮完成源码修正和独立真实引擎验收，未部署、未启动或操作用户 Editor。

## 两条失败链

1. `ActiveTransitions` 把已绑定音符改了音素拓扑视作不支持的工程。随后 `Recover` 正确拒绝不完整控制执行，却因此停止了整个序列。旧波形和音高线是未完成新渲染的结果。现在将这种情况按目标替换处理：原数据在内存中留给原生撤销，新的发音不继承旧音素控制；保存只写当前仍匹配的目标。音色库改变也不再被当作普通位置移动来重绑定旧控制。
2. 即使音符自身发音未变，邻接音符也可能把原来的 `Sil → l` 换为 `a → l`。`ResolveAvailable` 只解析完整存续的过渡身份及共享接点；消失的目标保持休眠。共享接点的别名不完整时整组休眠，不把偏移套到残余一端。数据校验、未知字段保护、规划失败和执行失败仍然严格拒绝；没有捕获这些错误后重试无控制渲染。

对前接连唱音符的真实测试还发现原生源进度映射过早失败。记录到：分配区间为 `[3330,3347)`，计划中的 ART 是 `[3337,3376)`，此时实际仍是临时静音行 `[3330,3347)`。后一个 NOTE 尚未补齐，不能在这里宣告最终身份错误。

`transition_gain::mapping_begin` 现记录引擎当前合成帧，`mapping_end` 遍历“尚未消费、已经分配”的进度，而非只遍历新追加帧。临时行不匹配时等待后续 NOTE；匹配后才写入源位置。实际合成时仍核对 ART 身份和源位置的精确位值，未完成的映射不能成为成功结果。已消费帧不回写，各引擎仍使用自己的 TLS 与不可变 Part/epoch 快照。

没有新增音频试算、输出 WAV 拉伸、清空所有缓存或重新打开工程的恢复路径。候选查询及原生分配／合成的职责不变。导出签名、工程格式与结构体不变，clock ABI 15 / transition ABI 2 不变；后续部署必须同时更新主补丁和原生 DLL。

## 验证

证据：[transition-pronunciation-lifecycle-20261018.json](evidence/transition-pronunciation-lifecycle-20261018.json)。

- 以 6.13.1.1 SDK 编译，分别运行真实 6.13.1.1 / 6.13.3.1。每版新增 16 次渲染，覆盖过渡端点、进度、音量和旧偏移组合后改发音，同 Part 另一音符与另一 Part 的 VEL 更新，移动后的有效 score／音素位置，原生和共享撤销／重做，新发音重新建立独立控制，插入前接连唱音符及撤销，保存重开。
- 原有组合矩阵每版 40 次渲染通过，包含浮点系数、音素 timing、独立选样、音量、保存失败回滚、序列复制、未知格式保护、缓存重开及多 Part 实际并发。两版对应 PCM 完全一致；40 项与修复前已验收的正常矩阵也逐项完全一致。
- 新故障矩阵不是全部逐位相同：同一恢复输入的重放，以及跨版本的一次撤销 VEL 比较，记录到短区间最多 2 个 PCM16 量化单位、RMS 约 0.02855、186 个采样点不同。探针显式记录比较值，只接受峰值 ≤ 2 且全段 RMS ≤ 0.1 的数值差异；确认“声音变化”时使用同一标准的反面，不能把量化差当作有效控制变化。VEL 对照选用能产生明显变化的 `l a`，发音替换为 `l o`。原生 NOTE 跟踪已确认输入值确实更新，临时跟踪代码已移除。
- 新增 3 项托管身份／保存数据测试，总计 235 项通过。新增临时行替换后的未消费区间回访测试，46 项 Rust 测试通过。整个解决方案 Debug／Release 隔离构建均通过，无警告、无错误。
- 特定故障矩阵包含输入准备与实际合成的最大单次耗时约 496 ms（6.13.3.1）／586 ms（6.13.1.1）。这是小夹具端到端测量，不代表最大 Part 或所有声库的性能。

未做用户实际 Editor 的钢琴窗像素或鼠标手势验收。移动回归核对真实渲染完成、有效 score、有效 WAV 和新的音素位置；不把显示回退算作渲染修复。

## 复验入口

沿用 [正式后端探针](fixed-phase-backend-integration.md) 的 SDK、原生库和隔离程序集设置，增加：

```powershell
$env:VOCALOID_TRANSITION_PHASE = '1'
$env:VOCALOID_TRANSITION_ONSET = '1'
$env:VOCALOID_TRANSITION_PRONUNCIATION = '1'
dotnet <harness.dll> --transition-host-probe --patcher-dse-initialization <全新输出目录>
```

`VOCALOID_TRANSITION_PRONUNCIATION_PLAIN=1` 单独执行无自定义控制的原生发音／VEL 历史对照；`VOCALOID_TRANSITION_CONTEXT_ONLY=1` 单独执行前接连唱插入。完整原有组合矩阵不设置这三个发音测试开关。原生 DLL 使用本轮对应源码构建，不能使用只修主补丁前的旧原生 DLL冒充通过。
