# 接续音素 timing 边界锁定修复

2026-10-17，在用户保持打开的工程中，通过 VOCALOID MCP 只读查询确认：`k uo` 的末端是 `960 + 410 = 1370 tick`，下一音符 `t 7` 的起点是 `1500 - 130 = 1370 tick`。两个滑杆对应同一个原生音素接点，两侧都保存了约 -46.44 ms（-8 原生帧）的偏移。

现场诊断为 `query: NotSupportedException: Conflicting controls at a shared phoneme boundary.`。鼠标移动只更新目标音符的控制，而必要上下文保留另一侧旧控制；同一个原生源帧因此被要求映射到两个不同位置。移除目标自身偏移来计算拖动基准时，还会错误继承另一侧旧偏移，不能靠捕获异常或放宽交叉限制解决。

## 行为与实现

- 仅根据原生 planner 的精确基线帧识别共享边界。音符在乐谱上接续、屏幕接近或索引相邻都不是联动依据。
- 显式边界编辑同时解析该帧的全部音符边界别名，把新的偏移或重置应用到所有别名，保留其它边界和辅音系数。普通渲染查询仍严格拒绝不一致的工程控制。
- 预览缓存键包含编辑边界索引；预览解析成功不会让同一候选绕过普通渲染查询的冲突检查。准备阶段捕获源音符身份，查询阶段不回访用户工程。
- 基准查询清除共享边界两侧的偏移；候选绘制同步更新两侧的线、标签和音量区域。即使点击的一侧没有独立存储偏移，也能重置另一侧持有的共享控制。
- 松手时两侧控制通过一条批量历史提交，一次通知触发后续刷新和失效；撤销、重做一起恢复。历史登记失败回滚所有成员，历史仍跟随原生音符身份迁移。工程格式和原生 ABI 不变。

修改涉及 `PhonemeBoundaryEdit`、`PreparedPhonemeTiming`、`SampledTimingDocument.EditMany`、Session/Host 和音素覆盖层，没有修改原生 DLL、用户工程或设置。用户随后要求部署，16:14 已备份旧主补丁，通过既有符号链接更新主 DLL，并独立核对安装哈希；原生 DLL 保持不变。本轮没有启动、关闭或自动操纵 Editor。

## 验证

独立 SDK 探针 `--shared-boundary-probe` 使用现场的声库、位置、时长、音高、音素和控制值重建两音符夹具。先确认普通候选查询能复现原冲突，再验证显式编辑和严格渲染查询的缓存隔离。每次候选查询的 DSE Start/Step/Samples 均为零。

| 操作 | 共享接点绝对 tick | 原生帧 |
|---|---:|---:|
| 原值 | 1370 | 3419 |
| 从左音符末端改为 -4 帧 | 1392 | 3423 |
| 从右音符起点改为 -12 帧 | 1348 | 3415 |
| 重置 | 1415 | 3427 |
| 撤销重置 | 1348 | 3415 |
| 重做、保存加载 | 1415 | 3427 |

12 次渲染包含初次加载与温态基准、上述编辑/历史/归档，以及浮点系数 `.18359375/.736328125` 和仅另一侧持有偏移的重置。两侧预测接点始终相等，实际已消费的原生采样段均覆盖该接点，音频非静音、native Failures=0。撤销、重做、重载及最终恢复原值分别与对应温态参考 PCM 逐字节相同。首次声库加载的 PCM 与温态可能不同，探针保留该结果并单独标为 `cold`，没有把它作为恢复比较的参考。

另通过 20 次独立选样/VEL/浮点系数/timing 组合、四 Part 三轮并发与顺序参考的 12 次 PCM 比较，以及 183 项托管测试。Debug/隔离 Release 解决方案与研究探针构建通过。真实 Editor 的联动预览、共享撤销及工程保存仍待用户复验；独立 SDK 渲染不代替这些 UI 验收。
