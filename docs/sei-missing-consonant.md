# 乐正绫「炽」`s ei` 的 s 缺声诊断

2026-10-18。只读检查用户当前编辑器，并在独立进程复现，没有改动/保存用户工程，没有启动、关闭编辑器或部署。

## 现场与结论

声库 `BY98KLLZTDYH7YEE`，音素 `s ei`，音高 62、长度 480 tick、VEL 64。宿主已完成渲染，score/wave 有效；音素边界为 `[-25,-13,477]`，s 的显示跨度约 12.5 ms。当前音符无生效 timing 计划，宿主发布的自定义原生 Part 快照数量为 0；旧拼音的控制保留为历史数据，未用于当前渲染。

**这套声库没有 `s→ei` 素材，当前引擎没有从其它过渡借出 s。** 素材索引和实际合成工作项给出同一条链：

```
Sil→s（4 帧，几乎静音） → Sil→ei → ei→Sil
```

实际并未选中 `s→ei`。s 也没有独立 STA 单元，可听的 s 位于其它辅音到元音的 ART 中。单独合成 s 的整段 PCM16 峰值只有 1 LSB，接近量化/抖动底噪；把这份入口源拉长无法生成正常辅音。

这也限定了完整素材菱形的能力：它完整覆盖的是当前已选 stage。当前选到的 `Sil→s` 本身仅四帧，完整覆盖不能补出目录中缺失的 `s→ei` 发音。

## 静态与运行时交叉验证

只读解析安装 DDI，共 2556 个 ART 路径；所有路径的相邻节点中均没有 `s→ei`。`s→a`、`s→7` 各有 4 层；`Sil→s` 只有一份 4 帧单元。`ei` 自身有 4 层 STA，元音 token 有效；s 的 16 条出边中没有 ei。

DDI SHA256：`234207C757D9FDD2832C91C12EAC03D0E3A5E11BF8AEAB79D4D802FE01D005BB`。复用了仓库外已有公共解析器，并核对其固定 SHA256 为 `AAB606781B80B6FA656BE4C1657261C6770B605D7EC3F47FE4D2ECBC5CC0C994`，没有把 DDI/DDB 或商业音频复制入仓库。

相同音高、长度、VEL 的独立原生对照：

| 音素 | 边界 tick | 真实选样 |
| --- | --- | --- |
| `s ei` | -25 / -13 / 477 | 缺 s→ei，改走 Sil→ei |
| `s a` | -142 / -2 / 477 | 真实 s→a，辅音侧 23 个源帧 |
| `s 7` | -136 / -2 / 477 | 真实 s→7，辅音侧 22 个源帧 |
| `s iE_r` | -25 / -13 / 477 | 同样缺 s→iE_r，走 Sil→iE_r |
| `s\ ei` | -25 / -13 / 477 | 换成 s\ 仍缺对应边 |
| `s\ iE_r` | -158 / -2 / 477 | 真实 s\→iE_r，辅音侧 26 个源帧 |
| `s 7 ei` | -136 / -2 / 271 / 477 | s→7 与 7→ei 都有素材 |

WAV 中 1.330–1.480 秒的固定前缀窗，`s ei` 峰值为 1 LSB、RMS 约 0.043 LSB；`s a` 为 560 / 108.7 LSB，`s 7` 为 422 / 79.2 LSB。原生选到真实 s 过渡时，前缀出现显著非零信号。此处是采样信号检查，不自动作主观听感分级。

`s 7 ei` 证明现有素材可以形成带 s 的路径，但增加了 7 的音素及过渡，不能当作保持原发音和原 timing 的透明修复。本轮未把该写法写回用户工程。要保持 `s ei` 的身份和 timing，又使用其它过渡中的辅音，需要进一步做显式借样及接续控制。
