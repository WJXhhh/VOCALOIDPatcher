# 过渡音 timing / 音量前端接入研究

2026-10-17。基于[独立过渡后端](standalone-transition-backend.md)及当前音素 timing、音量、选样交互实现。此次交付交互方案、可拖动的会话原型和接入审计；未修改生产前端/后端、部署或启动/关闭 Editor。原型不连接引擎、不合成声音，范围交互只作示意，不能代替引擎认证。

后续实现与验证见[过渡带接入记录](transition-frontend-integration.md)。下文保留设计时的缺口说明；其中条件范围、工程数据、共享撤销和统一发布已在后续实现，实际编辑器鼠标交互尚待验收。

## 推荐交互：音素下方的过渡带

保留“在对象上直接调，辅以精确小面板”的既有方向。在 Emotion 工具中增加明确的编辑对象切换：**音素 / 过渡 / 选样**。默认沿用当前音素编辑；模式属于当前视图状态，不是额外一套永久开启的工程参数。只切换编辑对象，不改变任何声音数据。

过渡模式下，音素标签与边界保留作参考，在其下方显示一条较薄的过渡带。每段严格按真实 ART 的 Begin…End 绘制，标明 `l → a`；起音和尾音显示 `起音 → l`、`a → 收尾`。两端是 timing 手柄，中间是带圆点的音量横线。Split 用较弱的参考刻度表示，不在过渡模式中拖动。长持续段可以留下空白；那里没有 ART，不能为消除“缝”而虚构过渡区间。

同一条 ART 的完整贡献共用一个 dB 值。前/后半段各有可调覆盖时长，不显示成两条独立音轨，也不承诺任意录音混合或独立左右增益。

| 操作位置 | 行为 | 可见反馈 |
| --- | --- | --- |
| 左/右端手柄横拖 | 改该侧真实接点 | 当前可达带、前/后覆盖时长、已确认候选 |
| 音量横线/圆点纵拖 | 改这条过渡的 dB | 横线高度、实时 dB 数字；时间坐标不变 |
| 段体单击、窄过渡的名称按钮 | 选中并打开精确面板 | 对应 ART 与两侧音素一起高亮 |
| 精确面板 | 以前/后覆盖毫秒、dB 输入 | 显示实际可达值；超范围不改数据 |
| Shift + 拖动 | 减小拖动灵敏度 | 仍落在真实可达帧，不伪造亚帧精度 |
| Ctrl + 单击一个手柄/音量线 | 重置该控制 | 共享接点统一重置，单条历史 |
| 面板“重置此过渡” | 同时重置两端与音量 | 整体校验后一次提交；有共享端会影响邻段 |
| Esc / 丢失捕获 / 切换 Part | 取消候选 | 完整恢复按下前的值，不写历史、不渲染 |

“段体随意上下拖也改音量”不作为默认方案：它太容易与选择、横向拖动混淆。音量拖动只从可见的横线/圆点启动，沿用用户已熟悉的音素音量手势；边界优先且在按下时锁定操作类型，不能拖到中途切换。

第一版接入不加入整段横移、两端联动拉伸或“同名过渡全部修改”，避免一次手势隐式移动受保护音素边界或跨音符改多个身份。

## 为什么不用同一层塞全部手柄

当前代码已经存在明确命中关系：

- `ConsonantTimingOverlay.cs` 的 `Search` 与 `OnPreviewMouseDown` 先处理选样模式，再处理音素边界、音素音量和旧辅音入口。
- `ConsonantTimingOverlay.Phonemes.cs` 的 `HitPhoneme` 使用横向 ±7 像素容差。
- `ConsonantTimingOverlay.Volume.cs` 的 `HitVolume` 几乎覆盖整个音素内部；`GainGlyph` 在其下沿画横线与圆点。

若只把新手柄加进同一命中链，既可能被音素音量吃掉，也可能抢走音素 timing。同一时间点同时承载音符边、音素边和 ART 接点时，增大命中容差会进一步恶化问题。

因此推荐独立过渡带，并由编辑对象模式隔离命中。对照方案“同层选中展开”只展开当前 ART，可减少垂直占用，但需要更频繁选中，邻段联动也不如独立带明显。它保留在会话原型中供比较，不作为默认选择。

## 短过渡、共享端、跨音符

不要把短过渡视觉拉宽来暗示不存在的时长，也不要让左右命中区彼此重叠后依靠绘制顺序猜测用户意图。短到两个手柄无法分开时，主图保留真实窄标记，通过名称列表进入精确面板；必要时提供局部放大。列表顺序与时间顺序一致，选中项使用完整名字。只有确实需要区分重复身份时才追加“前段/后段”或邻音符标识，普通交互不暴露素材地址、stage 数字和帧游标。

同一物理接点只画一个控制柄，并加共享标识 `◇`。悬停/选中时高亮全部别名所涉及的 ART；拖动时它们同步更新，整组操作只有一条撤销记录，不能给两边保存两份互相冲突的坐标。

锁定分成不同情况：

- 保留现有音素边界时无独立空间：显示锁定端，提示原因；其它端与音量仍可用。
- 范围还在查询/引擎暂忙：显示准备状态，不冒充锁定或“没有范围”。
- 整体能力不支持/上下文不完整：显示不可编辑原因，保存的控制仍保留。

真实三音素夹具 `n → n#2 → a` 中，第一段 End 与第二段 Begin 都是帧 3344；邻近受保护位置为 3343 / 3345，因此该共享端只有一个可达位置。界面应明确锁住这一个共享端，而不是显示两个可拖但永远回弹的滑杆。两条 ART 的增益仍可以分别调节。

跨音符过渡以右侧音素所属音符作为显示主行，尾音以左侧音符作为主行；同一过渡只画一次。通过 Part 的时间坐标绘制，允许真实区间伸出音符矩形。选中时高亮两侧真实音素；音高不同也不按音符矩形裁掉前端或后端。静音上下文不伪装成可选音符。

## 松手不回弹的状态契约

至少区分 Idle、PressWait、PreparingRange、DraggingTiming、DraggingGain、FinalValidation、CommittedAwaitingRender、Failed。候选值、已确认模型值和实际渲染状态分开维护。

1. 悬停/选中时预热当前布局和相关端范围，仅处理当前 Part 与可见目标。UI 线程捕获稳定输入；私有准备的后续查询放后台，不能在 UI 线程等原生 mutex。
2. 按下时捕获来源 generation/revision、布局指纹、当前整组控制、操作目标和原值。不到移动阈值仅作单击，不产生参数修改。
3. timing 候选必须属于**当前整组控制条件下**的真实可达集合。光标请求、最近认证位置可以同时显示；实线手柄只能画在认证位置。范围有孔洞时不能当成连续区间。
4. 一次只允许一个查询运行，等待队列只留最新目标；去抖/合并覆盖旧请求。获得锁前后、回到 Dispatcher 前后均核对代次。超时保持最后认证位置并显示忙状态，不将其记为不可达。
5. 音量拖动不触发新的无音频规划；本地只更新候选 dB 和显示。timing 的 Move 也不提交源工程或合成音频。
6. MouseUp 进行最后整组校验，成功后一次更新文档、一次共享撤销、一次 Part 渲染调度。尚未认证的光标位置不能先变成“已提交”，之后再被渲染结果拉回。
7. 松手后保留已认证的控制几何，标记音频更新中；新渲染结果按 Part/epoch/revision 校验后接管。过期完成通知不得覆盖新值。失败时保留可诊断状态，不能用旧波形或无控制渲染冒充成功。

当前后端范围扫描在八组夹具上测得冷查询中位数约 5–8 ms、最慢约 48 ms；仍不足以证明可以每个 MouseMove 同步扫描。第一次显示可达带之前需要准备状态；后续读取缓存。原生帧约 5.8 ms，精确输入按实际可达点返回显示，不把任意毫秒输入原样留在控件里造成真假两套值。

## 接入前发现的四处硬缺口

### 范围必须对当前组合求条件范围

当前 `QueryTransitionRange(layout, endpoint, revision)` 的候选只有目标端修改，缓存键也是布局指纹 + 原始接点。它验证的是其它接点处于布局基线时的单轴范围。用户先改 A 再拖 B 时，不能直接复用。

需要增加接收 `currentControls` 的入口，缓存键包含规范化后的当前 timing 控制指纹及接点身份。扫描候选时保留其它接点修改，只替换当前共享接点；增益不影响几何，不必进范围缓存键。组合校验仍走 `QueryTransitionControls`。这不是给 UI 再套一次几何 clamp 能替代的工作。

### 文档不能持久化布局指纹和绝对帧

`TransitionControlPlan` 当前绑定瞬时布局，`TransitionIdentity` 中的音符地址又含位置/时长。它们适合本次执行校验，不应直接当成长期工程数据。

需要独立的 `TransitionDocument`：用工程内稳定音符身份关联两侧音素 occurrence、符号、方向和 stage/重复序号；共享接点存一项，增益按 ART 存。磁盘端保留可核对的 locator 与拓扑签名，不能只保存对象指针或列表下标。接点控制保存相对当前中性 ART 接点的偏移秒值；实际输出帧在重新准备后求解，避免移动音符时变成错误的全 Part 绝对时间。

改变音素 timing、选样、歌词或上下文后必须重建绑定。身份唯一、共享关系一致才重放控制；一端变成多端、拓扑变动或范围不再可达时，保留原数据并标记待处理，不能换绑到最近同名音素。整段复制可重建两侧关系，单音符复制不能自动携带指向原工程邻音符的跨音符控制。

建议独立版本化归档项 `VOCALOIDPatcher/transitions.json`，避免将双侧身份和多个端点硬塞进现有 `TimingAdjustment(kind,index,value)`。旧预留 `transition.offsetSeconds` 单索引也不足以表达本功能。未知版本/字段与当前能力不支持时应继续打开、保留、保存，执行能力与数据保留能力分开。

### 原生发布必须只有一个 Part 快照所有者

`SampledTimingHost.Publish` 当前已经在同一个 epoch 下组织采样 timing 与选样契约。独立后端的 `PublishTransitions` 会发布系数、warp、增益并跟踪自己的准备生命周期。如果 UI 再平行调用它，随后旧宿主发布普通 timing，就会覆盖过渡控制；UI 临时准备释放也可能撤掉刚提交的路由。

需要把过渡编译结果接入同一个 Part 渲染快照协调器，所有控件只改文档。由协调器合并现有系数/音素 timing、过渡接点/增益与选样契约，再用同一个 epoch 发布；音素音量接现有的后处理链。UI 候选准备可以释放，已提交快照由 Part 会话持有，不能绑在手势对象上。缓存关闭/撤路由顺序沿用后端已验收的约束。

### 绘制与交互要有隔离的数据适配

增加 `ConsonantTimingOverlay.Transitions.cs` 及独立的段/接点/增益显示原语；不要把 ART 塞进现有 `Onset`、`BoundaryHandle` 的音素序号。复用当前根 Canvas、坐标变换、主题、光标、提示和捕获清理，但将瞬时编辑对象模式收为统一枚举，避免再加一个与 DurationMode 可同时为 true 的开关。

过渡模式命中顺序为活动手势 → 当前模式控件/面板 → 选中共享端 → 选中增益线 → 段体选择 → 原生空白操作；其它模式不命中过渡控制。单独的过渡控件池常驻，刷新合并，后台不得直接访问 WPF 或源 SDK。不可支持的版本只隐藏/禁用执行入口，不能清除工程控制。

## 共享撤销与保存规则

一次拖动是一条 `ICustomParameterHistoryEdit`，复用 `CustomParameterHistoryCoordinator`，共享端修改按整个文档差量提交。前/后端候选、所有别名及精确面板共用同一值源，不维护相互回写的第二份业务值。

面板按 Enter、失焦或滑杆松手提交，输入过程不逐字符写历史。Esc 恢复当前未提交输入。连续数值调整的合并必须具有显式会话边界；不能把用户之前的其它参数撤销吞掉。

归档写入只在原生保存成功后进行，原子更新独立条目，保留其它扩展数据。撤销恢复的文档也要触发新的 Part 快照，而不是仅把手柄画回旧位置。

## 实施顺序与验收

1. 先补条件范围、长期文档/共享接点编码、版本保留及 Part 快照唯一发布；沿用独立 SDK 验证组合、保存、撤销、缓存和并发。
2. 加只读过渡带：核对跨音符、起音/尾音、stage、真实坐标、短段、缩放及滚动，不新增可写手势。
3. 接过渡增益与精确面板，再接单个/共享接点 timing；所有入口共用一次提交与渲染调度。
4. 宿主内测试拖动几十次、快速切换 Part、播放中编辑、取消/丢失捕获、查询超时、删除/移动/复制音符、撤销重做、VPR 保存重开、多 Part 并发、旧版本保留及导出一致性。没有宿主验收前不宣称生产前端已经接好。

会话原型验证范围为：直接 timing / 音量拖动、撤销重做、Esc 取消、共享端同步、零自由度锁定、精确值网格对齐、两种布局及窄屏/明暗主题。使用真实夹具的静态 ART 位置，纯本地演示，不模拟引擎返回或音质变化。本轮仅文档与原型，无需编译生产 DLL；安装文件应保持原样。
