# 采样声库发音过渡类型与自定义适配规则

2026-10-15。接续[自定义进入过渡可行性](custom-pronunciation-transition.md)，范围为当前哈希的 DSE 及本机七套中文 V5、八套日语 V4X。目标是列全实际连接素材、原生处理类型和借用边界，供后续实现逐音符自定义过渡。

**本机 15 库的 ART 目录与阶段已完整盘点；已识别的类别映射、候选与阶段规则已有原生实验或既有报告对应。** 自定义借用仍须实现与验证合成适配，尤其不能将原生左右分段生成直接当成通用隔离接口。本轮没有做真实借用音频或 Editor 内验收，也不把这 15 库当作其它语言、其它版本声库的全集。

## 实际素材全集

新工具 [catalog_sampled_transitions.py](../voicebank/tools/catalog_sampled_transitions.py) 重新读取全部 15 库的 DDI，以[既有 479 对照](../voicebank_doc/evidence/479_v5_v4x_cross_reference.json)锁定每库 SHA256 和公共解析器 SHA256。只读元数据，没有读取或保存商业 PCM。

| 范围 | 非空双音素 key | 非空三音素 key | 空目录 key | ART part 数 |
| --- | ---: | ---: | ---: | ---: |
| 七套中文 V5 | 17,901 | 0 | 0 | 56,051 |
| 八套日语 V4X | 7,437 | 994 | 7 | 23,881 |
| 合计 | 25,338 | 994 | 7 | 79,932 |

共 26,339 个目录 key，26,332 个有素材。key 按库分别计数，不代表跨库去重后的不同发音种类；part 是该 key 下的素材候选，也不等于一种独立“过渡类型”。全部 part 的 alignment 组数和区间内外关系通过本轮检查，未发现错误。

完整结果分为两份：

- [sampled_transition_keys.csv](../voicebank_doc/evidence/sampled_transition_keys.csv)：逐库、逐 key、逐 stage，共 27,333 条阶段记录，另有表头，其中 7 条为空目录。包含左右音素、PHDC 类别、素材数量、方向性边界分类及 alignment 组数。
- [sampled_transition_catalog.json](../voicebank_doc/evidence/sampled_transition_catalog.json)：每库完整类别成员、类别连接矩阵、每个目标音素的前置来源、空 key、无 ART 音素及各类计数。

三音素 key 各产生两个阶段行，因此 CSV 行数大于 key 数。CSV 中的左右音素始终按本阶段列出，`path` 保留完整目录路径与 `^` 标记，不能丢弃路径后把它当成普通双音素。

两份结果在独立进程重建后逐字节一致。范围外的新声库应重新盘点；音素表里有名字、目录里有节点，都不足以证明该过渡存在。

## 素材结构与阶段

| 结构 | 原生含义 | 自定义时的约束 |
| --- | --- | --- |
| 普通双音素 ART | 一条连接，一个 stage，两组 alignment | 是首个实现对象；分别保留两侧的 inner/outer 映射 |
| 三音素 ART | 同一 part 有 stage 0、1，分别取 alignment 0/1、2/3 | 资格检查依赖相邻阶段候选；不能只凭当前音素对强塞任意 stage |
| 多个普通 ART 连用 | 各自选材，再进入联合评分和分配 | 改一条边可能改变邻边的最终选择 |
| STA 持续单元 | 支撑持续音与长音符分块，不是另一种 ART 连接 | 借用进入过渡时应保留主体来源，不能把整枚音符都换掉 |

八库中独立三音素素材仅出现在四套 EVEC 库：Original、Soft、Solid 各 284 个 key，Rin Power 为 142 个；每 key 有多少 part 仍须逐项读取。

本轮重跑原生索引与选择实验，见[选择契约结果](../voicebank_doc/evidence/transition_selection_contract.json)：30 组缺边查询、324 组候选过滤、40 组阶段资格，以及 416 组评分与最终选择，全部零不一致。以下几条是已验证的区别：

- 单独只有三音素的前一对或后一对、又没有可接的前列表时，多阶段候选可能被排除。
- 准入检查比较 part 身份与预期 stage，不仅比较音素名字。
- 同一列表中，同 part 的连续 stage 有连续性优势；重复同 stage 或反向 stage 顺序不等价。
- **阶段准入不保证最终成对选用。** 跨列表对照已有“前边使用三音素 stage 0、后边选普通双音素”的反例。

详细规则及反例见[运行时图研究的候选与联合评分部分](../voicebank_doc/101_v4x_runtime_graph_completion.md)。

## 发音类别全集

本机 15 库共有下列 14 个 PHDC 分组名称，其中 `Syllables` 全为空，其余 13 类均有成员。当前这些库的每个 PHDC 音素都有分组，未发现重复归组；这只是本批数据事实，工具仍保留多类别的表达能力。

| PHDC 名称 | 中文含义 | 与过渡相关的处理 |
| --- | --- | --- |
| `Vowels` | 元音 | STA 查找优先；输出入口没有独立同名专用分支，通常使用通用映射 |
| `Nasals` | 鼻音 | 参与起音、接点长度整形；扩展条件下有专用重复与推进规则 |
| `Liquids` | 流音 | 类似鼻音的专用映射；中文 `l` 和日语 `4` 属于本类 |
| `Semivowels` | 半元音 | 参与长度整形；扩展时可根据 PCM 最低能量位置停留与续接 |
| `UnvoicedFricatives` | 清擦音 | 扩展时采用分段曲线变形，另计算重复位置标志 |
| `VoicedFricatives` | 浊擦音 | 接点整形与半元音/浊擦音的 PCM 停留路径 |
| `UnvoicedPlosives` | 清塞音 | 左侧短目标裁取有专门选择；右侧可扫描 PCM 并生成留空位置 |
| `VoicedPlosives` | 浊塞音 | 右侧塞音扫描与留空路径 |
| `UnvoicedAffricates` | 清塞擦音 | 左侧短目标裁取及右侧扫描、留空 |
| `VoicedAffricates` | 浊塞擦音 | 右侧扫描、留空路径 |
| `Silence` | 静音类 | 音素回退、长度分配和帧消费均有相关规则，不能只按字面 `Sil` 判断 |
| `GlottalPlosive` | 声门塞音 | 当前输出入口没有独立同名映射；实际素材必须另查 |
| `Breathings` | 呼吸音 | 已有独立呼吸 ART 与短 PCM 余量读窗证据；没有统一通用余量假设 |
| `Syllables` | 音节类分组名称 | 本机 15 库为空，没有因此发现一套额外音节素材 |

另有 `Whisper`：本批声库没有这个 PHDC 分组，但当前 DSE 输出入口确实查询它，参与左侧短目标裁取。本轮将其作为引擎分支单独检查，不能因本机未收录就从引擎能力中删除。

这些类别也不能直接翻译成固定的“元音→辅音”几个菜单项。例如清辅音、浊辅音内部仍分塞音、擦音、塞擦音；同为有声音素，流音和元音的处理也不同。逐类别的实际连接矩阵保存在目录 JSON 中。

## 边界与上下文类型

下表与前述发音类别是可以组合的不同维度，并非互斥的另一套音素枚举。

| 情形 | 已查明的规则 | 借用过渡时的处理 |
| --- | --- | --- |
| 静音进入 `Sil → X` | 是真实 ART；有些目标不能直接从静音进入 | 仅提供当前库存在且有 part 的来源 |
| 收尾 `X → Sil` | 与起音不对称；特定缺边条件会反向复用进入素材 | 保留真实收尾与反向回退的区别 |
| 正常内部 `X → Y` | 使用本阶段候选与邻项代价 | 将设置附着在目标进入边 |
| 同名连接 `X → X` | 即使存在素材，也不保证每种时长都选中；还可能形成反向工作项 | 不能简化成“同元音必然直接延音” |
| 同音符内多音素 | 与分到相邻音符时的选择结果可能不同 | 不能只对拼接后的音素串做全局替换 |
| 相邻音符连接 | 工作列表可跨前后音符，候选阶段也可跨列表关联 | 明确目标音符归属，保留列表上下文 |
| 留有短间隔 | 索引路径有连续性判定，可能仍走连续连接 | 使用实际调用时间步长，不能拿界面 tick 直接比较 |
| 留有长间隔 | 进入非连续路径，可形成静音段及重新起音 | 借用上下文不能绕过真实休止语义 |
| 长音符 | 可插入多个 STA 工作项，带独立查表及扰动规则 | 过渡与持续段分开缓存和失效 |
| 直接树路径 | 与预建索引路径的选材协议、元数据和回退不同 | 需要分别识别，不能只 hook 一个假定唯一入口 |
| 正向使用 ART | 读取当前 stage 的原方向区域 | 使用对应帧取整及边界规则 |
| 反向使用 ART | 区间、取整和若干专用映射不完全镜像正向 | 显式携带方向，不用手工反转数组代替 |
| 缺失音素或声库 | 提交行为取决于路径，可能形成静音或保持 pending | 自定义失败应恢复完整原调用 |
| 目录存在但无 part | 不属于可用素材；本批确有 7 个实例 | 在候选列表中禁用 |
| 音素存在但没有 ART | 本批均有 `?`、`Asp` 等实例；Rin Power 还有不少注册后缀 | 不把 PHDC 全表直接当作过渡选项表 |

时间判定不能跨入口混用：[索引实验](../voicebank_doc/101_v4x_runtime_graph_completion.md)在 0.01 秒步长下观察到 gap 12/13 的连续/非连续分界；[直接树实验的另一组自建条件](../voicebank_doc/evidence/237_region_direct_tree_two_note.json)观察到 20/21 的工作项变化。这些不是可以直接做成 UI 的通用毫秒阈值。

重叠音符的 Editor 整理、不同语言的连读省略，以及任意 tempo/音高轨迹下的自然宿主列表，尚未被本轮目录或人工调用矩阵穷尽。它们是上游调度验证项，不应被伪装为已验收的某种统一过渡类型。

## EVEC 后缀与呼吸变化

| 素材形式 | 需要保留的事实 |
| --- | --- |
| 普通 token | 按完整名字查找，不以显示歌词取代音素 |
| 编号后缀 `#…` | 可能表达 Color、辅音起音或其它已注册变化；语义依声库配置 |
| `*#1`、`*#2` | 属于特定释放音素材，不能当成普通元音或简单字符串装饰 |
| `br…` | 可有独立呼吸连接与异常短余量；此命名分类不等同于 PHDC 类别本身 |
| `^…` 中间目录 | 用于恢复多音素路径；展开成阶段时只按已核对的前缀规则处理 |

在本机 EVEC 库里，`*#1/*#2` 同时属于 `Silence` 类；因此“按词形分组”和“按引擎类别分组”会交叉。不能为了让 UI 分类整齐就删掉这种关系。

完整 token 匹配、未知 `#` 后缀回退、未知 `*#` 向静音类回退，已有原生查询证据；但**名字能回退不表示缺失的录音被补齐**。EVEC 的具体编号含义和事件排布以[当前适配进度账](../voicebank_doc/31_evec_v6_adaptation_progress.md)为准，不能采用早期报告里“任意串直接交给引擎即完全等价”的推断。

## 输出映射算法与优先级

本轮复用现有 Ghidra GUI Program，重新确认 `/v6/DSE.dll` 元数据与安装文件一致：SHA256 `7a4965bd377dbc2b08710e807ae1345b67d9fff6579ca0c01a769f744366f5b5`，x86 LE64，基址 `0x180000000`。查询仅限只读。

实际核对的入口包括 `0x1801a0450` 输出生成、`0x1801b2260` 长度整形、`0x18019d650` 分配、`0x1801acbc0` 持续单元查找及 `0x1801757a0` 帧消费。地址只适用于该哈希。

输出入口在特殊扩展条件开启时，左右两侧的分类分支优先级不同：

| 侧别 | 依次检查的专用路径 | 未命中时 |
| --- | --- | --- |
| 左侧 | 清擦音 → 鼻音/流音 → 半元音/浊擦音 | 通用映射；短目标再区分清塞音、清塞擦音和 Whisper |
| 右侧 | 满足本侧伸长条件的清擦音 → 四类塞音/塞擦音 → 鼻音/流音 → 半元音/浊擦音 | 通用映射 |

因此不能只定义一个“辅音伸缩”函数。已核对的算法族为：

1. **通用裁取与线性伸缩**：左右的进入端/出口端不同，超过 outer 时才进入相应延长规则；单帧区间有退化分支。
2. **起音与接点长度整形**：先处理系数、类别、同名接点及方向，之后才做目标时长分配。
3. **鼻音/流音重复与推进**：扩展下有专门的停留与尾段行为，反向不能统一镜像。
4. **清擦音曲线变形**：分段曲线与重复位置标志共同影响后级，不能只替换位置数组。
5. **半元音/浊擦音最低能量停留**：从实际 PCM 扫描得到停留位置，再填充和续接。
6. **塞音/塞擦音扫描与留空**：包含负 pivot、精确空帧标记及后级空输出处理。
7. **正反向取帧、插值及清浊交界**：是位置生成之后的消费层；是否混合、是否清空和缓存复用另有契约。

完整数值模型与既有大矩阵见[运行时图研究](../voicebank_doc/101_v4x_runtime_graph_completion.md)的 121–145、后续生命周期和读帧部分。上述算法不是每次合成都全部开启：直接树的一组调用明确关闭附加扩展，索引调用则可传入邻接区间长度。不得用人工强制开启的实验推断 Editor 必然走该分支。

## 新发现的左右隔离边界

新工具 [probe_transition_split_classes.py](../voicebank/tools/probe_transition_split_classes.py) 实际调用原生输出生成函数，先生成原 part 的左侧，再生成另一个 part 的右侧，保留实际左右音素 ID。使用两个不同的四组 alignment、自生成 PCM，交叉 stage 0/1、正反方向、两组系数、扩展开/关及三个长度组合。

覆盖 14 个库内类别名称、额外的 Whisper 及 Default，共 **2,208 组、4,416 次原生调用**。描述符、音素 ID、输出时间与工作项数量的结构断言全部通过，两次独立运行完整结果逐字节相同，见[分段类别结果](../voicebank_doc/evidence/transition_split_classes.json)。这是一份写入范围观察，不是对每帧数值和声音建立了新的独立正确性模型。

| 类别 | 组数 | 区间外帧槽发生变化 | 右侧调用使此前左侧帧变化 |
| --- | ---: | ---: | ---: |
| Default | 48 | 0 | 0 |
| Nasals | 144 | 33 | 0 |
| Liquids | 144 | 33 | 0 |
| Semivowels | 144 | 4 | 4 |
| VoicedFricatives | 144 | 4 | 4 |
| UnvoicedPlosives | 144 | 26 | 14 |
| VoicedPlosives | 144 | 26 | 14 |
| UnvoicedAffricates | 144 | 26 | 14 |
| VoicedAffricates | 144 | 26 | 14 |
| 其余七类各自 | 144 | 0 | 0 |

其余七类为 Vowels、UnvoicedFricatives、Silence、GlottalPlosive、Breathings、Syllables、Whisper。Default 没有类别成员，避免重复计算三种等价成员设置，故为 48 组。

总计 178 组检测到本次分配区间之外的帧槽内容变化，其中 64 组的右侧调用改写此前左侧帧，均发生在人工启用扩展的输入中。统计采用调用前后的缓冲快照，不记录写入相同值的指令；表中 0 表示本矩阵未检测到内容变化。所有写入仍位于夹具拥有的环形缓冲区内；这不是安装文件修改，也不是宿主内存损坏或听感异常的观察。

一个与 `la` 类别直接相关的反例：仅右音素归 Liquids、stage 0、正向、系数 1、扩展开启、目标左右长度 1/1。右侧调用的正式区间为 `[1,2)`，但还改写帧槽 2–14。它没有覆盖左侧，却可能影响后续片段，说明只检查“前音符有没有变”还不够。

因此原型需要隔离的帧生成与受控提交，或者在明确的完整连接边界适配来源，同时保留后级标志、缓存和衔接语义。**不能仅将前一次调用设为 right=0、后一次设为 left=0，就宣称所有类别已隔离；也不能盲目裁掉这些额外写入，假定声音仍等价。**

## 用户示例的真实来源

本轮通过已有离线 G2PA harness 调用中文 language ID 4，使用自有内存 sequence 查询，得到：

```text
ru = z` u
he = x 7
la = l a
```

结果、工具源码哈希和原生 DLL 哈希见[G2PA 例子](../voicebank_doc/evidence/transition_g2pa_example.json)。因此中文示例应研究的是实际边 `u → l`，参考边 `7 → l`；前一轮用 `e` 是机制夹具标签。

七套中文库都确有这两条普通双音素素材：凝各 2 个 part，婉各 4 个，沐/幽/清/萌各 3 个，炽各 4 个。每库 `l` 的结构性前置来源均为 39 种，含静音来源；这不是已验收的 39 种可随意互换的音质选项。

日语库的对应材料也单独确认存在：八库均有 `M→4` 和 `e→4`，每条按库有 2–4 个 part。但本轮 G2PA 例子查询的是中文，不能把这个结果当作日语音节或外来语 `la` 的解析验收。

## 与发音连接相邻的效果

V5 的 Attack/Release 表情和 VQM/Growl 不能直接并入“前置音素来源”枚举。它们与 ART 来源、时长、音高层控制属于不同层次。

[现有 V5 对照报告](../voicebank_doc/118_v5_v4x_cross_reference_and_expression.md)记录本机三份关联七库、内容哈希相同的效果资源：attack 有 14 个属性目录，release 有 11 个，总计 25 个目录、33 个样本：

- Attack：Airy、Bel canto、Down、Down2、Down3、Down4、Ornament、Ornament2、Trill、Up、Up2、Up_Accent、Up_Weak、VocalFry。
- Release：Accent、Decrescendo、Dynamic、Ornament、Ornament2、Stop、Up、Vib、Vib2、Vib3、VocalFry。

这些名称解释的是效果资源，不等于元音之间的 ART key。EVEC 的 Release 又是声库里的音素素材与事件排布，须与上述 DVQM 效果分开。REG 的音高层选择也不等于改变前置音素。

## 自定义过渡的支持边界
