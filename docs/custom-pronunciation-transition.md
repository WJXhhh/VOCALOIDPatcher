# 采样声库自定义音符发音过渡可行性

2026-10-15。范围为传统采样声库，目标是在实际音符仍为 `ru la` 时，让 `la` 的进入过渡采用类似 `he la` 的素材。

后续[全类型目录与适配规则](sampled-transition-catalog.md)已补充 15 库全部连接 key、PHDC 类别、三音素资格和左右分段边界。中文 G2PA 已确认本例参考边为 `7→l`；特殊类别的扩展路径会写入本次分配区间之外，因此下文普通夹具的分段成功不能泛化为所有类别的隔离保证。

**可以进入原型实现阶段。** 当前 DSE 已在自建元数据实验中接受“实际音素身份”和“所选连接素材”分离，也接受将原连接左侧、借用连接右侧分别生成相邻工作项。后者更接近保留 `ru` 主体的要求。尚未验证真实声库的最终声音、拼接平滑性和 Editor 调度，因此不能宣称已完整实现该听感。

## 需求对应的音素语义

这个功能适合定义为后一音符的“进入过渡来源”：选择 `la`，设置它按指定的前置音素或参考音节进入。`ru` 的歌词、实际音素、音高和长度仍保留。

`ru`、`he`、`la` 是用户层的音节描述。实现必须先用当前声库的 G2PA 结果确定边界音素，不能把这些字符串直接当作 DDI key。例如当实际末尾音素为 `u`、借用上下文末尾音素为 `e`，而目标起音为 `l` 时，可将边界问题表达为：

| 项目 | 原始发音 | 希望的来源 |
| --- | --- | --- |
| 前一音符主体 | `ru` | 保留 |
| 进入目标辅音的边 | `u → l` | 借用 `e → l` 的全部或右侧 |
| 目标内部的边 | `l → a` | 初版保留原路径，之后按试听判断 |
| 目标持续元音 | `a` | 保留 |

这里的 `u/e/l/a` 同时也是本轮实验的标签，**并未确认某套真实声库的 `ru/he/la` 恰好对应这些音素**。中文、日语、英语和 EVEC 后缀都应由各自声库解析。用户输入“像 he 过来”时，最先相关的通常是 `he` 的末尾音素，不一定需要借用整个 `h` 起音；若参考音节的影响超出一条边，还需扩大参考渲染范围。

原版 Velocity 控制辅音时长，Portamento Timing 控制音高变化位置；它们没有在这些定义中提供指定连接素材来源的语义。见 [VOCALOID6 官方参考手册第 50–51 页](https://rsc-net.vocaloid.com/assets/pdf_files/bb/VOCALOID_Reference_Manual_ENG.pdf#page=50)。本功能需要独立的补丁数据与合成适配。

## 现有技术报告提供的依据

1. [ART region 消费研究](../voicebank_doc/41_v4x_runtime_region_consumers.md)确认连接素材带有 outer/inner 区间，实际帧处理会读取区间，不能只替换一个音素字符串而忽略源帧映射。
2. [运行时图研究](../voicebank_doc/101_v4x_runtime_graph_completion.md)已经贯通目录、音素对索引、候选、stage、长度分配和帧工作项。双音素通常是一阶段、两组区间；三音素素材是两阶段、四组区间，同一条音素对可能来自不同素材阶段。
3. 同一研究的跨音符实验表明，同样的音素路径放在一个音符或分到相邻音符中，实际入选素材会不同。素材选择需要考虑音符边界与邻接关系。
4. [REG 控制报告](dse-pitch-layer-control.md)的宿主实验已经遇到并修正进入连接归属、逐音符合成缓存失效等问题。这些基础设施可以复用，但 REG 的评分偏移本身只改变层选择，不能直接代表换成另一音素对。
5. [V4X 与中文规则边界](../voicebank_doc/102_v4x_vs_chinese_layer_rules.md)及 [V5 对照](../voicebank_doc/118_v5_v4x_cross_reference_and_expression.md)说明候选数量、缺边、后缀和三音素布局需要逐库检查；不能由音素存在推断目标连接素材可用。

其中跨音符素材读帧的既有证据属于自建事件条件；REG 报告中的宿主听感验收也只覆盖其记载的参数与路径。两者为本功能提供实现依据，不能替代本功能的音频验收。

## 本轮只读核对的原生入口

复用了现有 Ghidra GUI Program `/v6/DSE.dll`，查询元数据、相关函数和有界交叉引用；安装文件 SHA256 与 Program 元数据一致：

```text
SHA256     7a4965bd377dbc2b08710e807ae1345b67d9fff6579ca0c01a769f744366f5b5
架构       x86 little endian 64 bit
映像基址   0x180000000
```

以下地址仅适用于该哈希，不是跨版本 hook 配置：

| 地址 | 作用与本功能的关系 |
| --- | --- |
| `0x18018d790` | 从素材目录构建音素对索引，保留 part、stage、limit |
| `0x18018e450` | 以两个音素名查询索引范围 |
| `0x1801aa0a0` | 为工作列表建立候选范围，包含缺边压紧等处理 |
| `0x1801acda0` | 联合选择候选并写回所选描述符、分配长度 |
| `0x1801a0450` | 由描述符、实际左右音素名及左右长度生成帧工作项 |

本轮尤其核对了最后一个入口：实际音素 ID 由独立传入的左右名字查询，所选 part/stage 则从描述符复制。二者不是必须由同一字符串强绑定的单个字段。这是保留实际音素、借用其它连接素材的关键切入点。

`0x18018e450` 还有评分及其它调用者。正式实现不能对所有同名音素查询做全局替换；必须限定 Part、目标音符、进入边和渲染代次。

## 原生离线实验

脚本：[probe_transition_context_override.py](../voicebank/tools/probe_transition_context_override.py)。
结果：[transition_context_override.json](../voicebank_doc/evidence/transition_context_override.json)。

实验在独立 Python 进程中加载哈希固定的 DSE，使用自行构造的三组连接元数据：`u→l`、`e→l`、`l→a`，每组有三个候选层。所有组的区间、dynamics 和 tempo 相同，用两种音高层间距及九种目标音高组合控制变量。没有加载商业声库或 PCM。

每组条件依次执行以下五种情况：

| 情况 | 次数 | 验证内容 |
| --- | ---: | --- |
| 原始基线 | 18 | 正常查询、选择并生成 `u→l` 和 `l→a` 工作项 |
| 借用整条连接 | 18 | 仅把第一条边的候选范围换成 `e→l`，继续使用实际音素名 |
| 仅借用进入侧 | 18 | 原 `u→l` 描述符生成左侧，借用 `e→l` 描述符生成右侧，二者相邻 |
| 借用素材缺失 | 18 | 先在独立工作对象查询，不存在则保留原候选 |
| 借用后的基线 | 18 | 再次执行原始路径，检查状态没有残留 |

**共 90 例，零不一致。两个独立进程运行所得完整 JSON 逐字节相同。** 每例均核对：

- 实际音素名和工作列表数量在选择后保持不变。
- 所选 part 确实来自预期的原始组或借用组，stage/limit 保持合法。
- 在本轮匹配元数据条件下，后续 `l→a` 的层选择、区间分配保持一致。
- 输出帧指向正确工作项；源位置与既有独立映射模型一致。
- 借用素材的工作项仍记录实际 `u/l` ID，而不是把工程改成 `e/l`。
- 进入侧模式的第一段来自原 part，第二段来自借用 part；输出区间相邻，后续 `l→a` 仍连接其后。
- 共享音素对索引字节没有变化，缺失候选没有压紧实际工作列表。

进入侧模式中原生函数接受“左长度非零、右长度零”和“左长度零、右长度非零”两次生成。它证明按源区间拆开生成有机械上的可行性；**它没有验证声码器如何处理这两个新相邻工作项的缓存、平滑和音频边界**。

这批 90 例仅覆盖普通双音素元数据，分类表为空，未覆盖真实流音等类别整形。真实借用素材的音高、时长和强度往往不同，联合选择可能连带改变后续素材；不能将控制变量实验里的“不变”外推为任意真实声库均不受影响。

复现命令：

```powershell
$dse = Join-Path $env:ProgramFiles 'VOCALOID6/Editor/DSE.dll'
python voicebank/tools/probe_transition_context_override.py --dll $dse --output "$env:TEMP/transition-context.json"
```

## 两种借用方式的取舍

**整条连接替换**最容易接在候选选择与长度分配之间，但连接本身同时含两侧声音。将 `u→l` 全换成 `e→l`，可能让 `ru` 尾部也出现 `e` 色彩。保留工程音素身份不等于保留此前的波形。

**仅替换目标进入侧**更符合本需求：保留原连接左侧的源素材，目标侧采用参考连接的源素材，各侧使用自身 outer/inner 映射。本轮验证了生成这些工作项的原语；生产实现仍需审计帧缓存和相邻项处理，并试听接缝。两侧时间来源不同，不能直接沿用同一裸帧号，也不能假定恰在音符起点切换。

连接是共享的发音过程。即使保留了 `ru` 主体，为了听起来像从另一元音进入 `la`，边界附近仍可能需要改变一小段声音。产品语义应承诺“保留前音符主体，控制目标进入过渡”，不应承诺前音符全时域波形逐样本不变。

如果所需 `la` 听感还依赖它内部的 `l→a` 或更长上下文，仅替换 `e→l` 可能不够。这时可以扩大借用片段，或用相同音高、时值和控制曲线分别渲染真实上下文与参考上下文，再在已核对的边界上拼接；后者渲染成本更高，适合作为听感对照或后备路线。

## 首个产品原型的建议边界

先支持当前库存在的普通双音素连接，设置附着在**目标音符**上。最小界面可提供“自动”和“参考前置音素”，也可将参考音节经 G2PA 转换后显示实际匹配的音素。先保留原生音高层评分，不同时加入多个混合强度参数。

实现分成四个边界：

1. **持久化与历史**：以补丁自有的逐音符数据保存前置来源与模式，复用 REG 的项目保存、复制、撤销框架。存名字及声库校验信息，不持久化进程内 part 指针。
2. **渲染绑定**：渲染开始前发布只读表，使用已核对的 Part/音符/epoch 映射，解决同音高、重复歌词和并行 Part 的归属。目标是当前音符的进入边，不能把前一音符所有查找都改掉。
3. **候选与分段**：先在独立临时对象查借用候选，检查非空、stage、两侧区间与音素类别；保持原音素列表。让适配层为原侧和借用侧分别生成源位置，再交给原生后级处理。只改 part 指针不足以同时保证区间和分类正确。
4. **失效与回退**：过渡修改要使相关原生合成单元及 PCM 缓存失效，至少包含共享进入边的依赖。首版可复用 REG 已有的整 Part 失效方式；版本签名、音符归属或借用素材任一检查失败时，使用完整原始路径。

EVEC 三音素、Color/Release、跨声库混合应在普通边完成后分别接入。三音素 stage 有邻接资格与联合代价约束，不能只强塞一个 stage，或者把四组按平均长度拆分。没有候选时也不能伪造不存在的录音素材。

## 下一阶段必须验证的声音与宿主行为

首个真实声库样例应准备同一 Part 的三份对照：正常 `ru la`、参考 `he la`、实际 `ru la` 加进入过渡借用。保持两音符的音高、长度、间隔、Velocity、REG 及控制曲线一致，并分别比较 `ru` 主体、边界和 `la` 起音。

先检查借用 part 是否实际进入帧加载与 PCM 输出，再判断听感。既有 REG 调试已证明“选择器指纹改变”可能仍未使最终缓存失效，因此不能只看 hook 被调用就验收。

行为矩阵至少包括连续与留空、短音符与长音符、升降音高、目标位于 Part 首尾、缺失连接、真实音素类别、重复音符、多 Part 并行、EVEC/REG 共存，以及撤销、重做、保存重开。最终还要比较进入侧拆分是否引入爆音、空洞、元音泄漏或时长漂移。

本轮交付为研究报告、离线探针及元数据结果；未修改产品合成实现，未部署或启动、关闭 Editor。未运行解决方案构建；验证包括探针执行、独立重复及 Python 语法检查，声音与宿主内路径留待产品原型阶段。
