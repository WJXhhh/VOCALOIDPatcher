# 独立选样时长的前端接入方案

2026-10-17。基于[根因修复及回归](duration-selection-root-causes.md)、[评分原型](independent-duration-selection-prototype.md)和当前编辑器适配代码。本文保留实施前设计；已完成的源码接入、验证结果与当前限制见[宿主接入记录](duration-selection-host-integration.md)。

建议在 Emotion 内增加明确的“选样”工具，以音符为初始控制单位，直接调节选样时长比例，并辅以精确小面板。真正接入之前，需要把研究进程里的全局评分比例和历史状态改成按 Part、引擎及渲染代次持有的状态，并验证与已有音素 timing 的组合。

## 数据含义与控制单位

用户调的是选材时的假设时长。实际音符长度、VEL、用户已经调整的音素边界仍由原来的时间控制决定。偏好增加不保证录音更长，也不保证换样：引擎还比较录音音高、动态、声学接续和候选资格。

当前原型在联合评分区间使用 `round(regionRealFrames × ratio)`。它没有逐音素独立预算，也没有逐音符隔离的产品路由；`DurationCostHook._scale` 是研究进程级变量。因此初始接入应显示为**音符选样时长**，同一音符的各音素共用比例。后续逐音素、逐过渡控制需要先建立工作区间的归属关系，不能只把一个音素下标传给现有 Hook。

| 项目 | 建议语义 |
|---|---|
| 自动 | 无手动偏好，使用当前明确选定的候选策略；恢复“原生自动”同时恢复原生策略 |
| 手动比例 | 正有限数，相对当前真实时间预算；内部以固定精度规范化后保存 |
| 比例展示 | `50%`，辅助文字为“按约一半时长选样”，不称为素材实际长度 |
| 毫秒输入 | 小面板提供换算：假设音符时长 / 当前音符实际秒数 = 比例；保存比例 |
| 变速或改音符长度 | 比例保留，显示的假设音符毫秒数重新计算；真实时间用 tempo map 两端时间差 |
| 恢复 | 删除该项手动覆盖；不以 0 表示自动或静音 |
| 未来目标 | 模型可预留 Note、Phoneme、Transition，但当前执行器仅接受 Note |

可先在交互示意中用 25%–400% 的对数刻度，中心为 100%，左右各为两次倍增；这只是便于比较的设计范围，尚未证明该范围内所有连续值都可用。原型将各评分区间夹在 1–4096 帧，产品需要报告量化及范围限制，不能默默吞掉超界输入。音符级毫秒显示也不应冒充某一 ART 或音素实际读帧长度。

手动 100% 在原生候选策略下应规范化为无覆盖。候选策略属于独立设置；若用户显式启用扩展来源，即使比例回到 100%，也不能显示为“原生自动”。

## 交互设计

当前 [ConsonantTimingOverlay](../VOCALOIDPatcher/VOCALOIDPatcher/ConsonantTiming/ConsonantTimingOverlay.cs) 的命中顺序为音素边界、音素音量、辅音时长。音素边界附近约 7 像素用于横拖，[音量命中](../VOCALOIDPatcher/VOCALOIDPatcher/ConsonantTiming/ConsonantTimingOverlay.Volume.cs)覆盖音素内部。因此再把普通横拖塞进音素内部，容易在短音素上误操作。

建议采用一个显式工具入口：

| 场景 | 操作与反馈 |
|---|---|
| 现有 timing 和音量工具 | 沿用现有手势；选样标记只读 |
| 切到选样工具 | 在目标音符下缘显示独立短刻度及把手，选择整个音符 |
| 左右拖把手 | 左侧偏短音预算，右侧偏长音预算；提示实时显示百分比 |
| 真实音符和音素竖线 | 固定在原位置；选样刻度使用自己的比例坐标，不沿时间轴伸长音符 |
| 单击把手或右键音符 | 打开精确面板，包含比例、换算毫秒数、候选策略及结果状态 |
| 短音符或缩小视图 | 从音符右键或选择后的面板进入，不要求命中几像素的窄音素 |
| 双击把手或面板恢复按钮 | 恢复自动；快捷键须与现有 Ctrl 多选、双击重置行为统一审计 |
| Escape 或丢失捕获 | 取消候选，不写工程、不生成历史、不启动渲染 |
| 松手 | 一次提交、一条共享撤销记录、一次正常重渲染请求 |

面板初始只显示“整个音符”。`@N x 7` 等多音素会共同受这一个音符偏好影响，不能画出三个可编辑的独立选样把手。将来原生执行器确认支持工作项级约束后，再开放相应目标。

控件延续覆盖层常驻、绘制对象冻结、刷新合并、歌曲坐标转换和视口裁剪的现有约定。新增功能应有独立设置键；入口不能依赖音素音量开关。选样工具激活时，只替换命中路由，不把它伪装为原生 Velocity 数据写入。

## 结果状态与候选策略

现有矩阵在原生候选窗口、权重 1 下没有换样；扩大到 1200 cent、权重 128 的实验才出现明确换样，而且包含跨录音音区。产品不能将这两个诊断常数藏在一个默认滑杆后面。

建议默认保留原生候选策略；扩展来源作为单独、明确标示实验性质的选项，展示可能改变录音来源音区。两者都受真实 timing 约束。候选策略及算法版本必须进入保存和缓存身份，避免重开工程或软件升级后同一比例有另一种含义。

结果按阶段显示：

| 状态 | 能说明什么 |
|---|---|
| 正在调整 | 候选比例变化，尚未写工程 |
| 待查询或规划中 | 请求尚未得到引擎结果，不能显示候选数量 |
| 计划未换素材 | 在本次完整准备和查询覆盖范围内，选中的来源与自动对照相同 |
| 计划将换素材 | 规划结果选中了不同来源；若范围不完整则只显示“计划结果待核实” |
| 等待渲染或渲染中 | 参数已经提交，音频尚未核验 |
| 已渲染并核对 | 已检查本代次实际消费的素材及真实边界 |
| 查询或渲染失败 | 保留本次请求及具体失败类别，不把旧音频标为新结果 |

只有完整枚举并经过资格过滤的结果才能称为“可选素材数量”。研究日志里的评分调用次数或见过的指针数量不能用作候选数。来源比较应使用有界、稳定的素材描述，不保存研究进程中的指针或临时编号。音频变化不能单独证明换样；换样也可能因联合接续影响相邻区间。

## 前后端请求流程

```text
UI 候选比例
  → 已准备的目标音符和必要上下文快照
  → 原生无音频规划与有界选材摘要
  → 检查源版本及请求序号后更新候选提示

松手后的最终值
  → 验证并提交自定义参数及共享历史
  → 为受影响 Part 发布不可变渲染快照
  → 通过现有 VSM 缓存身份触发正常重渲染
  → 检查代次、实际素材及真实 timing 后发布结果
```

MouseMove 仅更新候选和最新查询目标，不修改服务模型，不触发 `StartAsyncRendering`。局部规划串行处理同一准备对象，最多一个运行请求和一个可覆盖的最新请求；进入昂贵工作前和返回后均检查源版本。冷启动及输入准备放到后台，UI 线程只采集安全快照和更新显示。

松手时若最终目标尚未查询，保留最终请求进入一次校验，不能悄悄提交上一次响应对应的比例。用户在等待期间换音符、改 VEL、拖 timing、Undo 或关闭工程，旧请求立即失去发布资格。共享原生锁只允许短时 try-lock 和最新请求重排，不能在 UI 线程阻塞等待音频渲染。

查询结果建议包含 `RequestId`、源 Session、源 Revision、目标身份、候选规范化值、候选策略、时间计划指纹、素材摘要及状态；其中计划结果和实际渲染结果使用不同字段。0.364 ms 是上轮已准备输入的纯 planner 中位耗时，不是宿主拖动延迟目标；还需分别记录输入准备、排队和端到端 P50/P95/最大值。

## 真实 timing 与既有控制的组合

新功能的参照必须是“选样自动、保留当前 VEL、浮点系数及所有音素 timing 调整”的时间计划，不能拿无用户调整的音符作为参照。

已有 [phoneme_timing.rs](../native/playback-clock/src/phoneme_timing.rs) 在 allocate、stationary、mapper 的输入端应用 warp；[DurationTimingContract](../voicebank/tools/evec_render_harness/DurationTimingContract.cs) 则在更上游接点整形、最终分配和提交静音处限制原生计划。建议先采用**保存 warp 前的真实分配计划，然后让现有 warp 只执行一次**的组合顺序；需要通过组合探针核对，不能把最终已 warp 的段长再交给现有 warp。

局部规划和正式渲染必须复用相同输入、上下文、候选策略与组合顺序。现有纯 planner 测试没有证明所有非零用户边界偏移都符合新组合契约。若更换素材造成工作项拓扑变化，应返回明确不支持的组合及根因；不能覆盖回原音频、平均切分音素或移动波形来掩盖。

## 原生渲染归属与并发

研究类中的 `_active`、回调 scratch、时间计划游标和音色头部均是串行独立进程实现。它们不能直接注册到编辑器。

可复用 [sampled_timing.rs](../native/playback-clock/src/sampled_timing.rs) 的 Part → render scope → parser → schedule 绑定机制，但需要扩展出独立选样上下文：

| 状态 | 建议归属与生命周期 |
|---|---|
| 用户选样参数 | 工程文档；UI owner 线程修改 |
| 选样及时间计划快照 | Part、渲染代次；原生只读引用计数对象 |
| 当前评分区间与目标归属 | parser 和 schedule；明确 current/target 音符及其联合工作区间 |
| 调用暂存及递归栈 | 线程内的调用栈项；不能用一个全局 context 槽 |
| 时间计划消费游标 | 本次引擎实例及 scope；前瞻撤回必须恢复已观测的检查点 |
| 音色历史 | 每次渲染独立头部；共享只读表的寿命覆盖所有读者 |
| 层间平滑历史 | 每次渲染独立值；访问全局 BSS 的交换区间由共同同步机制保护 |

尤其要验证目标音符比例不会作用到另一 Part 或不属于它的邻接评分区间。跨音符联合区间如何处理相冲突的偏好，应先以原生分段归属为依据定义，不能用“最近音符”或全进程 NOTE 次序猜测。

层间平滑涉及 DLL 全局值；单个引擎里的递归互斥锁尚不足以证明跨引擎互斥。生产 Hook 必须让全部相关访问，包括未启用选样的普通渲染，也遵守同一锁序，或改为真正的实例状态访问。不能靠把全部音频渲染串行化来宣称完成并发。

[NativeRenderSession.Gate](../VOCALOIDPatcher/VOCALOIDPatcher/Utils/NativeRenderSession.cs) 只协调主动使用它的补丁渲染路径；真实宿主通过原生 render-core scope 进入，并不自动受此 Semaphore 保护。计划器、自动渲染、导出及复制工程路径都必须纳入验证。

原生热路径采用 Rust 有界数值结构，避免逐帧进入托管、分配字符串或生成诊断大字典。新增 ABI 使用独立结构及明确版本；若改变现有 ABI，须同步托管封装、尺寸检查和版本。

## 保存 撤销 与缓存

选样是独立的数据语义，建议新增 `DurationSelectionPlan`、`DurationSelectionHost` 和 `VOCALOIDPatcher/duration-selection.json`，复用共享历史协调器及工程保存事务。不要把它塞进 `TimingAdjustment`：当前 `PhonemeCoefficient()` 只接受系数和音素边界，其它 Kind 会被执行器拒绝。

保存参数包含规范化比例、目标种类、候选策略及评分算法版本；不保存原生指针、查询结果、波形、计划消费游标或预测边界。自动无覆盖可以省略。全部字段先校验后应用，并保留有界 ZIP/JSON 读写约束。

运行中优先复用 `BreathVolumeService.NoteGeneration` 的音符代次与明确的复制生命周期；保存时将活音符解析为当前定位及完整身份，加载时严格匹配。仅复用旧 `TimingNoteAddress` 字典会在移动、改长度、音高或声库后变为 detached，不能把这种失联作为新参数的正常编辑行为。删除后撤销、指针复用、复制粘贴和多 Part 复制都要显式传递或恢复值。

[SampledTimingProjectSavePatch](../VOCALOIDPatcher/VOCALOIDPatcher/Patch/Patches/SampledTimingHostPatches.cs) 目前先写 timing，再写音量，保存态与 dirty 状态也由各模块处理。添加第三项时，应将三类扩展写入和 dirty 确认放在同一个成功边界：任何一项失败都不能把内存标为已保存。Load、备份、自动保存、DuplicateSequence、内部渲染副本及导出使用同一份快照契约。

原生 [timing_cache.rs](../native/playback-clock/src/timing_cache.rs) 已有 immutable snapshot → live Part 的查找路由。扩展其内容指纹，纳入选样参数、候选策略、算法及时间契约版本，保持旧字段参与；不以清空全局缓存代替正确身份。查询缓存还需包含源输入、上下文、tempo map、当前 timing 计划及引擎版本，不能只用“比例相同”判命中。

内容指纹与发布代次分开：相同内容可复用同一缓存身份，但旧回调仍需通过当前 Session、Revision 和请求代次检查。撤销恢复应同时核对参数、边界、实际素材及 PCM；只看到滑杆回原位不算完成。

## 实施顺序与验收

1. **原生迁移及归属验证。** 先建立可重入、按 Part/引擎持有的上下文，验证两个相连音符采用不同偏好，以及不同 Part、规划器和普通渲染混跑不串值；移除所有研究全局游标。
2. **组合与数值验证。** 覆盖 VEL 两端、浮点系数、左右边界非零调整、多音素、变速、前瞻撤回和恢复；扫查 100% 附近及量化阈值。当前评分仅在 `virtualFrames != duration` 时替换，高权重公式在阈值附近可能出现突变，不能未测就承诺连续音色变化。
3. **文档生命周期接入。** 在没有新 UI 的情况下验证交错原生/自定义撤销、保存失败、加载、复制、移动、删除恢复、同路径渲染缓存及晚到结果。自动档在原生策略下与无补丁基准做精确对照，手动恢复对比同一策略下的基准。
4. **无音频查询接入。** 验证规划结果和实际消费素材摘要，分别统计准备、纯查询、锁竞争和 UI 延迟；连续快速改值只保留最新请求，不排队合成音频。
5. **工具与小面板接入。** 先单音符，再扩展批量；检查窄音符、滚动缩放、换 Part、Escape、LostCapture、播放中编辑和连续拖动。新增文本同步四语言翻译和设置刷新。

每项验证失败均定位到输入、路由、时间计划、状态历史或缓存的具体层次。发布条件是该路径的根因解决及回归通过，不通过扩大边界容差、忽略音频差异或使用旧结果伪装成功。

本轮仅完成源码审查与设计整理，没有修改产品执行代码、启动编辑器或部署；没有新增宿主验证数据。界面示意中的比例范围、毫秒和状态均用于交互评审。
