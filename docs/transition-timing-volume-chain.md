# 过渡音 timing 与音量：实际引擎链路

2026-10-17。接续[起音/尾音内部时长研究](articulation-edge-duration-research.md)，本轮扩展到多音素、相邻音符、短音符、擦音和真正的三音素 ART 两阶段。只新增独立研究探针和验证报告，没有接前端、修改生产合成链、部署或操作正在运行的 Editor。

## 已得到的结论

**timing 和音量都有可用的原生控制切口，且应作用于实际 ART 工作项。** 两者不需要用候选录音评分来间接实现。

- timing：在既有音素边界保持不变时，可调整 ART 与相邻持续段之间的内部接点，改变两侧实际输出长度与源帧读取。独立可调范围取决于当前规划；不是每个端点都有剩余空间。
- 音量：已找到并验证原生合成帧加入重叠相加缓冲前的线性增益。只对目标 ART 驱动的帧贡献乘增益，不改工程 DYN、候选、音素边界或输入频谱，也不对最终 WAV 做时间窗乘法。
- 两版实际组件各完成 **125 次渲染、625 次无音频规划**，另各记录 7 个无独立可调空间的请求。两版的 PCM、工作项、源帧映射、增益输入与支路记录逐项相同。范围与摘要见[证据](evidence/transition-control-chain-20261017.json)。

这里的“单独”是针对 ART 驱动的合成帧贡献：这些帧已经经过原生取帧、插值和音色处理，不能再将其中混入的每条录音视作可独立分离的声轨。本轮没有承诺任意过渡的音质、无限时长或全部宿主行为已经验收。

## 目标身份与静态核对

复用 Ghidra 当前 GUI Program `/v6/DSE.dll`，成功读取元数据、所需函数和有界交叉引用；没有导入、切换或修改项目。该目标仍是旧 DSE，SHA256 `7A4965BD377DBC2B08710E807AE1345B67D9FFF6579CA0C01A769F744366F5B5`，x86 LE64，映像基址 `0x180000000`。

新版 DSE SHA256 为 `844452F19271B66634A625F37068933BADDD607C3670278C58580528A3CE9DFD`。[第二版本验证](second-real-version-compatibility.md)已核对两版 DSE 代码节相同；本轮进一步在两套真实 DSE/VSM/托管 SDK 中运行同一研究 harness。以下均为 DSE RVA，适用于这两个已核对的哈希，不能作为其它版本的默认地址。

## 从音符到声音的控制链

| 阶段 | 入口 / 消费者 RVA | 本功能相关职责 |
| --- | --- | --- |
| 输入准备 | VSM NOTE/Singer 编码；DSE `0x1B2AB0` | 将音符和控制事件提交给私有/真实引擎 parser；生产输入复用已有局部后端 |
| 工作列表 | `0x1A2DD0`，另有直接树路径 `0x1B54D0` | 按上下文组织音素、静音、连音、预算和候选；不能只凭音符显示长度推断 |
| 索引候选 / 联合选材 | `0x1AA0A0` → `0x1ACDA0` | 选取 part、stage、方向；三音素 stage 有邻项资格与联合代价 |
| 整形 / 预算分配 | `0x1B2260`、`0x19D650` | 按 alignment、音素类别、系数、剩余时长分配实际两侧长度 |
| ART 帧映射 / STA 生成 | `0x1A0450` / `0x1A7F30` | 产生 ART 与持续段工作项及输出帧→素材源帧映射；既有 timing warp 在此生效 |
| 接缝准备 | `0x16AF70` | 准备、复用相邻工作项的帧缓存；更改内部长度也会改变其依赖 |
| 取帧 / 插值 | `0x16A870` → `0x1757A0`，必要时 `0x1753A0` | 消费所选 part、方向和源帧位置，读取 alignment、分类并插值 |
| 原生帧处理 | `0x16A250`、`0x16FCB0`、`0x165350` 等 | 完成音高及相邻帧处理；不是简单拷贝录音 PCM |
| 频谱准备 | `0x16E830` / `0x16CE20` 等分支 | 依据有声/无声和配置生成后续合成帧；DYN 在这里也有消费，不能用修改 DYN 冒充纯增益 |
| 当前帧加入合成缓冲 | **`0x141F50` 的第五参数** | 接收线性增益，乘当前帧的时域贡献，再与已保留的重叠部分相加，之后生成整数输出 |
| 最终混合 | `0x171E10` | 混入其它活动对象及输出处理；不是天然携带单个 ART 身份的独立声轨接口 |

mapper 调用引用分别回到 `0x1A2DD0` 和 `0x1B54D0`；长度分配与联合选择的引用也回到工作列表生成器。`0x141F50` 两处代码调用均来自真实帧输出循环 `0x168940`。合成入口首 17 字节已按完整指令边界核对，研究 detour 同时校验精确组件档案及指令前缀；未把 Ghidra 推断出的函数原型直接当作可信 ABI。

原生输出循环对控制器 2 作非线性变换（可见 `log10(9*c + 1)` 因子），再与其它当前帧因素组合，传入上述线性增益参数。自定义音量应在这个**已经计算好的 native gain 上乘自己的系数**，而不是反写控制器 2。素材 `dynamics` 候选坐标又是另一层，见[同音力度分层核查](same-pitch-dynamics-sampling.md)。

`0x176240` 及其活动对象列表还涉及共享 DVQM Attack/Release 资源。本轮没有把这类附加发声对象等同于普通 ART，亦未声称同一 gain 切口已独立控制其所有输出。

## timing 的对象和限制

一条 ART 工作项包含：输出开始 L、左右分配交点 S、输出结束 R、实际 from/to、part/stage/limit、方向以及源区间。三音素素材的 stage 0/1 分别读取 alignment 0/1 与 2/3；它们可能共用 part，不能只按 part 指针合并设置。

本轮固定所有已有音素/context 锚点及目标 ART 的 S，分别移动 L 或 R，实际改变“前音素尾部/后音素头部”被这条 ART 占用的时长。相邻 STA 让出或取得时间。移动 S 则属于音素边界控制，不能与内部接点移动混为一件事。

研究原型提出 ±6 帧请求后，按真实相邻锚点计算可达位置，记录**实际**移动量（例如 MIKU `k→a` 左端只可外移 1 帧）；所有有效锚点保持严格有序。无空间时明确记录不可达，不合成另一组声音充当成功结果。此 ±6 帧是验证输入，不是产品限制或默认参数。

两版均出现相同的 7 个不可达请求：

- 中文多音素夹具的目标 ART 右端与受保护音素/context 边界重合：右伸、右缩及本轮要求同时改两端的组合请求不可执行。
- MIKU `n→n#2→a` 的 stage 0 右端及 stage 1 左端，在保留音素交点后没有可独立调节的整数帧区间：各两个方向的请求不可执行。

这些是“保持本轮保护锚点”的自由度限制，不是证明该素材永远不能调整。若需要改变这个共享位置，必须作为共享接点/音素 timing 操作重新规划，不能给同一坐标保存两份矛盾的边界。

还核实了一个原型判据错误：起初逐行比较完整素材序列，三音素 stage 1 右端外移时被判为“换样”。保留实际工作项后发现，ART 身份与顺序完全相同，持续素材也相同，但 STA 从 4 个重复分块变成 3 个。现分别检查 ART 完整序列、STA 连续来源序列及原始分块数；不再用重复次数冒充选材身份。原始两组工作项留在本机 witness，正式结果保留 `sameRawRowCount=false`，没有丢弃这一变化。

## 音量切口的实证

研究 hook 在真实输出循环中读取当前 schedule row，用真实起止、from/to 和 stage 确认目标，再仅将其 `nativeGain` 乘 `10^(dB/20)` 或 0。没有更改素材、工程参数、输入频谱或最终 WAV。

同时观察到 `state+0x1FC8` 与 `state+0x2B128` 两条 analysis 支路调用该入口。探针分别记录为 primary/auxiliary，并对同一目标 ART 的两条实际支路一致施加增益。只捕捉一个调用点或一条支路，会遗漏另一部分贡献；这些指针仅用于当前私有进程识别，没有持久化。

每个夹具有未安装 hook 的真实基准、安装 hook 的 0 dB、-12 dB、+6 dB、静音和恢复：

- 未安装 hook、0 dB 和两次恢复的 PCM hash 相等。
- 纯音量变体的完整音素边界、工作项及源帧映射与基准完全相同。
- 进入合成入口的谐波频率/幅度数组、残差频谱数组及原生 gain 逐次相同；变化仅在自定义乘数。其它 row 的 gain 不变。
- 中间不受邻帧重叠影响的区段，RMS 比达到约 0.2511886 / 1.9952623；静音区样本为零。独立汇总器使用绝对误差 0.0002 校验整数 PCM 的量化差异。
- 本批所有纯音量变体，变化均局限于 ART 对应输出区及其**尾端 1 帧**重叠区，外部 PCM 字节完全相同。44100 Hz / hop 256 下，一帧约 5.805 ms。

尾端这一帧是合成窗重叠的真实结果：最后一个 ART 帧的贡献还留在下一块缓冲中；静音该 ART 也不会把此前相邻帧已经留下的贡献一起清零。应当返回并解释这个影响区，不能裁掉它来伪造矩形作用范围。1 帧是本批实际合成配置的测量结果，尚不是所有分析窗、音高及模式的普遍上限。

本轮测试的是常量段增益，不是完成了生产平滑包络。后续应以 ART 帧坐标生成连续包络，在该乘法切口消费；不可把本轮逐帧指纹/数组哈希等研究开销带入正式渲染路径。

## 矩阵、性能与版本

11 个夹具：中文独立 `a` 的起音/尾音、`l a` 内部、`ts\_h i iE_r @N`、相邻 `a / l a`、短 `l a`、`s\ i_n n`、MIKU `k a`、相邻 `a / k a`，以及真正的 `n n#2 a` 素材 stage 0/1。

各夹具包含 12 种请求。每版 132 请求中 125 次实际渲染、7 次明确不可达；每次有效渲染后重放 5 次私有规划，共 625 次。两版实际托管 SDK 分别为 6.13.1.1 和 6.13.3.1，harness 均由最低已认证 SDK 编译。

每次私有规划都比较真实消费的 ART 起止、左右分配、来源与逐帧源位置，DSE Start/Step/PCM 样本计数变化全为零。查询不是仅依赖最终 score 或可视边界。

| 已预热的私有规划与读取/核对 | 中位数 | P95 | 最大 |
| --- | ---: | ---: | ---: |
| 旧组件 | 1.5944 ms | 2.1986 ms | 4.1642 ms |
| 新组件 | 1.3654 ms | 1.9266 ms | 14.9593 ms |

该时间包含研究中读取并比对帧表，排除引擎创建、输入捕获、冷初始化与界面调度；不能作为完整拖动延迟。新版存在约 15 ms 的尾部样本，不据此声称恒定 1 ms。

## 接后端之前还需要什么

下一步适合先形成独立的过渡布局查询/控制数据，而非立即画滑杆：

1. 在既有准备窗口中返回 ART 与 STA 数值快照：两端音符身份、音素边、stage/方向、输出 L/S/R、保护锚点及左右可达范围。不要保存原生 part 指针或按音符百分比猜范围。
2. 将内部控制与已有音素边界控制组合成一次单调映射；显式识别共享接点和零自由度。改变 VEL、词、音高、休止或选样后重新规划并核对归属。
3. 音量以 ART 身份和渲染代次发布不可变包络；同时覆盖实际需要的 synthesis 支路，保留原生 gain。跨音符 ART 依赖两侧，不能只失效显示上拥有设置的后一音符。
4. 分别验证外部音素 timing/系数/选样的组合、反向素材及缺边、其它分析窗和声学模式、DVQM/EVEC 附加对象，以及 Part 路由、并发、保存、共享撤销和缓存。不得把独立 harness 的进程级 hook 直接移入宿主。

本轮的多音素和三音素原型已说明切口可用，不代表以上产品生命周期已经实现。真实声音只做数值检查，未做主观听感或接缝品质验收。

## 复现与交付

- [TransitionControlProbe.cs](../voicebank/tools/evec_render_harness/TransitionControlProbe.cs)：`--transition-control-probe`，独立私有工程及真实引擎渲染。
- [summarize_transition_control.py](../voicebank/tools/summarize_transition_control.py)：重读两版原始报告和 WAV，验证 PCM 作用范围、增益比、源映射及版本逐项一致，生成可提交摘要。

```powershell
dotnet build voicebank/tools/evec_render_harness/EvecRenderHarness.csproj -c Debug --artifacts-path <隔离目录> "-p:VocaloidReferenceDirectory=<合法旧 SDK 目录>"
# 分别使用真实新/旧 SDK 的 harness 副本，并显式设置各自原生组件目录。
$env:VOCALOID_PROBE_EDITOR = '<相应真实 Editor 组件目录>'
$env:VOCALOID_TIMING_PROBE_NATIVE = '<已验证双档案 native DLL>'
dotnet <对应 harness.dll> --transition-control-probe --patcher-dse-initialization <结果目录>
python -B voicebank/tools/summarize_transition_control.py --old <旧结果> --new <新结果> --old-editor <旧组件目录> --new-editor <新组件目录> --output <摘要.json>
```

harness 与最低 SDK 编译的整个 Debug 解决方案构建通过，零警告、零错误。安装主补丁/native DLL 哈希及符号链接再次核对保持部署基线不变。原始 WAV、工作表及失败 witness 均在仓库外，未提交专有代码、DLL、工程或音频。
