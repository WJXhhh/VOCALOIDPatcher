# REG 选样不一致与临时工程终结器崩溃

2026-10-22。用户现场两次在 `WIVSMSequence.Finalize()` 抛出“原生对象尚未销毁”，Windows 记录为未处理的托管异常。崩溃前均先记录 ART 结束帧预计 3286、实际 3287，随后自动恢复。

## 边界偏差

使用保存工程的只读副本，在独立 DSE/VSM 进程复现同一差异。源 Part 起始两个音符音高、时长相同，REG 分别为 +6、+7。局部规划按确定的原生帧位置匹配 REG；正式渲染的 REG 路由原来会从重复音符推断时间原点，首次 current 查询可能无法消除歧义，漏用该次 REG。后续 target 查询得到匹配，已经不能纠正先前选出的素材。现场素材不同，过渡长度随之不同，并非可以放宽的一帧数值误差。

已绑定且仍属于当前代次的 sampled timing 渲染使用同一条经过验证的 VSM→DSE 固定原点（3087 帧）。REG 精确匹配音符位置、长度和音高；没有有效绑定的路径保留原有校准。过期绑定和不唯一的匹配继续拒绝。没有改变过渡校验、存档偏移、音符输入或用户 REG 数值。

Rust 回归明确重建相同音高、相同时长而 REG 不同的两个音符，验证第一次查询即得到正确 REG，以及错误代次、错误位置和失效绑定不会匹配。

## 原生所有权

旧后端忽略原生 `Close()` 的 false 返回值；释放后端引用后，仍开放的 owning wrapper 可能被 GC 终结。连续重建还观察到原生管理器已经移除对象、托管包装却仍持有旧指针的状态；盲目重试会访问已释放或已复用的地址。

修正后的清理先由管理器验证归属，再访问原生对象；存在未提交的私有修改时先回滚。仍存活而未成功关闭的 owner 转入强引用重试队列，所有关闭在原 owner 线程执行，重试限次后仍保留所有权。只有管理器明确证明原生对象已不再存在，才清空该私有包装的指针。没有全局吞掉终结器异常，也没有对仍存活对象禁止终结。

后端使用引用身份保存所有私有 owner，准备状态清理异常也不会跳过剩余对象的释放。应用关闭前停止定时重试并执行最后一次清理；关闭后排队回调不得访问管理器。MCP timing 诊断增加 `privateSequenceCleanup`，报告待关闭数、失败次数和已释放包装的确认次数。

## 验证边界

独立入口为 `--transition-host-probe`，设置 `VOCALOID_SEQUENCE_FINALIZER_PROBE=1`，`VOCALOID_TRANSITION_SOURCE` 指向本机工程。默认查询第 7 个非空采样 Part，可通过 `VOCALOID_SEQUENCE_TARGET_PART` 覆盖。该入口交替验证分块／非分块渲染，每次重建后强制 GC，检查音符输入、过渡存档指纹、原生失败计数及自动恢复记录。`VOCALOID_SEQUENCE_CLEANUP_PROBE=1` 单独注入关闭失败，验证强引用跨 GC、重试释放，以及已销毁原生对象的包装确认。

两版 SDK 使用同一份以最低 SDK 编译的隔离验证程序集和待部署 Release native。工程副本、原始诊断和 WAV 不进入仓库；源工程文件哈希在重放前后检查。真实 Editor 没有由代理启动或关闭，独立回归不能代替部署后的交互试听。
