# 同一 a：音素 timing、过渡两端与完整起音进度

后续目标已于 2026-10-18 澄清：菱形应服从现有 timing 范围，不得向外延长。新的独立对照与范围验证见 [固定范围内的表现映射](fixed-range-expression-comparison.md)。本页保留旧目标的研究与部署记录，不能作为新版交互语义。

2026-10-17。用户实测：音素起点提前可以得到较早、较柔和的主体起音；当前过渡左端只拉出弱前缀。本轮按同一音进行独立 SDK 对照，增加源帧进度研究原型。未部署，未修改正在运行的编辑器工程、生产 UI 或原生 DLL。

## 结论与证据范围

**图二所指的主体起音效果，在研究原型中已经复现；只调当前过渡两端不足以得到该效果。缺少的是同一 ART 内部的源帧读取进度控制。** 原型保持音符位置、长度、音高、VEL 和已有音素边界不动，并没有借助最终 WAV 淡入、音量增益或换录音。

这不是整段声音逐样本完全一致或主观听感验收。原型仍与音素 timing 参考在最初几帧、后续持续段和收尾存在差别。截图没有附带原始音频或精确拖动值，因此此处验证的是“主体起音在音符之前形成”的目标，不是与截图像素或未知原始声音完全相同。

汇总见 [JSON 证据](evidence/onset-process-comparison-20261017.json)。实际波形、10 ms RMS、逐帧源位置和原生合成输入记录保留在仓库外；分析脚本可重新生成图和统一音量的试听文件。

## 同音与对照定义

只读查询确认用户当前音符为声库 `BL8CEAM5N4XN3LFK`、`a`、MIDI 60、VEL 64、位置 960 tick、长度 480 tick。独立工程按相同条件建立，120 BPM 下长度为 500 ms，普通默认表情，不读取或改写用户控制数据。

所有对照使用同一个临时音符、同一实际 ART 素材对象，固定音乐音符。基准、8/24/48 帧请求、恢复交错运行；24 帧约 139.32 ms：

1. 音素起点提前，作为目标声音参考。
2. 过渡左端提前，Split 不动。
3. 过渡右端延后，Split 不动。
4. 两端同时外扩，Split 不动。
5. 两端直接使用音素参考的真实 L/R，但保留原 Split；排除“只是左右端没拉对”的解释。
6. 同样 L/R 和原 Split，将同一 ART 的源帧读取进度改为参考规划得到的进度。
7. 只改源位置、不复制帧标志；区分源进度与其它标志的作用。
8. 接缝预算假设的诊断对照，明确记录目标是否真正消费控制。

未对每个文件单独归一化，也未对齐、平移音频后计算相似性。时间轴是固定音符起点，包含原生 presend；RMS 窗为 441 samples（10 ms）。试听副本采用相同裁剪范围和同一倍率。

| 原始 | +35.374 ms | 0.053816 | 0.0023% |
| 音素起点提前 | -95.510 ms | 0.038601 | 42.9424% |
| 过渡左端提前 | +35.374 ms | 0.053816 | 1.0754% |

能量比例的分母为音符前 350 ms 至后 200 ms 的总能量，分子为其中音符之前的能量；不能解释成全 WAV 的百分比。主峰也在这个公共窗口内查找，不单独改变各对照的窗口。

参考和原型达到基准峰值 50% 的时间同为 -111.814 ms。原型与参考在公共窗口内 RMS 包络的均方根误差为**基准峰值的 0.364%**，不是“全音频只有 0.364% 差异”。当前左拉在原 Split 之后的起音区域与基准 PCM 完全相同，说明主体确实没有被拉过去。

原型、仅改源位置的原型，完整 PCM 相同。这排除了本夹具中“必须通过复制其它帧标志才能得到主体起音”的解释。

## 从边界到实际声音的链路

### 1. 预算和端点不等于发声进度

原始起音 ART：`L/S/R = 3343/3345/3378`。源素材有 35 帧，其 alignment 把前侧分给源帧 0…1，后侧分给 2…34。

当前过渡控件将音素/context 边界与 ART Split 固定。左拉后，L/S/R 变成 `3319/3345/3378`：前侧从 2 个输出帧扩成 26 个，但仍只读源 0…1；主体源帧 2…34 的时刻不变。枚举本夹具两个单轴范围的 **242 个实际可达候选**，Split 之前的源位置最大值始终为 1；查询中的 DSE Start/Step/PCM 样本计数均为零。

右拉只改变 S…R 的读取速率。主体变慢、主峰稍晚到达，但无法使主体在固定 Split 之前开始。两端外扩或缩成参考 L/R，仍没有解除这种源区间分配约束。

音素参考的 L/S/R 为 `3319/3321/3363`，S 确实提前，同时后侧分配和其它区间重新分配。此前“拉长起音 ART 且 PCM 改变”的验收不足以证明实现了这种起音形态。

### 2. 缺失的源进度控制

研究原型保留 `S=3345`，两端采用参考 `L=3319, R=3363`，在实际消费前替换这个 ART 的 schedule entry 源位置（entry+8）。源位置由同一素材、同一原生参考规划产生，没有交换 material 指针，也没有重写音频。

此时原 Split 之前已经读到源位置约 19.95，而不是只读到 1；在原 Split 之后接着读约 20.73…34。主体发声因而能够提前。原生返回的音素边界仍为 `[-2,477]` tick，与基准一致；音素 timing 参考则为 `[-136,477]`。

这些边界差异直接核对 native score，不是只在界面保留旧边框。原型的收尾源帧映射与基准完全相同，未把整段参考 warp 偷换成当前工程的音素 timing。

### 3. 源帧经过原生处理，再乘原生音量

已重新核对 Ghidra GUI 中的旧 DSE 元数据、所需反编译、调用引用及接缝入口指令；未导入、切换或修改 Program。旧 DSE SHA256 为 `7A4965BD377DBC2B08710E807AE1345B67D9FFF6579CA0C01A769F744366F5B5`，新版为 `844452F19271B66634A625F37068933BADDD607C3670278C58580528A3CE9DFD`，映像基址 `0x180000000`。下列地址仅用于这两套已认证组件：

| DSE RVA | 本轮核对的作用 |
| --- | --- |
| `0x19D650` 等上游分配 | 音素时长预算与类别约束 |
| `0x1A0450` | 按素材 alignment 和左右长度产生源帧位置；并非将完整起音均匀拉伸 |
| `0x1A7F30` | 持续段的生成与重复 |
| `0x16AF70` / `0x1751F0` | 相邻工作项的接缝准备与相关预算 |
| `0x16A870` → `0x1757A0` / `0x1753A0` | 实际读取源位置、取帧及插值；消费 entry+8 的整数/小数部分 |
| `0x141F50` | 已处理合成帧乘原生 gain，再参与重叠相加 |

因此完整关系是：**音符与预算 → ART/STA 分配 → ART 源进度 → 取帧/插值/帧处理 → 原生 gain → 合成窗重叠 → PCM**。过渡覆盖范围、源进度、音量不是同一个参数。

所有变体在相同输出帧、相同 synthesis 支路上的原生 gain 完全相同。参考和原型把主体源帧送到了更早的时间，那里原生 gain 较低；当前右拉使主体到达更晚。这可以解释为何端点时长的变化不能直接等同于预期的响度起音变化；本轮没有证明该 gain 曲线只由某一个 Accent/DYN 参数产生。

## 剩余差异与被排除的假设

24 帧参考与原型的 ART 消费位置、素材身份和源位置一致。86 份 primary/auxiliary 起音合成输入中，84 份的频率/幅度/残差数组哈希及 native gain 完全一致；差异是原生帧 **3319、3320 的 primary 输入**。

这导致最初 3 个输出块存在 PCM 差别，包含一帧重叠贡献。排除这段已明确发现的差异之后，起音主体 **10,496 samples**（约 238 ms）与参考逐采样一致。8/48 帧原型也出现主体一致、前端局部不一致的模式。这个“主体一致”不能冒充完整起音逐采样相等，公共窗口包络误差仍包含最初差异。

原先怀疑 `0x1751F0` 的 incoming-left 预算导致前两帧不同，已增加精确 prologue 校验的独立研究 hook 检查。该入口在本夹具只为后续持续段和收尾调用，没有为目标 `Sil→a` 起音消费控制。两组诊断的 `seamControlConsumed=false`，不计作成功控制；不能据此宣称修好了接缝或已经确定这两帧的根因。后续应继续定位前端帧的预处理/缓存，而不是静音、覆盖或裁掉差异。

后续区间也不完全相同：音素参考将持续段结束/收尾开始移动到 3412，原型保留基准的 3416。保持其它区间不动是独立起音控制的预期隔离，但意味着完整 WAV 本就不应强求与整套音素 warp 逐样本相同。

## 验证与后续接入边界

同一最低 SDK 编译的 harness 分别加载真实 6.13.1.1 / 6.13.3.1。每版 25 个记录变体和 1 次预热，共 **52 次实际渲染**；两版对应变体的完整 PCM、ART/STA 源帧计划逐项相同。每组恢复均与自身基准 PCM 完全相同，实际 material 对象未变。原生运行库使用部署基线的 Release DLL。

独立 harness 和整个解决方案 Debug 均通过隔离构建；没有修改 Rust 生产源码或新装原生 detour 到 Editor。安装目录主 DLL/native DLL 的哈希保持本轮开始时的值。研究 detour 只存在于独立进程，随进程退出释放。

后续产品方向应增加 ART **源进度/主体起音位置**，不能继续把覆盖带左端包装成“完整起音”。接入前还需：

- 明确源进度和 L/S/R 的合法组合、前端帧预处理及缓存依赖；保留受保护的音乐/音素边界契约。
- 验证辅音、连音、反向 ART、stage 1、缺边、声库变化及现有 timing/音量/选样组合。当前只认证这一个 `a`。
- 原生侧在正确的 mapper/取帧及预处理生命周期执行，按 Part/epoch 发布不可变数据，并把源进度纳入缓存身份。不能照搬研究中每次输出前遍历写 schedule 的方式。
- 独立处理保存、撤销、并发和版本能力，不在未知版本重放地址或丢弃工程数据。本轮不接 UI，也不部署。

试听仅用于后续主观判断，未声称已完成主观听感一致性验收。

## 2026-10-17：用户接受差异后的正式接入

用户接受上述主体起音效果，并同意把最前端和持续段的细微差异留作记录。新增独立的 `Onsets` 控制，不改变旧工程端点控制的含义。过渡模式选中 `起始→音素` 后，上方菱形横拖控制完整起音提前；往右拖回 0，Ctrl+单击归零，精确面板可输入非正的毫秒偏移。过渡覆盖范围和 dB 仍分别控制。

正式路径是：私有无音频边界参考计划 → 校验同一个 ART 素材/阶段/方向 → 保留真实音素接点的覆盖分配 → 不可变源帧进度表 → 统一 Part/epoch 发布 → mapper 分配完成时写入新建区间 → 原生取帧、合成。没有在每次 Step 遍历或重写整张表，也没有改 PCM。实际合成时再次核对当前行及源位置，未消费正确控制会报告失败。源帧表与 gain、warp、系数一起参与原生缓存身份和退休代次保护。Clock ABI 15，transition ABI 2；旧导出保留。

短辅音/低 VEL 的参考 ART 范围可能越过受保护的 Split。真实覆盖范围按当前共享接点的合法区间分配，参考源进度重采样到该范围；控制继续执行，音乐/音素边界不动。此时不承诺与整体音素 warp 产生相同的声学形状。`l a` 的 VEL 17/64/65/66、现有浮点 timing、音量、独立选样、原生移动/删除、共享撤销、保存加载、复制、缓存重开、双 Part 并发均通过两套真实版本的独立宿主回归。

同一个中文 `a` 的 -8/-24/-48 帧正式渲染与用户认可的研究原型**完整 PCM 相同**，两版本对应 PCM 相同；主体起音与音素 timing 参考相同，真实音素边界不变，每次归零都恢复基准 PCM。剩余差异仍是最初 3 个输出块和后续持续/收尾分配，不用裁剪、静音或其它处理掩盖。证据见 [正式接入音频校验](evidence/onset-progress-deployment-20261017.json)。这只认证该中文 `a` 的目标形状，不能推广为所有声库、辅音、连音均与音素 timing 声学等价。

完整可调范围首次查询约 43–47 ms，命中缓存约 0.4–0.5 ms；已有源参考的单点规划约 0.2–0.35 ms。本机该夹具可调 -170…0 帧，共 171 个值；全部查询确认 DSE Step/Output/Start 合成计数为零。范围跟随当前输入和组合重新认证，不把这个数硬编码进产品。统计不包含真正的音频合成时间。

复验正式后端时设置 `VOCALOID_ONSET_PRODUCTION=1` 后运行相同 harness。`voicebank/tools/verify_onset_progress.py` 使用原始 PCM、统一时间轴和无第三方依赖的包络核对；`VOCALOID_TRANSITION_ONSET=1` 让独立宿主回归同时覆盖源进度与原有控制的组合。工程 `Onsets` 独立保存相对秒数和两侧语义身份，使用现有共享撤销事务；旧补丁会将新增字段作为未知数据保留并拒绝擅自执行。
