# 多音素 timing 的静音桥接边界

2026-10-20，VOCALOID MCP 只读检查当前 6.13.3.1 编辑器。声库 `BETDB8W6KWZPYEB9`、速度 146 BPM、五个相接音符，包含 `s dei ao`（`s t ei AU`）与 `tiu wu`（`t_h i@U u`）。用户报告各条 timing 均无法拖动。没有修改、保存、关闭或重新启动用户工程，也没有部署。

## 故障与修正

宿主记录 `begin: NotSupportedException`，请求 `t_h/i@U` 边界时仅观察到 `t_h/Sil`。独立重建同一组音符后，默认布局的 `s/t`、`t_h/i@U` 和 `k/o` 均被拒绝，另外两个音符通过。开始手势会验证目标音符的全部边界，因此其中一个接点失败就让整音符无法编辑。

DSE 在缺少直接过渡时可使用严格接续的 `左音素→Sil` 和 `Sil→右音素` 两条素材。原生 VSM 把前一条的内部 split 分配给逻辑音素边界，而不是把素材交界或后一条的 split 作为边界。原验证只识别直接 split 和素材交界，漏掉了这条路径。

增加 `TimingBoundaryEvidence.MatchesSilenceBridge`。它同时要求：请求帧精确等于前段 split；前段 `From=左音素, To=Sil`；后段 `From=Sil, To=右音素`；两段首尾精确接续；两侧有效区间非空。校验器仅多读取前段 End 对应的一行，不扫描整条调度表。没有音素白名单、时间容差或绕过原生映射失败。

完整五音符规划中的证据为：

| 逻辑边界 | 前段 Begin / Split / End | 后段 Begin / Split / End |
| --- | --- | --- |
| s / t | 3290 / **3292** / 3293 | 3293 / 3294 / 3295 |
| t_h / i@U | 3450 / **3452** / 3454 | 3454 / 3456 / 3485 |
| k / o | 3556 / **3558** / 3560 | 3560 / 3562 / 3581 |

宿主错误里的 3326 是较短上下文窗口的坐标，不与上表完整上下文混用。

## 验证与剩余问题

同一最低 SDK 编译的 harness 分别运行真实 6.13.1.1 / 6.13.3.1 组件，每版结果一致：

- 五个默认布局全部可查，与宿主当前边界逐项相等。
- 对 20 条边界各请求 ±1 原生帧，共 40 候选。38 次实际渲染非静音且 PCM 改变，全部目标采样边界均出现在实际已消费的调度中，路由 Failures=0。
- 38 次中 34 次原始 VSM 位置直接相符；4 次属于既有的首元音延后后 VSM 返回空位置的情况，仅采样调度严格相符，需要现有的已验证边界投影。没有把空列表记作原始位置一致。
- 所有候选查询的 DSE Start/Step/Samples 均为零；最终恢复默认的 PCM 与温态基准逐字节一致。
- **剩余两次请求未通过，完整矩阵返回退出码 1**：第二音符 `s/t` 接点 +1 帧，以及 `t/ei` 接点 -1 帧，均报 `Native phoneme mapping failed`，Reason=1，发生在后续 NOTE 回退重规划时。尚未证明它们是合法最短范围，不能称作正常下限或成功编辑。本次没有修改原生游标恢复算法。
- 既有 `uo/t` 共享边界、双侧编辑、重置、撤销/重做、保存重载与浮点系数组合回归通过；`f 7` 现场基线和六次真实渲染回归通过。
- 261 项托管测试通过，含静音桥接正例以及错误标签、错误 split、间隙、重叠和无效区间拒绝；最低 SDK 的 Debug 全解决方案构建零警告、零错误。

入口：`EvecRenderHarness --compound-boundary-probe --patcher-dse-initialization OUTPUT`。原生库通过 `VOCALOID_TIMING_PROBE_NATIVE` 指定。该探针固定重建现场，不读取或改写用户工程。相邻候选覆盖同一输出 WAV，不为每次渲染累积音频。

证据摘要：[compound-phoneme-silence-bridge.json](evidence/compound-phoneme-silence-bridge.json)。当前编辑器仍运行旧补丁；本轮未完成新版本宿主鼠标验收。
