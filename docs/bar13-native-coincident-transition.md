# 第十三小节删除左侧音符后渲染暂停

2026-10-21。用户反馈第十三小节左侧必须留有音符，否则渲染不完成。本轮通过 MCP、宿主日志和现场数值重建定位。现场工程有未保存修改，因此独立探针使用 MCP 捕获的 8 个音符、VEL、音素边界控制、Part 起点和时长、声库及速度，未把旧磁盘工程当作当前现场。

## 证据与原因

当前目标位于第二轨首个 Part，第十三小节首音为 `tu [t_h u]`，相对位置 4680 tick、长度 240 tick、音高 65、VEL 116，并保留起点偏移 0.052244898 秒（9 个输出帧）。MCP 显示渲染服务关闭、渲染未完成、timing host 暂停，原因是 `Transition anchors cross, collapse or lack fixed guards.`。日志堆栈落在 `TransitionLayout.ValidateAnchors → QueryTransitions → Publish`。旧的有效波形不代表这次渲染完成。

使用现场数值独立重放，首音前没有音符时重现同一异常；在左侧紧接一个 `a` 音符则通过。具体是原生 `Sil→t_h` 的 Split/End 原为 3852/3853，起点后移后成为 3861/3861：原生分配器合法地裁掉了该入场过渡的右半侧。音素本身的起点与后续边界仍严格有序。补丁却把所有观察到的 ART 端点都要求为严格递增，误将原生零帧半侧判作用户造成的非法塌缩，进而暂停整代次控制。

左侧音符隔着空隙时仍可能走 `Sil→t_h`，因此“任意放一个左侧音符”不是普遍有效的修复；紧接音符改变了实际入场采样路径。

## 修改

区分原生观察几何和下发的时间映射。布局允许已经由原生分配器产生的端点同帧，原有音素 warp 继续严格递增。其他过渡端点修改需要重编译 warp 时，仅将保持原坐标的既有同帧端点隐式表示；保留保护点，并逐点验证整数插值仍精确复现所有目标坐标，无法精确表示则拒绝。新编辑造成的塌缩、交叉或移动真实音素边界仍然拒绝。

可达范围始终包含已经认证的原生当前端点。没有删除既有 timing、过渡、音高或 VEL，也未修改原生 ABI。

## 验证

`--leading-note-timing-probe` 重建现场数值。修复后有／无紧接左侧音符均可规划、认证及下发。分别真实渲染预热、基准、进度、增益、另一处端点修改、恢复，共 12 次；全部已消费 ART 来源与计划一致，原生 timing/gain Failures 为零，音符位置、长度、音高、VEL 和音素文本不变。端点修改确实改变 PCM，恢复与相应预热后基准逐字节一致。

同一个独立 Part 再执行删除、添加、删除、添加左侧音符四轮，每轮预热和正式输出，共 8 次；全部完成，路由有效且无原生失败。每轮正式 PCM 与对应“无左侧／有左侧”的基准逐字节一致。所有规划查询 Starts/Steps/Samples 为零。
