2026-10-17。使用升级前的物理文件备份和升级后的实际安装，在独立 SDK 进程验证。没有部署、启动或关闭 VOCALOID Editor，没有导入或更改 Ghidra 项目。

结论：**同一份托管/原生补丁产物已在这两套真实组件上通过采样 timing、独立选样时长、逐音素音量及其工程/历史/缓存链路验收**。这不是对全部补丁功能或实际编辑器 UI 交互的认证，也不自动扩展到其他版本、重新签名或混搭的组件。

完整机器可读结果见 [证据](evidence/2026-10-17-second-real-version.json)。全部专有 DLL、VPR、WAV 和运行产物均在仓库外。

## 二进制变化与入口定位

升级后的 `VOCALOID6.dll`、DSE、VSM 为 6.13.3.1；旧版为 6.13.1.1。VDM 的版本号仍是 6.13.0.1，但文件哈希变化。身份判断使用完整组件哈希组合。

- DSE 的 `.text`、`.data`、`.pdata`、`.reloc` 完全相同，差异在调试信息和版本资源。
- VDM 的代码、数据和重定位相同，差异在调试元数据；目录发现 scope 增加新完整哈希，保留原来的精确指令检查和退出恢复。
- DSE_DFT 的所有映射节相同，但完整文件哈希变化。
- VSM 发生实际代码变化，不能仅增加哈希白名单。先按 PE 异常表限定函数边界，定位唯一入口候选，再检查反汇编和运行行为。

| VSM 入口 | 6.13.1.1 RVA | 6.13.3.1 RVA |
| --- | --- | --- |
| NOTE 编码 | `0x575d0` | `0x57530` |
| singer 编码 | `0x56e90` | `0x56df0` |
| score 映射 | `0xe1440` | `0xe1850` |
| render prepare | `0x60640` | `0x60570` |
| 缓存 hash | `0x91ee0` | `0x91e00` |

NOTE 编码、score 映射、缓存 hash 的完整函数在去除跳转/调用及 RIP 相对地址后，指令形状和字段访问一致，分别为 1935、892、235 条指令。这只是定位依据，不能证明所有外部调用语义不变。

prepare 从 5517 字节变为 5784 字节，栈帧和寄存器分配也发生变化。实际检查了 live Part、snapshot Part 和 Part mapping flag 访问及 detour 的完整指令前缀，并由真实多 Part 缓存测试验证，不把它描述成“仅移动地址”。

Ghidra MCP 本轮只查询到旧 DSE 的已加载元数据；没有把旧项目当作新 VSM 的分析结果。静态定位使用只读 PE 和反汇编对照，最终依据是独立进程中的行为验收。

## 兼容层改动

新增 `compatibility/sampled-timing-6.13.3.profile`，保留旧档案。C# 按确切 DSE/VSM 哈希组合识别档案，不接受交叉混搭。

Rust 从同一组档案生成注册表。profile ABI 升为 **2**：先查询桥接是否包含所需档案，再选择档案，回读指纹；选定后不能在进程中切换。VSM prepare/hash 安装地址使用已选档案，保留指令前缀检查。当前两版共用的 DSE/结构常量在构建时逐项核对；以后新增不同布局必须增加适配器，不能默用第一版字段。

数据层保持独立。除原有模拟测试，本轮还实际验证了：

1. 加入新档案之前，旧兼容层遇到真实 6.13.3.1：拒绝控制执行，但五组 timing/duration/volume/组合/未绑定数据可加载、复制、保存、重开及撤销。
2. 加入双档案之后，在仓库外建立“旧 DSE + 新 VSM”的真实混搭负例：仍拒绝执行，五组数据保留测试通过；没有改动安装目录。

两项均没有替换身份校验函数，证据中的 `componentIdentityInjected` 为 false。

## 托管引用也是兼容边界

直接用新 SDK 编译会产生对 `VOCALOID6, Version=6.13.3.1` 的引用，不能据此宣称同一产物能加载旧版。该问题已在实际旧版进程复现。

主项目和 SDK harness 新增 `VocaloidReferenceDirectory` 构建参数，默认仍使用本机安装目录。认证产物以合法备份的 **6.13.1.1 SDK 作为编译基线**，分别在 6.13.1.1 和 6.13.3.1 SDK 中运行同一份补丁及 native DLL。每次运行均记录真正加载的 SDK 版本和 SHA-256。

Release 合并产物的元数据已离线核对：引用 VOCALOID6 6.13.1.1，包含两份档案资源，不再引用独立 0Harmony。发行脚本也可传同名 `-VocaloidReferenceDirectory` 参数。专有参考文件由本机提供，不能放进仓库。

验证构建示例（`$baselineEditor` 是仓库外的合法旧版组件目录）：

```powershell
dotnet build VOCALOIDPatcher.sln -c Release --artifacts-path $validationOutput "-p:VocaloidReferenceDirectory=$baselineEditor"
```

`scripts/build-release.ps1 -Build` 使用通常的 Release 输出，可能更新安装目录所链接的文件；本轮没有执行它。未授权部署时应继续使用独立 artifacts 目录。
