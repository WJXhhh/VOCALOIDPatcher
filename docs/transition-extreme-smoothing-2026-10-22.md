# 极端过渡与自动音量平滑：2026-10-22 离线复查

本轮已修复能够稳定复现的自动平滑漏检和错误增益阶跃。用户报告的“过渡拉狠后方波”仍未在独立声库工程中得到稳定复现，不能把未观察到 PCM16 满幅削顶等同于没有内部失真或听感问题。没有启动、关闭或部署 Editor，没有改动用户工程或配置。

## 可复现的问题与修复

1. **接点没有进入处理链。** 宿主按名义增益差先筛 Begin/End；纯时间、素材进度编辑和 Split 接点可能不被检查。现在 `TransitionJunctionPlanner` 收集 Begin/Split/End，合并共享边界并保留真实相邻增益；后台回退规划包含当前 Part 的时间/进度编辑，仍跳过未编辑 Part。
2. **等响度断点被阈值旁路。** 两侧 RMS 相同也可能有相位不连续。音量阈值现在只控制响度桥，异常样本检查独立执行，并覆盖接点左右一个 DSE hop，处理相邻帧位置附近的尖峰。
3. **短尖峰掩盖自身。** 原检测把尖峰的回落沿算进邻近最大导数，1～3 样本脉冲因此无法通过异常判断。现在检测参考排除该小范围，修补仍从不可变局部快照读取。
4. **名义增益制造新阶跃。** 原实现直接对名义增益差做左右相反的增益补偿，即使 OLA 后的 PCM 已经连续，也会制造新接缝。现在要求窗内 RMS 差和同一半采样接缝两侧的实际增益差一致；过零附近才使用斜率辅助判断。连续起音和谐波曲线逐样本透传。
5. **余量不足同时关闭了衰减。** 原实现缩小整条增益桥，安静侧的单个高峰会连带取消响亮侧的衰减。现在将不可用的提升预算转移到响亮侧衰减，保持最大局部调整限制。
6. **密集接点重复处理。** WAV 处理器合并重复接点，以相邻接点中点划分独立处理范围，避免极短过渡的窗口反复叠乘。结果也纳入只出现在第二声道的修补。

参数键、归档和过渡进度映射保持兼容。没有给素材进度静默增加新的限速或裁剪，因为尚未证实这能修复用户报告的方波且保留旧工程意图。原生源码与 ABI 本轮未改动。

首先补充 13 个合成回归；修复前 11 个失败，覆盖等响度相位跳变、短尖峰、名义与实际增益不一致。随后增加渐变起音、64 组谐波相位组合、峰值余量、立体声、重复接点和宿主边界收集验证。现有旧测试中“物理连续也必须按名义设置强行处理”的断言已改成实际 PCM 行为契约；偏移测试使用位于偏移位置的真实断点。

最终托管测试 **460/460** 通过，ACE 参数离线程序和 BVL 离线程序通过。完整解决方案 Debug/Release 在独立 artifacts 目录构建，均零警告、零错误。

真实引擎主矩阵在本机 **6.13.3.1** 上完成 **1,099 次渲染**、**193 次明确拒绝的不可表示候选**。覆盖 V5 中文、V6 中文、MIKU；长短音符、MIDI 36/60/84、高 Velocity 127、鼻音/擦音/塞音；进度 ±1、原始/完整来源、端点极值与 -60/-24/+12 dB 的组合。

## 复跑

```powershell
dotnet build voicebank/tools/evec_render_harness/EvecRenderHarness.csproj -c Debug --artifacts-path <独立构建目录>
$env:VOCALOID_TIMING_PROBE_NATIVE = '<已验证的原生桥 DLL>'
dotnet <harness.dll> --transition-artifact-probe --extreme-combinations --patcher-dse-initialization <研究输出目录>
dotnet <harness.dll> --transition-artifact-reprocess <研究输出目录>
python -B voicebank/tools/analyze_transition_repair.py <研究输出目录> <证据.json>
```

`--extreme-pairs` 单独运行两端同时压缩/扩张的附加矩阵。分析脚本需要 NumPy；WAV 不写入仓库。`--extreme-combinations` 包含这类附加候选，本节 1,099 次主矩阵在加入该附加组之前生成，附加组证据单独保存。
