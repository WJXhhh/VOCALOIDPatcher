# 过渡精调面板的样式和打开手势修正

现场通过 VOCALOID MCP 确认第一 Part 的 `t_h → iE_n` 为选中目标，再以 computer-use 查看旧版精调面板。旧面板实际为系统白底，标签继承钢琴窗的浅色 Foreground，导致标题、标签、复选框说明和状态几乎不可见；普通输入框和按钮同时使用系统样式，与深色工具条不一致。

双击入口在 PreviewMouseLeftButtonDown 内直接打开 StaysOpen=false 的 Popup。Popup 随即获取鼠标捕获，而匹配的松手位于面板外，可能被解释为外部点击。这能解释需要按住鼠标移进面板再松手的现象。

修改：

- 提取独立 `TransitionEditorPanel` 视图，使用工具条同一套深灰、浅色文字和蓝色强调。显式设置标签、输入框、下拉框、复选框和按钮的配色与模板。
- 两列显示进度/音量、前侧/后侧时长；保留单位、完整素材开关、重置菱形、重置过渡、静音和应用。长操作说明放入对应控件提示。
- 顶部显示“过渡精调”和可切换的目标过渡；底部保留校验与错误状态。常态尺寸约 332×292，短视口仍可滚动。
- 按下时仅保存待打开位置并临时捕获鼠标；匹配松手后释放捕获，排队打开 Popup。Escape、失去捕获或上下文变更会取消待打开请求；异步打开前检查上下文代次。
- 精调面板内的鼠标和键盘输入不交给下方钢琴窗的 timing 拖动逻辑。仍通过外部点击、Escape、关闭按钮及上下文失效关闭。
- TextBox 模板避免重复应用 Padding，防止数字上下裁切。

验证：

- 完整解决方案 Debug（6.13.3.1 SDK）、Release（6.13.1.1 SDK）构建通过，均使用独立 artifacts，0 警告/错误。
- 484 项托管测试通过；四种语言 XML 可解析、无重复键、键集合一致。
- 在仓库外建立独立 WPF 预览，直接链接生产 `TransitionEditorPanel` 与 `AcousticControlStyle`，注入白底按钮和白字 TextBlock 的隐式样式以模拟宿主冲突。渲染结果中所有标签和数值可见，尺寸为 332×291.33。
- computer-use 实际操作独立预览：双击松手、鼠标留在触发按钮、数值输入 0.5、完整素材勾选、下拉框键盘切换并确认、Escape 关闭均通过。预览复现松手后打开的事件流程，但不等同于完整 Editor 内的集成验收。
- 当前工程 MCP revision 在检查前后均为 19，仍有原来的未保存修改。没有提交参数、保存工程、关闭或启动 Editor。
