# 采样声库：时长与选材关系

2026-10-17。范围是传统 DSE 采样声库，不含 VOCALOID:AI。本轮只增加独立研究探针和证据，没有修改或部署编辑器功能。

## 已确认的结论

用户后续目标已明确为分别改变起音、尾音的发音过程。新的[内部时长对照](articulation-edge-duration-research.md)在不换 ART 素材、固定音符及音素首尾的条件下实现了两端独立分配。下文的候选录音时长评分与这一目标不同。

**时长能够参与选材，但改变长度不等于一定换一条录音。** 当前证据需要区分三种情况：

1. 起音、过渡素材不变，只改变其分配长度及内部读帧方式。
2. 总时长足够时加入持续元音素材，再继续延长时重复利用该素材。这是实际素材组合改变，不能统称为同一过渡的拉伸。
3. 同一工作项保留了多个可用候选时，时长预算可以令选择器退选另一条素材。这个机制已用原生调用验证；是否有这样的候选，由具体声库和音素上下文决定。

本轮 MIKU、RIN、乐正绫的 126 次真实渲染观察到了第 1、2 类，**没有观察到仅因长度变化就将同一过渡换成另一条 ART 录音**。因此不能承诺任意音素都具有可切换的“短音录音 / 长音录音”。

## 当前二进制与原生链路

Ghidra 当前目标元数据和实际反编译查询均已核对：DSE.dll，x64，映像基址 `0x180000000`，SHA256：

```text
7A4965BD377DBC2B08710E807AE1345B67D9FFF6579CA0C01A769F744366F5B5
```

通过当前二进制的唯一入口签名，重新定位到直接树路径的准备函数 RVA `0x1B54D0` 和选择器 RVA `0x1B8F40`。早期音高层报告中的 `0x1B3FB0 / 0x1B7AA0` 属于旧版本，不能直接套用。本轮地址与[运行时图研究](../voicebank_doc/101_v4x_runtime_graph_completion.md)一致。

选择器先按素材音高、dynamics 收窄候选，再对保留候选进行时长相关排序。预算不足时，在仍可退选的工作项中找到当前素材总帧数最大的项，将它换为排序中的前一个候选，重新计算总长度。满足预算或再无可退选项即返回。它不会为了满足长度而自动放宽音高、力度条件，也不会保证返回长度一定小于预算。

排序也不等于单纯比较整段录音长短：比较器使用前两组 inner 长度，部分条件还依赖素材记录的 tempo；四组布局不能把后两组直接加入这一比较量。首尾裁剪也会影响预算消费。当前 `prepare` 的调用现场在选材后继续使用真实的可用帧预算分配左右长度，因此选材预算与实际输出长度在调用链上存在可研究的分离点。

同哈希 DLL 的两项已有原生实验已重新执行：

- `verify_region_budget_search.py`：735 组，零差异；覆盖 1–3 工作项、多个近音高/力度候选和预算退选。
- `verify_region_duration_order.py`：72 组，零差异；覆盖 inner 长度、素材 tempo、双组及四组布局。

上述结果证明直接树选择器的条件性换样机制。索引/联合评分路径另有 `0x1ACDA0 → 0x19E730` 调用链，不能把直接树的规则当作全引擎唯一算法。

## 真实声库对照

新增[独立探针](../voicebank/tools/evec_render_harness/DurationSelectionProbe.cs)，固定 MIDI 音高 60、VEL 64、音素与上下文，扫描以下组合：

| 声库 | 音素或上下文 | 结果 |
|---|---|---|
| MIKU V4X Original EVEC | `k a`、`n a`、`a`、`k a i` | 各组 ART 身份不变；长音加入 STA |
| MIKU V4X Original EVEC | 前一音符 `a` 紧接目标 `k a` | ART 身份不变；持续素材组合随目标时长改变 |
| RIN V4X Power EVEC | `k a` | ART 身份不变；长音加入 STA |
| 乐正绫幽 | `ts\_h i iE_r @N`、`l a` | ART 身份不变；长音加入 STA |
| MIKU V4X Original EVEC | 240 BPM 的 `k a` | 与 120 BPM 的等实际时长样例选材一致 |

每组扫描 24、48、72、96、120、180、240、360、480、960、1440、1920 tick，再回到 480 和 24 tick。120 BPM 下覆盖 25–2000 ms；240 BPM 下覆盖 12.5–1000 ms。共 126 次非静音音频渲染，其中 18 次为返回先前长度的身份稳定性检查，全部通过。

例如 MIKU `k a` 在本次稀疏扫描的 240 tick / 250 ms 时仍只有过渡素材，360 tick / 375 ms 时已加入持续元音素材；这只将切换区间限定在两次观测之间，不是精确阈值。`k a i` 和中文多音素的持续素材在更长的受测时长才出现。不能使用统一的“超过 N 毫秒必换样”规则。

120 / 240 BPM 共找到 7 对等实际时长样例，素材元数据及阶段序列全部一致。这些样例支持按实际时间/引擎帧研究长度，而非直接用 tick 作为选样参数；尚未覆盖音符内部变速。

比较的是实际合成消费过的素材身份、音素对、stage、方向及工作单元。连续重复使用同一 STA 会折叠为一个素材来源段。不能使用 WAV 散列变化证明换样，也不能把前瞻队列中尚未消费、可能被下一 NOTE 替换的临时 release 当作最终选材。

素材身份编号只在单个夹具的同一进程内有效，底层是保持加载的素材对象；证据不保存地址，不以编号跨进程比较。每个来源同时记录帧数、录音音高、dynamics、tempo 与 alignment 元数据。跨 tempo 夹具按元数据及阶段对照。

## 规划性能及准确性边界

对每次真实渲染捕获的相同原生输入，在已初始化的独立引擎中重放规划：

- 126 次素材来源段序列均与实际合成一致。
- 126 次规划合计 `Start=0 / Step=0 / Samples=0`，未请求音频合成。
- 耗时中位数 0.8006 ms，P95 1.3585 ms，最大 1.7682 ms。

计时包含原生规划和有界元数据扫描，**不包含输入准备、冷启动、宿主排队及重渲染**。不能直接当作编辑器拖动端到端延迟。

完整内部调度不能宣布逐帧一致：18 例持续素材的内部重复切段与实际合成不同，其中 2 例连重复段数量也不同；所有 ART 段的起止、身份与阶段均一致。此处验证的是选用了哪些来源，未验证所有 STA 内部循环切点。未来控制若依赖这些内部切点，必须继续查清其状态依赖，或使用与真实渲染复用的同一原生规划结果。

汇总证据：[duration-sample-selection.json](evidence/duration-sample-selection.json)。原始逐段记录及 WAV 留在本机独立探针输出目录，不作为源码提交。

## 后续实现方向

更合适的数据语义是独立的“选样时长”，而非通过暂时移动音符边界来碰运气：

1. 真实长度决定节奏和最终 timing；选样时长只用于查询、评分或选择有资格的素材。
2. 选择完成后仍按真实时长重新规划，再核对实际音频消费的素材和边界。
3. 模型预留音符、音素、过渡工作项三个寻址层次。多音素 stage 有联合资格与连续性约束，不能把每个 stage 当作任意独立录音切换。
4. 候选目录应明确显示有无长短变体；只有一条候选时，不把持续素材重复或普通拉伸冒充“换了录音”。

优先实验直接树入口的独立预算，并单独审计索引评分路径。不要改写共享声库素材的原始时长字段。当前尚未验证独立预算控制的音频、音符长度保持、缓存失效及宿主并发，因此本轮没有接 UI 或部署。

本轮构建：独立探针、完整 Debug 解决方案均通过，零警告、零错误。

后续独立预算/评分与真实音频实验见[独立选样时长原型](independent-duration-selection-prototype.md)：已经出现条件性换样正例，同时保留多音素 timing 和恢复失败的边界。
