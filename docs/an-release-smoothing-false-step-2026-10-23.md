## 复现

原生缓存按文件长度筛出 7 个候选，以 20 个音符的时间和音高序列核对；匹配项平均预期音高相关度 0.9817，235993 个样本与音素音量输出直接相等。缓存副本保留在仓库外。进一步将实际音素音量缓存送入修改前的生产平滑器，在收尾区域与宿主平滑输出逐样本一致，确认来源是后级处理。

异常在原生 frame 4265，即 Part WAV sample 301568 / 6.838277 秒，换算歌曲时间约 **41.886222 秒**。这是 `a_n → Sil` 收尾过渡的开始，原本过渡控制增益 0 dB。此处并非前一轮 `xiang` 的两个音素独立淡回原音量问题。

## 修正和验证

`TransitionSmoother.TryGetGainStep` 新增两侧各 10 ms 的邻域 RMS 确认，要求其增益比与四样本推断相差不超过 1.5 dB；窗口按可用样本缩短。安静到无法可靠估计的区域不做增益补偿。孤立样本断点检测和修复保持原路径。

3 项量化谐波自然衰减回归在修改前均失败，修改后精确透传；另外覆盖 120/392/1000 Hz、每种 3 个相位的真实音量台阶，确认局部响度差缩小且范围外精确不变。完整托管测试 **482/482** 通过，使用合法最低参考 SDK 6.13.1.1 在独立 artifacts 目录构建整个 Release 解决方案，零警告、零错误。
