# 工程控制数据与原生后端分离

后续：同日已完成第二套真实组件的限定范围验收，profile ABI 更新为 2，见 [6.13.1.1 / 6.13.3.1 对照](second-real-version-compatibility.md)。本文及其证据保留为第一阶段记录。

日期：2026-10-17。此轮未部署，也没有启动或关闭 VOCALOID Editor。构建全部使用临时 `--artifacts-path`，避免安装目录中的主 DLL 符号链接被构建间接更新。

## 工程生命周期

`SampledTimingHost.Get/Load/Copy` 现在仅建立工程会话。`SampledTimingSession` 使用 `TimingBackendLease` 按需取得局部规划器；加载、快照、归档、保存、共享撤销、原生音符身份重绑定、缓存失效和关闭不再要求私有 DSE 引擎构建成功。失效只清理已存在的实例，关闭会正确释放已经注入或按需创建的自有实例。构建失败保留独立错误状态，不破坏文档，也不把异常永久缓存成一个无法重试的实例。

timing、独立选样时长和逐音素音量继续使用原有工程条目和参数语义，没有把引擎预测结果写入工程。timing 模型原先允许的未知调整轴仍可保留和回写，执行时仍须经过能力校验。真正损坏的 JSON、重复 locator、非法数值或未知归档 schema 版本继续报错。

对于有效归档中暂时无法绑定到当前音符身份的记录：

- timing 文档保留原记录，保存时保留尚未绑定过的记录。
- duration/volume 将其作为未绑定数据保留，不按当前音符索引猜测对象；保存和工程复制时仍带上这些值。
- 不允许普通参数编辑静默覆盖相同 locator 上未解决的 duration/volume 数据。
- 已经绑定过、随后被用户删除的 timing 音符仍按原有规则留在内存供撤销使用，不把其控制误保存到新占据该索引的音符。

输入观察器初始化失败也仅影响执行能力，不再导致已加载的控制文档被销毁。公开的 VSM 工程 API 仍是宿主适配的基础；这不承诺原生编辑器自身无法读取的工程也能被补丁强行打开。

## 执行与数据状态分开

带控制的渲染若无法建立经过验证的规划、映射、路由或缓存身份，会记录失败并拒绝该次控制渲染，数据仍可保存。不再把跳过 timing 的普通渲染作为控制已成功执行。没有这些控制的工程继续走原生渲染。

诊断分别暴露文档能力、规划器实例、音素映射、渲染路由和独立选样安装状态。组件已识别只表示匹配兼容档案，不等同于全部能力已经安装或行为已经认证。

## 兼容档案与桥接握手

权威档案为 `compatibility/sampled-timing-6.13.1.profile`，只认证当前 DSE/VSM 的完整 SHA-256 组合，不能用编辑器显示版本替代。包含规划器/编码器/映射器/缓存入口、全局量、主要结构偏移、NOTE 步长、score 布局、虚表槽和必要调用点。

- C# 将档案作为资源嵌入，在第一次执行前识别组件；业务归档和历史层不读取它。
- Rust 的 `build.rs` 从同一文件生成常量，相关模块不再各自维护这些数值。
- 档案使用 LF，C# 与 Rust 对原始档案字节计算同一 FNV-1a 64 位一致性指纹。指纹用于识别配套构建，不替代 Yamaha 模块的 SHA-256 校验。
- 新增独立的 profile ABI v1：校对 ABI、指纹和实际模块句柄，然后选择档案。Rust 的 timing/phoneme/duration 私有安装入口在未选择档案时直接拒绝，早于入口读写和 hook 安装。
- 旧桥接 DLL 没有该握手时，受控执行拒绝；后续部署必须提供配套的托管和原生输出。
- 未知组件的拒绝结果按已加载模块句柄缓存，避免鼠标交互反复哈希大 DLL。模块尚未加载和暂时的文件读取失败仍可重试。

档案描述的是当前 v1 私有适配器。函数原型、短指令校验和 trampoline 重定位仍是适配器的一部分；不能只改 hash/RVA 就宣称支持另一版本，也没有新增“部分 hook 安装失败可全部回滚”的承诺。旧有其他功能的全部私有依赖不属于本次 timing/选样链路的收拢范围。

无后端验证使用单独的 SDK 进程、真实文件/历史补丁和当前托管 SDK，只对缺模块/组件身份进行注入；不是在第二套真实 Yamaha DLL 上运行。第二套构建仍未认证。

最终测试期间发现旧 Rust 注册表测试会因并行写入争用生产路径的 `try_read`，偶发返回空。仅给依赖该全局注册表的测试 fixture 增加了互斥隔离，保留生产回调的非阻塞读取策略；修正后默认并行及 20 轮并行压力运行全部通过。

重现入口为 SDK harness 的 `--compatibility-host-probe`、`--timing-profile-probe`、原有 `--duration-host-probe` 和 `--shared-boundary-probe`。宿主文件验证须以独立 Debug 构建 `-p:PatcherIsolatedValidation=true --artifacts-path <临时目录>` 进行，不能加载普通生产主程序集来替代隔离构建。
