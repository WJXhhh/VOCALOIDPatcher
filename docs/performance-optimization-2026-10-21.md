# 渲染后处理与界面刷新性能优化

本轮针对渲染等待、滚动缩放和参数编辑中的额外开销。已于 2026-10-21 经用户授权部署到 Editor，尚未完成宿主内性能验收；下面的耗时是离线后处理基准，不是 VOCALOID 整体渲染提速比例。部署文件与校验结果见 `evidence/performance-optimization-deployment.json`。

后续十分钟宿主采样、跨 Part 失效和临时时值工程复用另见 [采样报告](performance-sampling-2026-10-21.md)。那一轮新增改动也已随后经用户授权部署，等待宿主交互验收。

## 已修正的路径

- `RenderedWaveCachePatch`：用每 Part 的加载票据替代整个管理器共享的 generation。一个 Part 开始渲染不再丢弃其他 Part 正在加载的 PCM；旧任务不能覆盖同路径的新渲染结果，也不能清掉新任务的 pending 状态。
- 缓存加载的并发等待、文件重试改用异步等待；重试间隔释放加载名额，文件暂时占用不会独占名额阻挡其他 Part。维持最多两个并发文件加载。
- 后处理完成和缓存加载完成引起的波形重画合并到 Dispatcher 后台队列，同一轮通知只执行一次全局重画。渲染开始时仍同步使对应 Part 的旧 PCM 失效。
- 自动过渡平滑在没有非零音量编辑时跳过原生过渡查询。需要回退查询时，在 UI 线程捕获准备对象、在单个后台工作名额内查询，返回后核对 Part generation 和时值会话 revision。已有执行计划和导出等待语义保留。
- 参数区能量背景按包络、可视范围、缩放、tempo revision、显示范围和 DPI 缓存冻结绘图。相同数据的编辑通知不再重建几何；新建几何时相邻采样点复用时间换算结果。
- ACE 声学处理不再为纯气声/假声估计无用的 LF 闭合参数；复用窗函数和噪声缓冲，将有界临时数组改成栈空间，并跳过中性力度的逐样本指数运算。保持原有频谱模型、音高估计与处理顺序。

## 可重复基准

在独立输出目录构建后执行 `AceAcousticOfflineTests --benchmark`。输入是固定的 44.1 kHz、12 秒合成元音，每个模式预热后运行五次，报告中位数和当前线程托管分配量；包含输出数组和 STFT 累加数组，不包含宿主、磁盘读写、原生渲染或 UI。

本机一次前后对比：

| 模式 | 修改前 | 修改后 | 托管分配，修改前 → 修改后 |
| --- | ---: | ---: | ---: |
| 力度 | 7.80 ms | 8.14 ms | 2.12 → 2.12 MB |
| 气声 | 507.74 ms | 201.72 ms | 100.85 → 10.70 MB |
| 张力 | 437.49 ms | 435.18 ms | 58.37 → 10.67 MB |
| 假声 | 435.81 ms | 166.51 ms | 58.36 → 10.67 MB |
| 气声 + 张力 + 假声 | 512.00 ms | 501.47 ms | 100.85 → 10.70 MB |

张力和组合处理的 CPU 耗时仍主要受必要分析影响；本轮对它们的收益主要是降低临时分配，不能据此声称全部参数处理都快了约 60%。

## 第二轮：诊断采集、能量解码和密集音素音量

### 关闭诊断时仍在采集快照

`RuntimeObservationPatch` 的观察补丁始终注册，原先只有最终 `RuntimeObservationLog.Write` 判断 `observations.enabled`。即使标记不存在，渲染分块、完成和歌词入口仍创建字典、计算哈希，访问音符、PCM、score；原生完成入口还会通过 Part 句柄采集渲染后的快照。

现在 23 个观察入口在采集前检查开关，postfix 只在对应 prefix 建立观察状态后采集，异常观察也遵守开关。原生开始/完成 postfix 的 MCP 通知在观察判断之前，关闭观察仍发布 `render_started` / `render_idle`。BVL 诊断门面也先判断开关，再读取原生诊断、创建哈希或整理标记。

外部标记按 250 ms 间隔轮询，支持运行中创建/删除，最多约 250 ms 后在下一次调用生效；缓存的关闭路径不逐回调访问文件系统。没有改动用户的实际标记、配置或日志。

用 `PatcherIsolatedValidation=true` 构建的前后程序集，在独立 STA 测试进程反射调用实际观察入口（没有启动 Editor）：

| 检查 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 关闭观察时，23 个 prefix 中创建观察状态的数量 | 16 | 0 |
| 10,000 次空进度回调耗时 | 294.08 ms | 2.27 ms |
| 同一批回调的当前线程托管分配 | 8,001,056 bytes | 1,056 bytes |
| 关闭观察时，开始 + 完成的 MCP 事件数量 | 2 | 2 |

这里包含反射调用成本，使用空句柄，不能代表真实工程的原生快照耗时。实际工程中被跳过的扫描成本需宿主测量。

### 能量包络分块解码

保留当前的 1 ms hop、20 ms RMS、10 ms peak 和原有样本累计顺序，只将逐样本 `BinaryReader` 调用改为最多 64 KiB 的帧对齐分块解码。不额外保留整段 PCM；支持短读取，保持流的所有权、取消和 RIFF 长度检查。

固定 48 kHz、60 秒立体声音频，预热后五次中位数，前后解码器读取同一文件；四种格式的 RMS/peak 数组和时间信息逐点相同：

| 格式 | 修改前 | 修改后 | Stream 读取调用次数，前 → 后 |
| --- | ---: | ---: | ---: |
| PCM16 | 91.29 ms | 9.35 ms | 5,760,013 → 189 |
| PCM24 | 53.98 ms | 12.39 ms | 17,280,013 → 277 |
| PCM32 | 69.66 ms | 17.36 ms | 5,760,013 → 365 |
| Float32 | 72.33 ms | 12.40 ms | 5,760,013 → 365 |

读取次数包含 RIFF 头，是 Stream API 调用数，不是磁盘 I/O 次数。

### 音素音量区间扫描

`PhonemeGainWaveProcessor` 原来对每个采样点遍历同一处理窗口中的全部区间。连续编辑许多相邻音素会把处理成本放大为“采样数 × 区间数”。现在按起点依次加入区间，及时移除结束的区间，仅计算当前重叠的增益；保留等起点的原有乘法顺序。淡变内部之外直接使用精确的权重 1，减少无用的 `Cos(π)` 运算。

固定 48 kHz、60 秒 PCM16 立体声，相邻区间均为 -6 dB，预热后取三次中位数，包含文件复制、处理和写出；每组输出与旧处理器 SHA-256 相同：

| 相邻区间数量 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 1 | 38.81 ms | 27.82 ms |
| 60 | 119.20 ms | 31.10 ms |
| 240 | 350.18 ms | 27.55 ms |

### BVL 中性路径

没有非默认 BVL 增益、也没有需要撤销的 BVL 派生文件时，不再重新注册音源、使 PCM 失效和触发全钢琴窗刷新。实际移除已有派生文件（例如把音量重置为默认）仍执行刷新。渲染完成后的原始音源绑定由原生完成处理器执行；BVL 区域通知仍保留。

第二轮整个解决方案 Debug / Release 独立构建均为 0 警告、0 错误，Release 合并成功；345 项 McpTests、BVL 离线验证和 ACE 参数/过渡平滑离线验证通过。用户随后授权部署，已安装通过验证的合并 Release、同步四份翻译，七个载荷文件全部通过 SHA-256 校验；原生 DLL 与映射文件内容一致，无须替换。部署保留上一版程序集和被替换翻译的备份，未启动或关闭用户 Editor。
