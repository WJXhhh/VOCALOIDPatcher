# fe 音素 timing 无法开始拖动

2026-10-17，VOCALOID MCP 只读现场：中文声库 `BL8CEAM5N4XN3LFK`，单音符位置 960、长度 480 tick、音高 59、VEL 28，音素 `f 7`。显示与原生边界均为 `[-25,-13,477]`。没有修改或保存用户工程。

## 根因

本次不是共享边界冲突。覆盖层在开始拖动时验证整个音符，报告：

```text
Native sample mapping did not produce the requested phoneme boundary at 3257 (f/7);
observed 3253..3257:Sil/f@3255;3257..3291:Sil/7@3259.
```

`f` 与 `7` 没有共用一条 `f→7` 素材。DSE 使用两条独立起音素材：先 `Sil→f`，再 `Sil→7`，它们在 3257 帧处精确相接。音素边界是两条采样段的接点，不是第二条素材内部的 3259 帧分割点。

`TimingBoundaryEvidence.MatchesJoin` 已支持两条独立素材的接点，但只接受后一段的 `From` 等于目标右音素。这种 `From=Sil, To=7` 的起音素材不满足旧判断，于是未编辑的基线也被拒绝，任何滑杆都无法开始。

## 修复与约束

补齐独立起音素材的接点证据：左右采样段必须在请求帧精确相接，左侧音素标签必须吻合，右侧必须是 `Sil→目标音素`，其内部分割点在该段范围内且右音素占用非空区间。没有按 `f` 或 `7` 添加白名单，也没有扩大时间容差、忽略标签或跳过原生分配验证。

只修改托管证据模型和研究探针，不修改原生 DLL、ABI、工程格式、拖动范围或 VEL。短音素仍不得交叉或塌缩：本现场 `f` 只有约 12.5 ms、两个原生帧；向内移一帧有效，向内移两帧会塌缩，查询仍拒绝。

## 验证

`PhonemeTopologyProbe` 增加可选 VEL、音高、音长及步长参数，重放现场输入。修复前七个查询没有成功，其中未修改的基线也报同一接点错误。修复后：

- VEL 28、三条边界各 ±1 帧：基线与六个候选查询全部通过；六次真实渲染的采样段边界均符合查询、Failures=0，音频非静音且 PCM 改变。五次原生 VSM 边界直接吻合；首元音边界右移的一次 VSM 返回空列表，实际采样段仍严格吻合，使用既有的已验证边界投影，没有为本次增加回退。
- VEL 64、三条边界各 ±2 帧：四次有效编辑渲染通过；两次向内塌缩在查询阶段按原有约束拒绝。探针对此组返回失败码，验收通过读取结果逐项确认这两条均是预期的塌缩拒绝，未将其它异常当作成功。
- 所有局部查询的 DSE Start/Step/Samples 均为零。
- 之前 `uo/t` 共享接点的 12 次真实渲染、双侧编辑、重置、撤销重做、保存加载及浮点系数组合回归通过。
