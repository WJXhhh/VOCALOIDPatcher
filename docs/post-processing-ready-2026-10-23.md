# 已就绪音源不重新等待编辑稳定期

2026-10-23。继续普通 Part 后处理优化，22:35 已按用户要求部署，未启动、关闭 Editor 或修改用户工程。

## 请求分类

之前 WaveFilePath 检测到上游音源路径变化后，会把重新绑定当成一次新编辑：音素音量和过渡平滑再等待 100 ms，ACE 再等待 120 ms。Comp 成品发布给 ACE 也走相同入口。

现在每个 Part 独立记录最近一次输入变化的稳定期。普通编辑仍开启原来的 100/120 ms 窗口；已就绪音源只等待这个窗口的剩余部分，不重新计时。没有待稳定的编辑时，可以直接捕获并处理。ACE 的文件占用/不可读重试仍保留 120 ms 间隔和原有限次。

重新绑定在 Dispatcher 上核对 Part 状态引用、渲染状态和当前上游路径。排队后音源变成另一条路径、Part 已移除或正在原生重渲染时，不使用旧通知启动工作。原有 generation、取消、处理锁、音源读回版本检查和发布前检查保留。

## 上游尚未完成的保护

路径暂时回退到原声不代表所有上游已完成。BVL、音素音量和平滑增加当前工作状态记录；还有上游任务时，保留原来的等待长度，但不把它记作新的用户编辑。随后收到真正完成的新音源路径时，可以替换这次等待，直接处理。关闭的功能不阻塞下游。

BVL 的 `RebuildCompleted` 仍表示任务结束，不改成成功承诺，其原有通知路径继续使用普通去抖。新增的待完成标记由当前代次清除，旧任务的 finally 不得清掉新任务。Comp 输出跳过普通 BVL/音素音量/平滑链，仅当当前 Comp 结果非 Dirty 且有 WAV 时，才向 ACE 发已就绪请求。

这不是完整的依赖任务图：普通渲染完成、BVL 通用完成等入口仍按原方式调度；中间结果发布与 UI 刷新也尚未合并。
