# 独立选样时长：宿主接入与前端

2026-10-17。承接 [前端接入方案](duration-selection-frontend-integration.md)。后端、共享历史、保存和 Emotion 工具已接入源码；本轮没有部署，也没有启动或关闭 VOCALOID Editor。原生验证运行在独立 SDK 进程中，界面检查使用独立 WPF 进程，不能代替编辑器中的滚动、缩放与鼠标实测。

## 已接入的控制

后续用户实测认为该控制未产生所需的前后端变化。目标修正和独立原型见[起音与尾音内部时长研究](articulation-edge-duration-research.md)；本页记录已部署方案的实现，不再将它等同于两端发音过程控制。

设置中新增 **音符选样时长**，默认关闭。开启后，Emotion 左上方出现 **选样** 模式按钮。

- 模式内，音符底部横线是比例刻度，中心为 100%；左右拖动只预览 25–400% 的候选比例。实际音符长度、VEL 和音素边界不随这条刻度移动。
- 松手提交最后位置对应的比例，产生一条共享历史和一次普通渲染请求；MouseMove 不写文档、不合成音频。
- 单击音符或使用音符右键入口打开精确面板，可以输入百分比、换算毫秒数及候选策略。短音符也能从右键进入。
- 默认保留原生候选资格。**扩展来源（实验）** 单独启用，允许扩大录音音区候选，不能承诺每次修改都会换样。
- 双击、面板中的“恢复原生自动”同时恢复比例 100% 和原生策略。Escape、失去捕获、切换目标及外部输入修改取消候选；已保存的超刻度值不会因打开面板被夹到 400%。
- 当前单位是整个音符。多音素共用该比例，不显示尚未实现的逐音素选样把手。

界面仅显示请求参数与提交/失败状态。尚未提供生产级的选材摘要接口，因此不显示“已换样”“可选素材数”或“已核对素材”。导出入口会先检查 timing/选样渲染准备状态，未准备好时启动正常渲染并拒绝输出旧结果；真实混缩文件尚未做编辑器内验收。

## 后端与组合顺序

`DurationSelectionHost` 用音符原生对象的代次持有文档值，保存时转换成当前工程定位。原生端接收每 Part、每代次不可变快照，评分归属使用当前 NOTE 的工作区间；相邻音符可以使用不同系数。递归桥接参数、时间计划游标、音色头与层间历史均有独立生命周期。

组合顺序为：当前 VEL/浮点系数的原生时间计划 → 独立选样评分 → 恢复原生分配与最终映射入口的时间预算 → 已有音素 warp 一次 → 合成。只恢复上游半段分配仍会遗漏某些反向尾辅音的整数舍入；本轮将最终 mapper/stationary 的分配也纳入契约，修复中文组合中实际 ART 尾端多出 1 帧的问题。

原生评分采用“原生分数 + 虚拟/真实分配成本差 × 权重”，因此同一策略下 100% 为中性，不在量化阈值附近切换两套绝对分数公式。原生策略权重为 1；实验策略明确使用扩大音区资格及权重 128。策略、算法、数值及时间契约进入缓存身份，指针、游标和代次不进入内容指纹。

## 生命周期修复

| 场景 | 处理 |
|---|---|
| 原生与自定义撤销交错 | 共享时间线区分自定义命令和原生历史；原生 Undo/Redo 完成后按恢复的完整音符图重绑代次 |
| 移动、删除恢复 | 通过活音符代次授权定位更新，不按“最近音符”匹配；已删除参数不写到占据旧下标的新音符上 |
| 选样、timing、音量保存 | 同一次扩展保存成功后才确认保存态；注入写入失败时恢复旧 VPR、保留 dirty |
| 最后一项覆盖撤销 | 保留无选样偏好的原生执行作用域，单独持久化 `ScopeOnly`，保持音色/层间历史重置一致 |
| 私有序列关闭 | Close 前捕获指针；包装对象归零后仍能清除内部对象登记，防止新工程复用地址后被误认成内部序列 |
| 原生输入变动 | 原生更新通知定位受影响 Part；渲染产生的 `DidUpdatePhonemePosition` 是派生结果，不再作为用户输入修改 |
| 输入复用 | 计划缓存按 Part 的完整音符/表达/tempo/物理时间身份校验；单改比例复用契约，不相信“波形有效”标志来判断输入未变 |
| 未修改 Part | 不为其他 Part 提交无变化的 VEL 编辑；同一工程中另一受控 Part 保持 PCM，且没有进入原生 render scope |
| 内部副本 | 同身份副本复制参数，原生输入修改后重新规划；拆分受控音符、改拓扑的副本显式拒绝，尚未支持 EVEC 拆分后自动重映射选样参数 |

`NativeRenderSession.Gate` 仍只协调主动使用它的复制渲染器。选样路由没有以串行化全部音频渲染来实现隔离。

## 验证结果

机器可读摘要见 [evidence/duration-selection-host-integration-20261017.json](evidence/duration-selection-host-integration-20261017.json)。测试工程均为临时合成数据，没有读取或修改用户正在编辑的工程。

- 托管测试 176 项、Rust 测试 38 项通过。完整 Debug 解决方案、渲染 harness 及独立目录的合并 Release 构建通过；Release 的警告是 Rust 链接器输出导入库创建信息。
- Release 原生库：VEL 0、浮点系数、VEL 127、中文 `s\ i_n n` 共 20 组组合，实际边界、实际消费的过渡区间和重复恢复均一致。实验组中观察到实际素材变化及 PCM 变化。
- 四路并发（三个独立控制 Part 加一个普通渲染）三轮通过，受控原生 scope 峰值为 3；四路音频均与各自串行参考逐样本一致。
- 原生/自定义交错撤销重做、保存失败回滚、重开两次、缓存复用、移动撤销、复制/删除反复撤销、跨工程首次粘贴及其撤销重做、内部副本和副本 VEL 更新通过真实 SDK 验证。重新应用失败的相同数值只重试对应 Part，不新增历史；同一失败代次的完成通知不能清除错误。
- 同一工程三个受控 Part：修改其中一个 Part 的 VEL 后，另一个受控 Part 的 PCM 完全相同、`Scopes == 0`。此时无需再次查询缓存键，不能把 `CacheKeys == 0` 误当失败。
- 精确面板检查覆盖法语小数文化、百分比/毫秒换算、输入不立即提交、NaN 拒绝、保留超刻度值，以及恢复自动时清除实验策略。

单音符 `k a`、已准备输入的 200 次纯规划：P50 0.0988 ms、P95 0.1156 ms、最大 0.3721 ms，Start/Step/采样输出均为零。独立会话冷初始化约 173.8 ms，输入准备约 9.4 ms；这些不是拖动延迟。当前首次建立会话仍在 owner 线程，需要后续编辑器实测其首次进入的停顿；没有将冷启动数字藏进纯规划耗时。宿主连续验证同一输入 100 次约 1.6 ms，没有增加规划次数。

## 当前边界与待验收项

执行器固定验证过的 Windows x64 DSE/VSM 镜像与 ABI。当前要求单一采样声库、44100 Hz/256 帧，以及可完整准备的 Part：最多 33 音符、规划窗口约 22 秒；DVQM、重叠、双声库等仍由既有输入校验拒绝。比例模型范围为 0.001–32，虚拟音符预算超过 4096 原生帧会拒绝，不能默默截断。上限是实现边界，并非所有声库、所有组合已穷举验收。

尚未部署。安装目录主 DLL 与原生 DLL 的 SHA256 均保持本轮开始时的值。真实编辑器中的模式按钮、滚动/缩放、鼠标捕获、快速连续提交和混缩导出仍需部署后验收；本轮没有代替用户批准部署或启动编辑器。
