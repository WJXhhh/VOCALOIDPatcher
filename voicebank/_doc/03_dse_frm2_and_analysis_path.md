# DSE 中的 FRM2 与分析路径

## 结论摘要

当前已把传统 DDB 顶层块与 DSE 6.13.1.1 中的实际 C++ 对象对应起来：

- `FRM2` 是 `DSE5::CSMSFrame` 的块 ID；对象大小为 `0x328`。
- `SND ` 是单声道/多声道 16-bit PCM 容器；其负载前缀为采样率 `u32`、声道数 `u16`、PCM 值数量 `u32`。
- 两种块都使用同一顶层头：4 字节 magic + 4 字节块总长。块总长包含这 8 字节。
- `DSE5::CSMSFrame` 同时实现了字段掩码驱动的写入器和读取器；`FRM2` 不是加密黑盒。
- DSE 中确实还包含 `DRS::CSMSAnalysis` 和 `DRS::CSMSRegionAnalysis`，能从内存 PCM 构造 SMS frame/region；批处理驱动存在但未导出，不能据此断言它就是官方声库制作器。

## 块级序列化

### 通用 CChunk 头

`DSE5::CChunk` 构造函数 `0x1801067f0` 保存 4 字节块 ID。`0x1801071f0` 写出：

1. `object + 0x08`：magic，4 字节；
2. `object + 0x0c`：块总长，4 字节。

写入容器 `0x1801080a0` 在写完子树后回到块起点，把“当前文件位置 - 块起点”写回长度。因此本机 DDB 首块 `FRM2 60 2c 00 00` 的 `0x2c60` 是整个 FRM2 块长度，不只是负载长度。

### SND

`SND ` 对象构造函数为 `0x180047f50`，写入器为 `0x180048960`，读取器为 `0x180048820`。负载顺序已经由 DSE 自身确认：

| 块内偏移 | 类型 | 含义 |
| ---: | --- | --- |
| `0x00` | `char[4]` | `SND ` |
| `0x04` | `u32` | 块总长 |
| `0x08` | `u32` | 采样率；构造默认 `44100` |
| `0x0c` | `u16` | 声道数；构造默认 `1` |
| `0x0e` | `u32` | 后续 PCM 值数量 |
| `0x12` | `i16[count]` | PCM 数据 |

所以必须满足：

```text
chunk_size == 18 + sample_count * 2
```

公开工具曾把最后一个字段保守地称作未知值/索引；从 DSE 的循环写入与读取代码看，它可以确定为 PCM 值数量。声道数大于 1 时，它仍然是交错 PCM 值总数，而不是每声道帧数。

### FRM2

`DSE5::CSMSFrame` 构造函数为 `0x18012a670`，vtable 位于 `0x180238d30`：

- `vtable + 0x68` → `0x180138560`：写入负载；
- `vtable + 0x70` → `0x1801363a0`：读取负载。

负载固定前缀为：

| 块内偏移 | 类型 | 暂定含义 |
| ---: | --- | --- |
| `0x00` | `char[4]` | `FRM2` |
| `0x04` | `u32` | 块总长 |
| `0x08` | `u32` | frame kind/状态，精确语义待定 |
| `0x0c` | `f64` | frame 时间值；运行时 region 路径也把对应字段作为时间处理 |
| `0x14` | `u64` | 后续字段存在与压缩方式掩码 |

掩码控制的主要数据族包括：

- 位 `0..2`：同长度的 1–3 组浮点数组；压缩模式可将每项量化为 1 字节。
- 位 `4..5`：另一组谱数组及伴随数组，也支持 1 字节量化。
- 位 `6`：`u16` 数组。
- 位 `9..20`：若干标量和复合对象。
- 高位：多组浮点数组、共振/滤波对象及列表。

普通掩码的完整物理顺序、代表性数值和运行时证据已经整理在 `05_main_frm2_semantics.md`；本节保留通用读取器视角。

### 全量掩码分布与帧步长

7 个参考库的 2,670,252 个 FRM2 只有三种掩码：

| 掩码 | 位集合 | 帧数 | 已确认的类别 |
| --- | --- | ---: | --- |
| `0x0000002000e00207` | 0, 1, 2, 9, 21, 22, 23, 37 | 2,573,791 | 全部 STA；ART 的普通/有声部分 |
| `0x0000000000000200` | 9 | 95,002 | ART 的轻量帧 |
| `0x00000000000e22b7` | 0, 1, 2, 4, 5, 7, 9, 13, 17, 18, 19 | 1,459 | VQM；在 Ning 中由引用逐项确认，其余库的数量也与各自 VQM EpR 数严格相等 |

位 9 单独存在时，块总长恒为 32 字节：8 字节外层头 + 20 字节固定前缀 + 4 字节标量。Ning 的 6,648 个这种标量全为 `0.0`，时间值范围为 0 到 0.1335147392 秒。普通帧中该值与谐波频率数组第一项严格相同，后续频率为其整数倍，因此位 9 已确认是线性 Hz 的 F0；轻量帧表示没有有效基频的 ART 无声区间。

普通 EpR 的时间轴从 0 开始，相邻帧严格递增：

```text
0.005804988662131519 = 256 / 44100 seconds
```

因此分析 hop 已确认是 256 samples。进一步对全部 DDI 样本比较 SND 长度与 EpR 数量：56,887 个普通 STA/ART 样本全部满足 `samples = frames * 256 + 2048`，而 7 个 VQM 满足 `samples = frames * 256`。普通单元的固定边缘扩展和 1024-sample 半窗对齐共同确认分析窗口为 2048 samples；公开提取脚本中写死的 512 点窗口不适用于本批参考库。

主帧中的位 0–2 共用一个元素数，但物理顺序为位 1 的谐波频率、位 0 的对数型谐波幅度、位 2 的弧度相位。代表性 Ning STA 帧的 count 为 350；后面依次是位 9 的 F0、位 37 的谐波 `ENV `、位 21 的主共振列表、位 22 的头参数与第二共振列表，以及位 23 的残差 `ENV `。主帧块长随动态结构变化，并非固定 11,216 字节。

## DRS 分析对象

RTTI 与 vtable 显示：

- `DRS::CSMSAnalysis` 构造函数：`0x1800cdde0`；
- 主执行函数：`0x1800d2cc0`；
- `DRS::CSMSRegionAnalysis` 构造包装：`0x1800956b0`；
- region 初始化、插帧、收尾：`0x180095780`、`0x1800957f0`、`0x1800959b0`。

构造函数接收采样率和一个大型配置对象，建立 FFT/SMS、窗口、frame buffer、F0/共振等分析工作区。主执行函数会创建 `DRS::CSMSFrame`，再经虚方法加入 `CSMSRegion/CSMSCollection`。

此前只确认了 `wbhsm_getAudioChunk → 0x18002d1c0` 的运行时构造路径；本轮又定位到独立的批处理驱动 `0x1800d9b10`。它可读取 `CSoundIO` 的 16-bit PCM，或读取 `{float *pcm, u32 count, u32 sample_rate}` 内存描述符，以 128 samples 为块供给分析器，循环调用虚方法取 frame、插入 region 并 finalize。原始 PCM 环形缓冲、读写指针、累计输入时间与 hop 公式均已恢复。

但该函数不在 DSE 导出表中，当前只有数据表引用而没有直接代码 caller。DSE 字符串中的 `InputSmsFile`、`OutputSmsFile`、`WindowSize`、`FrameSize`、`Overlap` 也尚未对应到实际入口。因而这是一条可靠的内部契约证据，不是稳定的官方训练接口。

完整偏移表、状态机和限制见 `06_drs_offline_analysis_driver.md`。后续需要分别解决：

1. 确认大型配置对象的字段名、默认值、普通/VQM 模式和版本；
2. 确认 F0/音素/region 标注是否还有外部输入；
3. 把 DRS frame/collection 转成 DSE5 frame/tree 时的字段复制与筛选路径定位出来；
4. 用自有短录音进行可重复的生成—写入—读取闭环。

## 独立验证器

`voicebank/tools/probe_ddb.py` 是本仓库自己的只读顶层探针，不导出 PCM，也不读取整个负载。它按顶层块长度 seek，检查：

- 文件是否能被 `FRM2`/`SND ` 块无缝覆盖；
- 每个块是否在文件范围内且长度至少满足固定前缀；
- 每个 SND 的总长、采样率、声道数与 PCM 值数量是否一致；
- FRM2 的 frame kind、时间值和字段掩码分布。

用法：

```powershell
python voicebank/tools/probe_ddb.py "C:\path\to\voice.ddb"
python voicebank/tools/probe_ddb.py "C:\path\to\voice.ddb" --json
```

另有 `voicebank/tools/probe_frm2.py` 完整解析普通、无声和 VQM 帧的内部数组、ENV、共振及 VQM 特征块，并执行逐字节重新序列化验证。其 `--scan` 模式已让 7 库全部 2,670,252 个 FRM2 精确走到块尾；全部 1,459 个 VQM 帧还额外完成了逐字段回环。M1 尚未完成的部分是若干字段的生成算法和声学标度，不再是块边界。

全量结果及逐库 DDI 引用闭包见 `04_reference_bank_statistics.md`。
