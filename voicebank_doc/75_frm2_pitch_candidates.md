# 模式4候选筛选、历史重选及插值

2026-09-14，DSE哈希同文档74，当前Ghidra目标已核对。
本轮将独立评分继续接到默认候选路径；只对能从队列帧读到正音高的样本作数值通过声明。
清浊门限及后续跨帧修正仍未恢复。

## 默认首选候选

模型为`frm2_pitch_candidate.py`，对应默认变体0、估计器+44为0的分支。

- 将配置的最低/最高Hz转换为评分bin范围。低端转换使用1e-8偏置，不是0.5四舍五入。
  本次最低40Hz、最高1000Hz，评分长度512，内部Nyquist为5512.5Hz。
- 先在允许区间寻找最强严格局部峰，作为相对门限参照。
- 再由低到高扫描候选，要求相对门限、相邻两侧形状及额外两点形状符合条件。
  常规门限为参照峰值的float 0.57倍；参照峰很靠前时另有0.35倍分支。
- 向两侧寻找严格局部谷；检查到候选索引1.5倍附近是否有超过当前峰1.1倍的竞争峰。
  无该竞争峰，且至少一侧谷/峰比小于float 0.9时，选择第一个满足条件的峰。
- 选择值还要通过float 0.05的绝对门限。不能将整段简化为argmax。

源码中变体4及+44非零还有不同分支，本工具不把它们混入默认实现；观察时检查+44为0。

## 历史重选与插值

默认分支还检查之前的音高历史：非零队列索引需至少5次连续计数，索引0时需2次。
相关历史值必须大于无效哨兵，相邻差的绝对值不能超过20Hz。
条件成立时，以最近音高对应bin的0.8至1.25倍为范围，结合配置上下限重新搜索。
重选局部峰须超过原候选评分的0.3倍，满足者中取评分最高者。

选定整数索引k后，对左右三点作抛物线修正：

```text
d = f32(f32(left - f32(center + center)) + right)
offset = d != 0 ? f32(f32(f32(left-right)*0.5)/d) : 0
position = f32(k + offset)
Hz = f32(f32(position / scoreCount) * nyquist)
```

各float舍入在工具中显式保留。此处返回候选Hz，不包含清浊拒绝和后续帧修正。

## 观察点与验证结果

观察器在调用原生step之前记录估计器当前队列帧的指针及历史上下文，
在step返回后读取同一帧的时间、Hz字段。这样不会把较早的批量输出帧误当作当前候选。
读取时断言bit31未置位，确认该队列帧仍使用Hz编码。
完整批量输出与无观察器基线仍逐帧一致。

输入仍是文档74的21份自有准备PCM；评分来自独立频谱、预处理和自相关计算。
**历史上下文取自原生调用之前的状态**，未从零独立演化历史。这一依赖不能省略。

| step结束时的队列结果 | 样本数 | 结论 |
| --- | ---: | --- |
| 正Hz | 16 | 候选预测最大差0.000030517578125Hz，均低于1e-3Hz门限 |
| 模型与队列均为0 | 2 | 仅一致性观察，不证明原生具体选峰分支 |
| 模型有候选、队列已为0 | 3 | 保留未闭合，不能当作候选验证通过 |

220Hz输入约0.035秒的采样处，模型首选索引26，经历史重选变为13，
预测142.31578064Hz，队列读取142.31579590Hz；如果跳过历史重选，预测约275.62036133Hz。
这给历史重选提供了实际生效样本，而不只是检查一个没有触发的分支。
原生未单独暴露整数候选索引，表中索引为模型结果，Hz才是直接原生对照值。

三个保留项是110Hz输入约0.151秒、220Hz和440Hz输入约0.215秒。
它们不能仅凭当前结果归因到某个清浊门限，还需继续追踪候选后处理。
此外，110/440Hz输入的若干队列帧此时仍有正候选，但最终整批输出全部为0；
这说明最终“没有正音高”不能解释为从未产生候选，后续跨帧处理也必须核对。
