# 谱峰后置过滤：斜率分支与反编译缺失

2026-09-14，目标DSE SHA256同文档61。原生入口为`RVA d04c0`。
本轮验证完整入口内的“51e60检测 + 可选斜率过滤”，不通过注入预制输出绕过检测。

## 已验证

160组自有频谱，覆盖64/257 bins、1000/44100 Hz、两种幅值插值尺度、
谐波模式开关及过滤开关。独立结果与原生入口的17,634个输出数值误差为0，
保留峰的两个int字段也全部一致；实际过滤985个峰。

独立实现为`frm2_fft_peaks.filter_slopes`，入口验证为`verify_frm2_peak_filter.py`。
证据：[62_frm2_peak_filter.json](evidence/62_frm2_peak_filter.json)。

## 配置与数值规则

- 分析对象`+ad8`为整数采样率，配置`+520`为整数插值模式。
  汇编明确使用`CVTDQ2PS`再转换/传参，不能把它们当作float字段写入。
- cfg03以dB提供检测阈值，入口用`32768*exp(threshold*ln(10)/20)`转换为线性幅值。
- 配置`+588`为整数后置过滤开关。关闭时直接返回51e60的峰记录。
- 开关启用且cfg38=0时进入本轮斜率分支。
- 相邻峰斜率为`float32(ampNext-ampCurrent) / float32(freqNext-freqCurrent)`，
  除法使用double；斜率大于0.4时删当前峰，小于-0.4时删后峰。
- 模式1下，当前峰小于40 Hz时直接删除。删除后按原生回退规则重新检查邻域。
- 循环只在`index < peakCount-2`时继续：末尾不足三峰不再套用这段规则。
  因此不能把它实现成对所有相邻峰一次独立筛选，也不能额外清理最后两个峰。
- 保留记录整体移动，频率、幅值、相位、区间计数和bin索引本身不被重新计算。

反编译中虽可见按峰间距变化的候选斜率阈值，但实际进入此分支前已要求`+588!=0`，
其后再次检查该开关并覆盖阈值为0.4。本轮遵循可达路径，未把失效候选公式推广为契约。

## 区间计数差异的当前边界

文档61的8个FFT实现差异仍保留。此斜率分支只比较前两个浮点字段，
区间计数随整条记录搬移；这段过滤本身不会读取计数来决定删除。
这仅限制了差异在本分支的影响，尚不等于已经审计所有后续消费者。

## cfg38非零分支尚未完成

本轮发现明确的反编译缺失：伪代码中的频率邻域循环看似只有递增索引，
并在调用ENV加点时省略了第三参数；实际汇编`d0b52–d0c24`包含：

1. 按距离构造权重并连续平方两次；
2. 乘输入频谱值，累计加权频谱及再乘一次频谱后的加权平方和；
3. 分母非零时相除；
4. 将结果放入XMM2，作为ENV加点的数值参数。

因此该分支绝不能按反编译文本复现为零或常量包络。
其完整权重窗口、包络插值与峰幅重写仍需汇编和原生对照，未计入本轮通过项。
后续[文档63](63_frm2_adaptive_peak_filter.md)已补齐这部分，并将整入口矩阵扩大到960组；
本节作为当时发现问题的记录保留。

本轮未声称全部后置过滤或整个普通FRM2生产算法完成。仍有模式2、制作配置、
瞬态/噪声分支及完整PCM生产集成等之前保留的范围。
