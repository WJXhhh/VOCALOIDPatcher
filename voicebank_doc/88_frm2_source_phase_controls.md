# 普通 FRM2：源帧相位控制量接入联合链

接续 [87](87_frm2_fitted_binary_consumers.md)。本轮取消联合链中人为固定的
derivative=0、classification=None，使用自有 PCM 的独立能量计算和帧历史生成控制量。
这完成当前默认分析配置的自动衔接，不代表其它分析模式或商业制作预设已恢复。

## 计算与适用条件

目标仍为 DSE.dll，SHA-256：
`7a4965bd377dbc2b08710e807ae1345b67d9fff6579ca0c01a769f744366f5b5`。
已通过 Ghidra 元数据确认 `/v6/DSE.dll`、x86 LE 64、基址 `0x180000000`。
大型主函数反编译超时后，以已加载 DLL 的限定范围反汇编交叉核对，未重启或改写项目。

原始特征函数 RVA `0xd92e0` 从能量产生 level：正能量使用
`min(0, f32(f32(log10(energy))*10))`，非正能量使用 -500。
主流程 `0xd4e8e..0xd4ee0` 计算：

```text
derivative = f32(0.5*f32(previous-before_previous)
               + 0.5*f32(level-previous))
```

两个历史值从零开始，按全部原始帧顺序更新，包括填充帧。
预测特征按原生帧身份关联最终帧，再用于有状态相位模型；不靠最终有声帧列表重建历史。
原生特征只作比较，不作为预测输入。

受测配置为 mode=4、hop=256，动态配置 `0x35/0x84/0x85` 均为零，入口有显式断言。
该路径 classification 数组保持零；观察器逐帧核对有效项全部为零。
因此这里传入 classification=0，而非上一轮的 None。
相位阈值为 5.9690260887146，实际覆盖 decay 约 0.2 与 π 两条分支。

非默认配置存在额外生产者，不能直接沿用本模型：

- `0x35` 非零可进入额外特征分析并改写控制量。
- `0x84` 非零可从加权频谱重算 level，随后使用另一组队列差分计算 derivative。
- `0x85` 对应的启用分支可由跟踪谐波构建频带特征和后续变换；零分类假设不适用。

这些分支已定位，未在本轮实现或宣称验证。

## 后续直接生产验证的配置反例

尝试把原始特征观察器直接接到 `verify_frm2_phase_pipeline.run_case` 后，
原有相位 harness 的 varying/220 Hz/256 样例在第一帧被严格比较拒绝：
预测归一化 energy 为 0.013421326875686646，而该配置原生 feature12 为
13663494.0；feature4 同时为 0.003921568859368563 对 0.0062500000931322575。
PCM 转为输入 ABI 的 float32 后，逐样本检查通过，因此该差异不是 PCM 精度问题。

显式设 mode4、动态参数0=1、automatic=1 后仍有相同差异。
再取消旧 harness 对配置 `+0x5a8=1` 的覆盖，原始特征比较不再首先报错，
但相位 harness 的帧计数没有推进，触发“Native batch did not produce frames”。
这仅证明两个 harness 的生产调度/特征路径不能直接拼接；尚不能从这些实验
断言 `+0x5a8` 的完整语义，也不能宣称控制量已经与原生相位生产联合验证。

实验适配已撤回，保留原有有效验证器和第88轮全量证据，未放宽容差。
下一步需要定位该配置下特征生产与相位调度的调用边界，再选择同一路径作直接比较。

后续已核实的入口边界（相同 DLL，元数据与限定范围反汇编再次核对）：

- `0xd73c3..0xd740f`：相位段要求配置 `0x2a>0` 且 `0x7d!=0`，否则跳至 `0xd81e7`。
  随后还检查待处理帧时间非负。相位计数在 `0xd81e1` 增加，跳过相位段时不会增加。
- `0xd690b..0xd6958`：配置 `0x7d==0` 才调用外层谐波跟踪 `0xef9f0/0xeff80`；
  非零值跳过这两次调用。这是相位 harness 需要提供谐波数组的直接调用证据。
- 构造配置后通过原生 getter `0x2b050` 交叉检查：写 `+0x5a8=0/1` 时，
  ID `0x7d` 分别返回 0/1；ID `0x17` 均为 0.25，ID `0x2a` 均为 4。
  所以前述差异不能归因于 `0x17` 或 `0x2a` 随该写入自动改变。

源链验证入口新增 `0x7d==0` 断言。这里补齐了调度边界，尚未解决相位路径中
原始特征被改变的具体位置，也没有把两种配置的生产算法当作同一个完整过程。

新增配置断言后，220 Hz 起音样例复验通过：49 个原始帧，状态阶段通过，最终输出无不匹配帧。
命令使用 `verify_frm2_pitch_state.py --frequencies 220 --shapes attack --native-fft`；
报告位于项目旁研究目录的 `phase_gate_89_smoke.json`，工具语法检查通过。

上述处理阶段差异已在[第89轮](89_frm2_source_phase_producer.md)定位并修正，关闭分类特征时的控制量至原生相位生产直接比较已通过。启用分类特征及相同自动F0/谐波序列重放仍保留。
