# 七库录音音高层、样本时长与无音高例外

## 结论

七个 V5 中文传统库的 836 个 STA 和 56,051 个 ART 样本级元数据已经逐项聚合。主音高层不是模糊的“高、中、低”标签，而是稳定的样本选择坐标：同一产品内，38 个 STA 的各层 `pitch1` 高度集中；具有完整层数的 ART 使用几乎相同的层网格。

从七库得到的相对模板为：

| 主层数 | 参考产品数 | 相对各库层中心的稳健偏移（半音） | 相邻层间隔中位数（半音） |
| ---: | ---: | --- | --- |
| 2 | 1 | `-2.503, +2.503` | `5.007` |
| 3 | 4 | `-3.670, +0.335, +3.335` | `4.006, 3.000` |
| 4 | 2 | `-5.377, -1.372, +1.624, +5.125` | `4.005, 2.996, 3.500` |

这些是可转调的相对形状，不是新歌手必须照抄的绝对音域。3 层产品的典型绝对点约为 `C4/E4/G4`；4 层两个参考产品分别接近 `C4/E4/G4/B4` 和 `C4/E4/G4/A#4`。应先确认歌手舒适音域，再把整组偏移平移进去。

```powershell

  --ddb-tools C:\path\to\ddb-tools `
  --bank Luo_Tianyi_Ning="C:\...\Luo_Tianyi_Ning.ddi" `
  --bank Luo_Tianyi_Wan="C:\...\Luo_Tianyi_Wan.ddi" `
```

本轮仍固定 `yuukawahiroshi/ddb-tools` 提交：


## 逐库层坐标

以下音分均相对 A4=440 Hz，按 `pitch1` 从低到高对 38 个 STA 取中位数：

| 声库 | 层数 | STA 层中位数（cent） | 近似音名 | 相邻间隔（cent） |
| --- | ---: | --- | --- | --- |
| Luo_Tianyi_Ning | 2 | `-700.450, -199.795` | D4, G4 | `500.655` |
| Luo_Tianyi_Wan | 4 | `-900.730, -500.088, -200.805, +199.545` | C4, E4, G4, B4 | `400.642, 299.283, 400.350` |
| Yan_He_Mu | 3 | `-901.356, -500.637, -200.690` | C4, E4, G4 | `400.720, 299.947` |
| Yuezheng_Ling_You | 3 | `-900.766, -500.537, -200.415` | C4, E4, G4 | `400.230, 300.121` |
| Yan_He_Qing | 3 | `-987.888, -586.938, -188.899` | B3, D#4, G4 | `400.950, 398.039` |
| Luo_Tianyi_Meng | 3 | `-900.894, -500.436, -201.660` | C4, E4, G4 | `400.458, 298.776` |
| Yuezheng_Ling_Chi | 4 | `-900.483, -500.055, -200.054, +99.676` | C4, E4, G4, A#4 | `400.427, 300.002, 299.729` |

对每个产品和层，全部满层 ART 的 `pitch1` 中位数与对应 STA 层中位数最大只差 `6.7443 cent`。这证明“STA 与普通 ART 共用主层网格”不是仅凭层数推断；它有实际坐标证据。

个别产品/音色的同层不同音素会出现几十 cent 的实际录音漂移。例如某些 STA 的 p95 范围明显比其它产品宽。构建器应保留 `pitch1` 作为人工整理后的层选择坐标，同时让 `pitch2` 保存每个样本从 F0 帧得到的实际参考音高，不能强行把两者都量化为整数 MIDI 音符。

## `Sil→无声辅音` 的单层样本确实是“无音高”

七库共有 96 个单层 ART key/sample；每一项都满足：

```text
source = Sil
target = PHDC 中的 unvoiced consonant
pitch1 = -FLT_MAX
pitch2 = -FLT_MAX
```

也就是序列化的 `float32 -3.402823466e38` 哨兵，而不是某个隐藏的中间音高。其时长中位数均为 `3072/44100 ≈ 0.069660 s`，少数达到约 `0.087075 s`。这为单层规则补上了比“层数统计”更强的证据：这些是短促、无 F0 的静音起辅音单元。

新库仍不应在录音前武断删掉其余音高的原始 take。保守流程是所有长提示先按主层全录，切分/分析后再让 `Sil→unvoiced` 只保留一个通过 QA 的无音高候选；这样不会因为产品间例外集合不同而欠录。

## 时长不是录音句长

逐库 DDI 样本时长中位数：

| 声库 | STA 中位数（s） | ART 中位数（s） |
| --- | ---: | ---: |
| Luo_Tianyi_Ning | 1.4425 | 0.3889 |
| Luo_Tianyi_Wan | 1.2016 | 0.3193 |
| Yan_He_Mu | 1.2655 | 0.2844 |
| Yuezheng_Ling_You | 1.1958 | 0.3193 |
| Yan_He_Qing | 0.9201 | 0.3541 |
| Luo_Tianyi_Meng | 0.5544 | 0.3077 |
| Yuezheng_Ling_Chi | 1.7473 | 0.3309 |

按有声/无声类别，各库 ART 中位数范围为：

| 转接类别 | 各库中位数范围（s） |
| --- | ---: |
| voiced → voiced | `0.3251–0.4586` |
| voiced → unvoiced | `0.1509–0.2032` |
| unvoiced → voiced | `0.2670–0.3541` |
| unvoiced → unvoiced | `0.0697` |

这些数值是最终单元的 SND/分析时长，包含普通 STA/ART 的 2048-sample 边缘扩展；它们不是原始录音句、音节拍长或歌手换气间隔。可以用它们检查切分候选是否荒谬，但不能倒推出唯一正确的录音 BPM。

全部 56,887 个 STA+ART 样本把 `dynamics` 写为约 `0.6`、`tempo` 写为 `90`、`unknown2` 写为 `0`。这证明最终树的元数据默认值高度稳定，但 `dynamics=0.6` 不是麦克风输入电平或 LUFS 目标，`tempo=90` 也不是已经恢复的原始录音节拍。

## VQM 旁证

七库各有一个 VQM 样本，`pitch1` 都是原始值 `224 cent`，时长只落在约 `0.6095/1.0565/1.7125 s` 三组。当前仍不知道 VQM 的 `224` 是怎样由 growl 录音/分析确定的；不能把它当作主层中心，也不能据此生成 VQM。录音 session 规划器暂不安排 growl take。

## 对自训路线的影响

现在可以把 M4 的层策略写成明确规则：

1. 选择 2/3/4 层之一，并使用对应的相对模板；
2. 通过试唱先选整组中心，使最低和最高层都落在歌手舒适区；
3. 38 个 STA 与全部普通 ART 使用同一层网格；
4. 保存每个样本的实际 F0，构建时分别写层坐标 `pitch1` 与实际参考 `pitch2`；
5. `Sil→unvoiced` 可在分析/QA 后降为一个无音高层，不在录音前欠采；
6. 真实录音仍必须验证音高稳定、噪声、边界窗泄漏与跨层音色连续性。

下一步的结构化录音清单见 [分层录音 session manifest](23_recording_session_manifest.md)。
