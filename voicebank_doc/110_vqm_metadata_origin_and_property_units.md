## 一、所查统计调用没有连接到DDI制作赋值

107确认了 `0xC84F0 → 0xC86A0` 的集合均值及斜率。本轮按现有交叉引用检查其直接上层：

| 已确认关系 | 当前能说明的内容 |
| --- | --- |
| `0x959B0` 在 `0x95A11` 调用 `0xC84F0` | DRS区域收尾后计算集合统计，输入来自上下文当前区域和hop；未见写part的pitch字段 |
| `0x8D6E0` 在 `0x8E44C/0x8E467` 调用 `0xC84F0` | 调整相邻区域边界及帧时间后，对两侧集合分别重算统计；不是DDI元数据保存入口 |

以上是Ghidra实际查询获得的限定调用关系及对象访问分类，不是对全DLL生产者的穷尽排除。本轮到这层停止，没有沿区域编辑的帧移动、索引重建等无关分支继续扩展。

`0x959B0`的可选后续调用`0xCBC80`也作了对象归属核对：它读取Frame另一个`+0x130`指针并写区域扩展统计`+0x278`，不能把这些偏移当成bit13的`Frame+0x128 → Feature`。本轮不展开该独立统计块的算法或原SMS2尾部专项，也未将它判为制作音高已找到。

24/24份VQMp的pitch2与原生均值核逐位一致仍有效，但上述连接仍不能把“数值吻合”升级成“原制作程序调用该核并写入DDI”。

## 二、公共part构造、保存、加载只是默认值与传输

RTTI确认虚表 `0x225B28` 属于 `DSE5::CDBDataPhUPart`。已查构造及虚表中公共元数据读写方法，不把所有PhUPart子类当成VQM专用类型。

| 入口 | pitch1/pitch2数据流 | 分类 |
| --- | --- | --- |
| `0x109B30` | 将part `+0x160/+0x164`一起清零；另将`+0x16C`设为float32 0.6、`+0x170`设90 | 默认初始化，不是估计制作音高 |
| `0x10B5D0` | 从part `+0x160/+0x164`各取四字节写出，前面有8+2字节元数据 | 序列化已有值；不重新计算或换单位 |
| `0x10B1A0` | 普通格式读pitch1/pitch2，再读其余三个float；备用格式读pitch1、dynamics、pitch2并清unknown2/tempo | 按格式加载已有值；不推导pitch1/pitch2 |
| `0x112220/0x113CC0/0x1148E0` | 先调用上述公共读取，再读取各自附加字段 | 已查派生读取包装，不是制作赋值证据 |

469对9组自有pitch字段位型分别验收普通/备用格式，共 **18组**。涵盖正负零、有限值、负FLT_MAX、Inf及NaN负载；这些是原样传输测试，**不表示非有限值是合法声库制作音高**。普通写出30字节、备用自有输入22字节；pitch1/pitch2四字节全部精确，写出时源对象保持。两个字段构造时均为0、其余默认值也已直接核对。

因此，这组入口可以从“疑似计算制作音高”中剔除；不能由此说DLL没有其它制作入口或字段不会被外部调用者直接赋值。

## 三、必须区分的三个音高位置

| 位置 | 实际含义/单位证据 |
| --- | --- |
| VQM part `+0x160` → 素材记录`+8` | Growl选择坐标，按Hz使用；沿用43、107–109，不由本轮重新定名 |
| VQM part `+0x164` | 已保存参考音高；V4X样本与有效Frame F0的cent均值逐位对应，原制作赋值连接仍未知 |
| DSE5 Frame `+0x1D0` → TimbreModel的`pitch`属性 | 从原生Frame读取器得到的Frame已统一为cent；getter只复制此槽，本身不执行Hz→cent转换 |

469给定55/110/220/330/440/520.6/880Hz的自有音高，各构造Hz编码及对应cent编码两份FRM2，共 **14份**。原生 `0x106E20` 加载后：

- Frame `+0x150`的bit31均置位，`+0x1D0`与独立cent公式float32逐位相同，两种输入编码得到相同值。
- 将真实加载得到的Frame交给原生模板叶和模型，`0x110020` 的`pitch`属性与该cent槽逐位相同。
- 同一加载Frame的`opening`和`dynamics`分别原样返回特征`+0x218/+0x21C`，即内部16/17；两种F0编码均不改变这些特征属性值。

例如220Hz和−1200cent两种文件输入均得到模板坐标−1200；880Hz和1200cent均得到1200。其余非八度输入同样逐位通过。`pitch`轴与Growl的part pitch1不是同一个位置，不能直接互换数值。

先前403/405在人工建立Frame上验证属性和选择器；本轮补的是**两种文件编码经真实加载器到属性消费者**的成对一致性。Frame规范化应归给加载过程，不归给只复制四字节的模板getter。手工拼接且未规范化的Frame不在这条加载保证内。

内部16在VQM完整窗的已有生产关系是特定峰幅度转dB后除10；模板把相同位置称为`opening`不等于已找到原生Mouth控制量换算。内部17被称为`dynamics`也不证明VQMp保存值的物理单位或PCM生产公式。保留既有“属性轴语义”和“商业VQM制作字段”之分。
