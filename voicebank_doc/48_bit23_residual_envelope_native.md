## 已验证的数值关系

已有静态入口`0x1800763b0(frame,setIndex,maximumFrequency)`生成DRS
bit23 / `+0x1c8` Envelope。代码在谐波位置计算输入包络幅度减去
两组共振响应及A/B/C曲线的模型幅度，再沿30Hz网格填充差值。
以下实验先隔离到无共振、B=0、仅A基值的情况，避免用复杂模型掩盖误差。

用DRS构造器`0x7ec30`建立自有帧，mask=`0x400203`：频率和幅度数组、
F0及bit22；频率为300/600/900Hz，F0=300，主/第二共振count均为0。
不设置bit7，使原生函数自行从谐波数组建立临时输入Envelope。
设置A，B=C=0，以setIndex=0、maximumFrequency=22050调用。

| 幅度数组 | A | 300/450/600/750/900Hz的预期输出 |
| --- | ---: | --- |
| -20/-30/-40 | -30 | 10 / 5 / 0 / -5 / -10 |
| -20/-30/-40 | -40 | 10 / 10 / 10 / 5 / 0 |
| -180/-180/-180 | -30 | -100 / -100 / -100 / -100 / -100 |

三次调用均返回0，生成736点Envelope，以上15个值误差均小于1e-4；
最大实际误差约3.82e-6。450Hz点的x与450/22050相差小于1e-12。
第一例输出mask为`0xc00203`，增加bit23。

这些结果直接支持：该路径生成的纵坐标是输入对数幅度与模型对数幅度的
差值，插值后限制到[-100,10]。第二例450Hz输出10，而若先把两端差值
20/10各自限幅再插值也会得到10，所以仅凭该点不足以区分两种顺序；
顺序结论仍以静态代码为依据，不声称本批点值独立证明全部操作顺序。

## 边界及未完成部分

第一例0Hz值为0，30/150Hz为1/5；900Hz后首个930Hz网格值仍为0。
说明本调用不会自动把最后一个差值外推填满整个Nyquist区间。
这些边界值来自首次探索调用，正式三例报告主要保留上述五个内部频率点。

bit23在这里是声学模型拟合差值，不能仅由旧文档的“残差/非谐波”名称
理解为独立噪声能量谱。真实共振响应、B/C非零、bit10偏移、无声输入、
完整合成消费者和成品V4X逐帧还原仍需验证。
普通bit37的生成公式仍未确定，本实验不能替代该项。

只使用自有数值数组，无商业PCM或点集落盘，独立进程正常退出。

## 非零曲线、bit10及限幅顺序已补充实测

保持无共振和300/600/900Hz三谐波输入，追加以下原生实验。

- 区分顺序：幅度[-10,-40,-50]、A=-30、B=C=0，原始差值为[20,-10,-20]。
  450Hz输出为5，符合先将20与-10插值得到5、再限幅；若先把20限制到10，
  再与-10插值则应为0，原生结果排除了这个候选。
- 非零曲线：幅度[-35,-40,-45]，A=-30、B=40、C=-0.0001。
  300/450/600/750/900Hz输出依次为
  -3.81782150、-5.74420166、-7.67058182、-9.61391449、-11.55724716。
  参考公式先在三个谐波处计算
  `amplitude - (A+B*(exp(f*C)-1))`，再线性插值并限幅；五点最大误差4.18e-7。
- 同一曲线开启bit10，并在DRS `+0xf8`设置3：上述五点各增加3，
  与`amplitude+offset-model`一致，最大误差同样小于4.18e-7。

三次调用均返回0，每次生成736点，全部15个点通过1e-4阈值。
这将前文仍依赖静态代码的限幅顺序，提升为有区分能力的原生执行证据；
同时闭合本受控路径的B/C和bit10作用方向。仍未覆盖真实共振响应及成品全量还原。
报告为`%TEMP%/v4x_bit23_curve_offset_order_20260913.json`。
DLL哈希再次核对一致，仅用自有数组，无Editor启动或源码改动。

## 两组共振的中心频率响应与求和已验证

使用原生共振setter `0x62760`初始化自有共振：中心600Hz、对数幅度-30、
带宽200Hz。输入谐波为300/600/900Hz，幅度均-30；显式把A/B/C置0。
分别将共振放入主列表（bit21、count/pointer为+0x180/+0x188）、
第二列表（bit22、+0x1b0/+0x1b8），以及同时放入两组。

| 列表配置 | 600Hz残差实际值 | 预期 |
| --- | ---: | ---: |
| 仅主列表 | -1.90735e-6 | 0 |
| 仅第二列表 | -1.90735e-6 | 0 |
| 两组各一个相同共振 | -6.02060127 | -20*log10(2)=-6.02059991 |

三次返回0，最大误差小于1.91e-6。该中心点证据支持两组共振均进入同一
模型幅度，并在线性幅度域求和后转回对数幅度；没有按功率相加得到3.01的结果。
尚未验证离中心频率处的滤波响应、不同带宽、多重共振及整条成品频谱。

首次实验因只调用构造器而未显式设置A失败：第二列表输出-100。
复查构造器得到A=10000、B=10000、C=0；清零分配缓冲不等于构造后字段为0。
显式设置A/B/C后通过。前文首次基值实验实际设置了A，C=0使默认B的指数项
恰为0；“B=C=0”的原描述应理解为有效指数项为0，而非B字段已被显式写0。
后续三组曲线/偏移/顺序实验均已逐项设置A/B/C，不受该初始化问题影响。

报告为`%TEMP%/v4x_bit23_two_resonance_lists_20260913.json`。
DLL哈希一致，仅用自有对象，无Editor启动；本轮仅修改文档，未运行构建。

## 离中心响应：两组不同共振、三种带宽通过

两组分别设置中心600/750Hz、对数幅度-30/-36；每次共用带宽20、200或1500Hz。
输入频率300/450/600/750/900Hz，幅度均-50；F0=150，A/B/C显式置0。
仍使用原生setter初始化每个共振，再调用bit23生成入口。

按当前共振对象派生系数独立计算消费者公式：

`theta = 2*pi*(fs/2 + center - f)/fs`

`den = hypot(1-a1*cos(theta)-a2*cos(2*theta), a1*sin(theta)+a2*sin(2*theta))`

`R(f) = gain/den * linearAmplitude/normalizer * exp(-((f-center)/2000)^2)`

对象字段fs/+0x60、gain/+0x68、a1/+0x70、a2/+0x78、normalizer/+0x80，
linearAmplitude为+0x50。高斯频宽常量从同DLL RVA0x5bfad0读取，确认为2000。
先求两组R之和，再计算`clamp(-50-20*log10(sumR/32768),-100,10)`。

| 带宽Hz | 五个频率点的最大误差 |
| ---: | ---: |
| 20 | 1.71e-6 |
| 200 | 6.24e-6 |
| 1500 | 3.44e-6 |

三次原生调用返回0，15个点全部通过1e-4阈值，覆盖离中心响应与上限裁剪。
这验证的是消费者如何使用原生setter生成的派生系数；并非独立恢复setter
系数生成算法，也不等于已证明成品库采用相同制作参数。
报告为`%TEMP%/v4x_bit23_offcenter_resonance_20260913.json`。
DLL哈希复核一致，全部使用自有数组/共振，无Editor启动或源码改动。

## 共振setter的系数公式也已独立核对

同目标Ghidra反编译`0x180062760`并读取DLL常量，得到：
RVA0x5bfed8=-2π、0x5bfec8=-π、0x5bfbb0=22050、0x5bf7a8=π、0x5bf888=2π。
在有限正常幅度输入下，滤波系数仅由限制后的带宽决定，中心频率另存于+0x40。

令`w=clamp(bandwidth,20,1500)`，`fs=22050`：

- `a2=-exp(-2*pi*w/fs)`
- `a1=2*exp(-pi*w/fs)*cos(pi)`
- `gain=1-a1-a2`
- `den0=hypot(1-a1*cos(pi)-a2*cos(2*pi), a1*sin(pi)+a2*sin(2*pi))`
- `normalizer=gain/den0`

独立Python使用这些数学表达式，而不读取原生派生系数作为参考值；
对中心200/600/5000Hz与输入带宽5/20/200/1500/2000Hz的15种组合，
分别核对原生setter写出的中心、带宽、fs、gain、a1、a2、normalizer。
全部字段精确吻合（记录的最大归一化误差为0），并确认两侧带宽裁剪。
幅度还原另见文档45，本次固定幅度-30，未覆盖NaN/Inf等异常输入。

这补齐上一节依赖原生setter系数的缺口：目前正常有限输入的系数生成式及其
离中心消费者均有独立计算对照。仍不据此声称完成商业帧制作链的逐项还原。
报告为`%TEMP%/v4x_resonance_coefficients_20260913.json`。
DLL哈希再次核对一致，独立进程正常退出，无Editor启动或源码改动。

## 成品V4X对照：直接使用最终谐波重算仍有反例

复用文档47已记录偏移的48帧（8库各首/末STA的首、中、末帧），
将各帧完整谐波频率/幅度、F0、两组共振三元组与A/B/C载入自有DRS对象。

## 找到对应的谐波重建消费方向

继续核对现有harness所调用的重建入口`0x180064c30`及其下游
`0x180077e40`。后者先清零幅度/相位输出，然后在bit22存在时加入
A与指数曲线贡献；bit23存在时按`frequency/maximumFrequency`求包络值并
加到幅度输出；随后合并共振响应，转为`20*log10(linear/32768)`后再相加。
这给bit23建立了生成与消费两个方向的静态对应：生成时从输入减去模型，
重建时将保存差值加回模型，而非作为独立噪声能量直接合成。

重建入口还包含由bit7包络重建幅度数组的另一分支，并在末尾可将bit10
幅度偏移折入数组、清除bit10。因此“最终谐波数组仍等同拟合时输入”
并非可以省略验证的前提。此调用链并未证明上述48个成品反例具体经过了
哪一分支，也不能据此断定差异就是该重建步骤造成。

`0x77e40`还存在按频率门槛切换共振响应实现的分支；本轮仅核对静态代码，
尚未做该完整入口的原生调用或两种响应实现的全频段对照。
Ghidra目标哈希和基址再次确认一致，仅只读查询，无源码改动。

## 生成→重建已通过原生幅度闭环

用前述两组共振（600Hz/-30、750Hz/-36），带宽分别测试200与1500Hz；
输入300/450/600/750/900Hz五个谐波的幅度均为-50，A/B/C为0。
先调用`0x763b0`生成bit23，随后对同一帧调用`0x77e40`恢复各谐波幅度。

消费者ABI实测为`int64(frame,float frequency,float maximumFrequency,
float* amplitude,float* phase,byte setIndex,float* threshold)`；
本次maximumFrequency=22050、setIndex=0，显式threshold=5000。
两种带宽的全部10点恢复到-50附近，最大误差7.63e-6，全部通过1e-4阈值，
生成与消费调用返回码均为0。这将先前静态的“差值加回”提升为实际闭环证据。

这些谐波落在30Hz网格上且差值未触及限幅，因此不能把10点恢复结果
推广到网格之间、发生限幅、高于响应切换门槛或所有商业帧。
本实验只验收幅度输出，没有将相位指针有返回值当作相位语义已验证。
报告为`%TEMP%/v4x_bit23_generate_consume_20260913.json`。
同DLL哈希复核通过，自有对象独立进程正常退出，无Editor启动或源码改动。

## 成品保存差值的消费方向对照（固定实验配置）

对前述48个成品帧，将其保存的bit23点集放入自有DRS Envelope，保留文件
两组共振及A/B/C，调用已验证的`0x77e40`。只比较0<f<5000Hz且幅度非10000
哨兵的谐波，显式响应切换门槛为5000，避免把高频分支混入本轮结论。
48帧均正常返回，但没有一帧全部比较点满足1e-4误差；整批最大幅度差为0.4838104。
Original EVEC首STA三帧最大差为0.2567024、0.1332645、0.2636108。

本次Envelope使用实验配置3/1/3、[-100,10]，原文件flags对应配置尚未完整映射，
因此应称为“固定配置下保存点值的消费对照”，不能冒称完整复现原文件Envelope
状态。原生配置函数`0x611e0`将三个模式参数分别写到+0x40/+0x41/+0x42，
后续需核对文件flags解码和求值模式，再判断上述偏差是否仍成立。
同时本次只比较低频谐波点，不能把0.4838与此前全频包络点最大差29.67直接
比较为同一指标的改善。

报告为`%TEMP%/v4x_bit23_saved_consume_20260913.json`，只保存逐帧偏移、
比较点数和误差统计，无商业负载落盘。DLL哈希核对一致，无Editor启动或源码改动。

## 文件flags的原生解码确认了实验配置差异

生成两份仅flags不同的自有ENV，点为(0,-10)、(0.5,5)、(1,-20)，
通过DRS Envelope构造器与通用reader `0x93000`实际回读：

| flags | 模式字节+0x40/+0x41/+0x42 | +0x54 | +0x58 |
| --- | --- | ---: | ---: |
| 0x01820002 | 3/1/3 | 0 | 0 |
| 0x00960002 | 3/1/1 | 0 | 1 |

两次reader返回0、完整游标与三点数量均通过。
后者才对应本文成品bit23的flags。此前保存点值消费实验采用3/1/3且+0x58=0，
确实没有恢复原文件的求值状态，因此0.4838104不能当作正确配置下仍有偏差的证据。

进一步以相同自有点值调用原生求值器`0x2b30`，在x=0.25/0.75处：
3/1/3配置输出-0.9375/-6.5625；3/1/1且+0x58=1输出-2.5/-7.5，
后者与线性插值一致。此为具体点值实测，尚未恢复模式3的完整插值公式。
下一步应按正确模式重跑成品消费对照，而非继续解释旧配置的误差。
