# 相位差历史：初始化依赖的触发条件

2026-09-15，继续普通 FRM2 精确数值语义，承接文档95。

## 已验证的结论

零初始历史不是唯一能匹配原生的条件。把私有分析对象的700个历史槽分别设置为0、-12、+12弧度，并让独立模型使用同样的给定初值，12组、1,044帧全部零误差：31,320项对齐相位、31,320项局部修正、31,260项有效历史差值、33,318个ENV点。预测不读取原生历史或ENV结果。

| 自有谐波序列 | 改变初值的效果 |
| --- | --- |
| 所有槽从首帧有效 | 无变化，初值在消费前已被实际差值覆盖 |
| 220 Hz槽在第10帧首次有效 | 两种非零初值均从第10帧起影响输出，各60帧ENV与零初值不同 |
| 4620 Hz槽在第10帧首次有效 | 无变化，高于3500 Hz时不沿局部历史修正分支消费初值 |
| 220 Hz槽先有效5帧、暂停10帧再有效 | 无变化，已有实际历史；这里是槽失活，不是整段F0变为无声 |

这将文档95的“可能读到未写历史”细化成了可复现的条件依赖：连续有声计数超过5，低于或等于3500 Hz的槽第一次有效时，如果该槽此前没有形成差值历史，输出会依赖所提供的初值。任意商业输入的激活规律仍未证明。

## 工具及验证

新增 `voicebank/tools/verify_frm2_phase_initial_history.py`。各例独立进程、60秒超时、步数上限；先严格检查每例原生与独立模型数值相等，再比较不同初值的ENV摘要。摘要只包含自生成数据的哈希。

`PhaseModel` 和 `run_case` 接受显式 `initial_delta`，默认仍为0，保持文档95的测试条件。运行报告记录初值和700槽容量。9组插入边界回归再次通过，783帧、17,042个ENV点仍零误差。未修改安装DLL、Editor或Ghidra项目，未使用Windows Temp。

## 未闭合的生产入口

本轮也尝试在mode4自动F0的自有PCM批处理入口仅打开相位分析，不注入谐波。原生step出现空地址读取，未得到可验收的相位输出。这个失败与文档53记录的直接启用相位分析后缺少谐波数组的配置限制一致；它不是“商业生产也有同样历史缺陷”的证明。未保留无法完成验证的临时探针，也没有更改正常批处理工具的接口。

因此本轮完成的是相位子流程的初始条件和消费边界验证。完整生产入口的有效配置、商业槽激活/预热契约仍待查明。不能把显式置零测试扩展为原生正常制作流程的完成声明。
