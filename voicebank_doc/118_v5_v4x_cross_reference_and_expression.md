# V5 与 V4X 交叉核对及表情资源机制

2026-10-15。本轮只读本机七套中文 V5、八套固定哈希的日语 V4X，以及三份新安装的 Attack/Release 资源。采用后来完成的 FRM2、VQM、pitch2 和元数据契约重新核对早期中文结论。**本批 V5 不需要另一套普通 FRM2 格式；最值得区分的机制是独立、按歌手绑定的 Attack/Release 资源。**

正式统计、哈希和动态结果见[证据479](evidence/479_v5_v4x_cross_reference.json)。本页限于这些产品，不能把中文/日语、厂商或制作配置差异自动归因于 V5/V4 代际。

## 2. 哪些原有规则可以沿用

**普通 FRM2**：所有 STA/ART 仍只用普通主掩码 `0x2000e00207` 或无声掩码 `0x200`，没有新增普通帧家族。完整边界验证沿用[37](37_v4x_frm2_optional_spectrum.md)之后的解析器，不必改变[98](98_frm2_numeric_completion_audit.md)已交付模型。另按每库 STA/ART 各16个分散 part 取首/中/尾帧，检查672帧：643普通帧、29无声帧全部 Python 按字节回环，原生读取与 F0 规范化一致。抽查含幅度、两组共振及三项第二头统计，不扩大为全量数值核一致。

**音高与边界**：836个STA、56,051个ART的 pitch2 均符合“STA全段、ART按PHDC有声outer区间，取正F0的cent均值”规则。其中163个ART无可用音高，预测和保存均为负FLT_MAX；其余最大误差 `0.0002659753 cent`，全部小于 `0.01 cent`。2,668,793个普通帧时钟检查无异常，ART时间在各outer区间重新起算。全部ART都是双音素、两组alignment，未见本批V4X EVEC的三音素/四组结构。

本批V5全部STA/ART都满足 `PCM count = frames×256 + 2048`，VQM余量为零。这个观察与早期中文统计一致，但V4X已有短余量反例，仍不把2048强制成跨产品规律。

**三项元数据**：56,894个part的 unknown2/dynamics/tempo 仍全部为 `0 / 0.6000000238418579 / 90`，与[117](117_part_scalar_consumers_delivery.md)的V4X基线相同。本批没有提供非常量样本，因而没有新增 unknown2 业务意义或制作公式证据。

**音素与目录**：七库均为同一62音素、38 STA key、2–4主层的中文体系，ART material key为2,556或2,559，与[14](14_chinese_phoneme_graph.md)/[22](22_reference_pitch_layers_and_durations.md)一致。七库共294个TMM、882个pitch/dynamics/opening轴数组，由两个解析方式确认全部为空；V4X的486个TMM、1,458个轴数组仍为空。空的保存目录不排除运行时或其它资源添加模板。

PHDC的EpR guide有两组配置：凝/婉/沐/幽43项，清/萌/炽1项。本轮只登记保存配置差异，未确认音频影响，不命名为V5专有算法。

## 3. Growl：同一体系，素材配置不同

| 项 | 本批V5 | 本批V4X |
| --- | --- | --- |
| 每库VQM part | 1 | 3 |
| VQM FRM2掩码 | `0xe22b7` | `0xe2287` |
| 保存的完整频谱 | 每帧2,049 bins | 不保存该段 |
| VQM总帧数 | 1,459 | 1,968 |
| 内部特征标志 | 全部 `0x1fffff` | 全部 `0x1fffff` |
| 外层bit18 / bit19 | `10 / 2049` | `10 / 2049` |
| 内部10/11/12/13数组 | 均为零 | 均为零 |
| 内部bit17 | 全部非零 | 全部非零 |

bit17指 `Feature+0x21C`，不是FRM2外层bit17。V5值约 `1.0727583–3.5875056`。两侧全部3,427帧的466,072个特征float、外层控制量及规范化F0与原生读取逐字节符合。读取不是生产算法，**本轮不追非零值来源或单位**。

V5 part的pitch1全为224，按既有Growl选择坐标解释；pitch2则随素材分组，约−1174.8623、−813.6685、−814.5186 cent，与帧正F0均值一致。选择坐标与实际参考音高不可直接互换，不能把224常量当作全部素材实际基频。

对每个VQM的全部帧串联和PCM分别求哈希，两者同时相等的分组为：

- 凝、萌：同一组，105帧。
- 婉、沐、清：同一组，295帧，跨两个歌手产品复用。
- 幽、炽：同一组，182帧。

七个产品因此不是七份独立Growl统计证据。V4X八库共同使用另一套三VQM样本。这里证明成品内容相同，不推断录音者或制作来源。频谱有无也是产品差异；旧V4中文样本同样可有完整频谱，不能称为“V5才支持”。

## 4. V5有EVEC的“衣钵”吗

**用途有相近之处，技术继承没有得到证明。** Crypton的[官方EVEC说明](https://sonicwire.com/product/virtualsinger/special/v4x)分为Voice Color、Voice Release、辅音强调；[V5官方手册](https://rsc-net.vocaloid.com/assets/pdf_files/VOCALOID5_Reference_Manual_ENG.pdf)印刷页42–43描述逐音符Attack/Release、强度调节、Pitch/Dynamics/Tone/Ornamentation分类及专用声库效果。两份说明没有建立实现同源关系。

本机V5七库没有`#`扩展音素，也没有已识别EVEC颜色/吐气扩展单元图。V4X EVEC的已验证依据仍是[31](31_evec_v6_adaptation_progress.md)及后续宿主记录，不能回到29早期“只加后缀便完全一致”的假设。

V5这批安装可以确认另一套资源组织：

```text
AttackReleaseLib/Components/<效果组件>/Voices
    → 允许关联的歌手CompID
Path → dvqm.dat
    → attack / release
        → 效果属性路径
            → multiph 或具体音素样本
```

| 效果组件 | Voices实际绑定 | 文件内容 |
| --- | --- | --- |
| `BN6BKCE4M6TM2NEA` | 乐正绫幽、炽 | 11,916,233字节 |
| `BN7BLCT4N6WM3NFD` | 言和沐、清 | 同大小、同SHA-256 |
| `BW5DWHP6YBSPAWFC` | 洛天依凝、婉、萌 | 同大小、同SHA-256 |

三份SHA-256都是 `81c3fa4393dd89ea2f2529dc2f678dd77c54b86594940420379157d9dbbd53e6`。成品安装允许一套效果内容经不同注册组件关联多个音色，没有为每个主声库准备独立效果内容。注册关联是保存的可用范围，不等于本轮验收了Editor最终筛选/派发。

唯一内容含 **25个效果属性目录、33个样本**：attack 14类/20样本，release 11类/13样本。包含Airy、Bel canto、Up/Down、Ornament、Trill、VocalFry及收尾的Accent、Decrescendo、Dynamic、Stop、Vib等。多数是`multiph`通用样本；VocalFry另有具体音素。样本数和属性目录数不能混淆。

三个路径均通过原生属性解析与分段核对，共99组，零不一致。对一个唯一内容的全部33样本逐一原生加载、配置，再做一次预处理与四次256-sample音频调用：33次预处理和132次音频调用均返回0，33,792个输出float全部有限且非零，缓冲保护区保持。**这是独立效果素材消费，不是效果混入七个歌手真实音符的听感验收。**

这条路径能承担起音、收尾、音色修饰的一部分表情用途。本轮没有找到与EVEC持续段Voice Color逐项等价、共享配置或共享扩展音素编码的证据。旧V4X EVEC在现代引擎里的兼容能力，与新V5产品是否内建EVEC，需要分别验收。

## 5. 入口与验证协议

目标仍是x86-64 DSE.dll，SHA-256 `7a4965bd377dbc2b08710e807ae1345b67d9fff6579ca0c01a769f744366f5b5`，基址 `0x180000000`。Ghidra元数据和`0x106E20`局部读取查询成功；没有重新导入、改名、改类型或扩大遍历。下列为RVA：

| 路径 | 本轮复用的入口 |
| --- | --- |
| FRM2/特征读取 | `0x106E20 / 0x135EB0`；直接原位读DDB，不复制帧到临时文件 |
| F0/模板属性 | 加载后置bit31、F0转cent，沿用110；getter `0x110020` 来源分类不变 |
| DVQM资源加载/释放 | `0xFEA0 / 0x10080` |
| 属性解析/三段时长 | `0x23F00 / 0x11180` |
| 控制创建/样本加载/信息/配置 | `0xB400 / 0x100A0 / 0xB5B0 / 0xB6B0` |
| 音高输出/音频块/销毁 | `0xD140 / 0xEB00 / 0xB480` |

原位读取的流逻辑偏移必须等于实际文件偏移，包括超过4 GiB的位置；不能照搬从零开始的独立帧协议。初始探针漏置该偏移，另曾误按原始Hz校验规范化F0；已按包装器和110既有规则纠正，失败不计通过。最终全组原生结果独立重复一次，JSON按字节相同。

新增工具：[交叉统计](../voicebank/tools/audit_v5_cross_reference.py)、[原位读取验证](../voicebank/tools/verify_cross_bank_vqm_read.py)、[仅整理已有JSON](../voicebank/tools/summarize_v5_cross_reference.py)。数据在仓库同级 `VOCALOIDPatcher-research-work/v5-cross-20261015`，不使用Windows Temp。DVQM复用 `verify_region_dvqm_segments.py` 的既有预处理、原生配置标量、首指针初值0和无gate-pointer协议，不修改原生函数或安装资源。

36项Python测试通过；Debug全解决方案构建0警告、0错误。既有467份evidence JSON哈希保持。没有启动/部署Editor，没有恢复制作算法或改动此前证据。

## 6. 剩余边界与可选后续

本轮盘点已完成。以下是可选的新验收工作：

| 可选项 | 还缺什么、能回答什么 | 停止条件 |

制作来源、原始录音者、bit17非零生产公式继续保留未知并搁置。本批样本也不足以断言所有V5都没有其它表情机制，或证明Attack/Release是EVEC直接后继实现。
