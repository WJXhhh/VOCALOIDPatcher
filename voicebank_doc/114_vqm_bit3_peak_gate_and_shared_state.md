# bit13内部3：双极峰门限及共享状态

2026-10-15。本轮在已经识别的原始特征入口中找到内部3的明确计算赋值和状态消费，补充[113](113_vqm_bit7_pitch_consumption.md)保留的字段解释缺口。**内部3在该路径中是原PCM窗口双极峰门限的0/1结果，不是能量或清浊概率。** V4X保存值恒1与此结果相容，但原商业配置及原制作调用尚未确认。

本轮实际Ghidra元数据/函数查询仍为`vocaloid`中的`/v6/DSE.dll`，x86-64，基址`0x180000000`，SHA-256 `7a4965bd377dbc2b08710e807ae1345b67d9fff6579ca0c01a769f744366f5b5`。以下地址均为RVA。没有重扫DLL、重新导入或启动Editor。

## 一、赋值和消费数据流

| 阶段 | RVA/位置 | 已确认内容 |
| --- | --- | --- |
| 原始特征调用 | `0xD2CC0`内`0xD3329 → 0xD92E0` | 正常原始特征入口，复用既有环缓冲/特征生产对象 |
| 清理与使能 | `0xD92E0` | 清零552字节Feature、内部4置−1；配置曲线ID23大于0才计算原始字段 |
| PCM极值 | context `+0xAE0/+0xAF0/+0xB00/+0xBB0` | 环缓冲当前2×hop窗口内取最大原样本与最小原样本；门限使用未去均值的极值 |
| 门限来源 | `0xD9A52..0xD9A89` | 配置`+0x510/+0x514`，分别对应getter ID88/89；按模块全局状态是否为0选择 |
| 写内部3 | `0xD9A9D`写1，`0xD9AAD`写0 | 写`Frame+0x128 → Feature+0x10` |
| 真实状态消费 | `0xD9AB0..0xD9AD7` | 读回内部3，将全局`0xAA9AB8`更新为该0/1结果，从而改变后续调用的门限选择 |

默认配置构造`0x90DE0`实际给两门限2600、3400。它们是整数配置，在比较前经过原生int/float转换；本文只验证所列正常范围，不把极端整数溢出或NaN输入列为有效音频协议。

令前一共享状态为`q`，原PCM窗口为W，开启原始特征时：

```text
q == 0：T = config[+0x510]；否则T = config[+0x514]
P = max(-100000, max(W))
N = -min(100000, min(W))
bit3 = 1 当且仅当 P >= T 且 N >= T；否则为0
下一共享状态 = bit3
```

极值初值为±100000，普通PCM16幅值在此范围内。**两侧都要达到门限，等值通过**；只出现一个很大的正峰或负峰，不等价于双侧通过。它也不先减均值，所以大DC偏移能使另一侧失败。门限单位是该原始PCM缓冲的幅值单位，本轮自有样本采用PCM16量级。

若配置曲线23关闭，Feature被清理后内部3为0，但这段门限/全局更新不执行，原共享状态保留。这里的“关闭”不是声音静音，而是原始特征计算使能。

## 二、数值及状态验证

新增[475证据](evidence/475_vqm_bit3_peak_gate.json)及[验证器](../voicebank/tools/verify_vqm_bit3_peak_gate.py)。它调用**完整原生`0xD92E0`**，不重定位内联块或替换分支；全部PCM、配置、Frame和环缓冲由测试自建。只在独立进程设置/恢复该模块的共享状态，不改安装文件或其它进程。

1,008个独立用例覆盖14种信号、3个环位置、6组门限、两种前状态及使能两值。包括：

- 静音、正/负DC、单侧脉冲、非对称双极信号及只在窗口最后一个样本出现负峰。
- 2600/3400的等值与相邻float32值、中间幅度3000。
- 默认门限、反向门限、相同门限、零和负门限。
- 物理起点0、1、63，其中63跨越64点环尾。

**1,008次字段值和下一状态均精确；源环缓冲保持。** 另有18次连续调用覆盖默认中间幅度、反向门限序列及两个独立分析context交替；这些序列只在开头设置一次共享状态，后续直接使用上一原生结果，不逐次重置。

默认2600/3400下，3000幅度的双极信号从状态0开始，六次结果为 **1、0、1、0、1、0**。这是代码及动态结果，不是常规“进入门限高、退出门限低”的滞回。反转两门限时才出现另一种保持/切换行为。因此只称它为“依前状态选门限”，不凭习惯给它命名。

共享状态是模块中的同一全局地址；一个context的结果会影响另一个context下一次采用的门限。线程竞争、同步和宿主调度未验证，不把这项测试延伸为并发安全结论。测试结束恢复原全局值。

## 三、原始字段到最终分析Frame

原始入口会把内部标志清为0：直接看到`Feature+0x10=1`还不能据此声称最终启用了内部bit3。475另用完整批处理入口`0xD9B10`验证这一边界。

两组自有220Hz正弦PCM各16,384个样本、峰幅分别1000和5000；采用既有模式4、手动220Hz协议。两次共128个最终Frame；每组排除首尾各12帧后，40个内段Frame全部携带外层13及内部3标志，字段分别全部为0、1。**80个内段Frame全部符合峰门限预测。** 没有把未测试的边界Frame算成精确重建，也未注入最终特征结果。

这一组结果证明原始计算能够进入最终启用特征的Frame，不只是未启用工作槽。既有通用序列化/加载证据继续适用，不重复其测试来增加本轮数量。

## 四、范围与剩余未知

本轮完成已识别原始入口中内部3的计算、真实共享状态消费、边界及最终Frame保留。未据此确认所有DSE分支只使用这一含义；对`0xD2CC0`及既有`0x31830`的直接指针候选检查也不是完整别名/索引覆盖，不能用“没有另获候选”证明其它消费者不存在。

V4X恒1的字段现在有可运行、可独立预测的生产规则，但商业门限、原始前置PCM及跨调用初态没有来源证据，**不宣称恢复原制作配置或逐帧原调用**。它与内部19默认清浊概率核分开，不能把两个字段互换。

bit13仍有制作相关知识边界：V4X内部7负常量来源、内部17单位/非零初始生产、原评分、零数组及未保存边界。VQM音高加载/已测消费已经交付，part pitch1原选值和pitch2制作赋值连接仍未知。上述未知不升级为原四项加载/消费交付的前提，也不因为当前未找到就写成DLL内不存在。
