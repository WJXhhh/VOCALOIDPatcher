# 源能量控制量与原生相位生产直接比较

接续 [88](88_frm2_source_phase_controls.md)。已解决该文末尾的原始特征观察阶段错误，
并将自有 PCM 推导的控制量接入原生相位生产对照。目标 DLL 哈希沿用第88轮。

## 字段覆盖的实际位置

原始特征函数 `0xd92e0` 先产生归一化能量及 level。
相位分析路径随后在 `0xd3a7c` 覆盖 feature+4，在 `0xd3b88` 覆盖 feature+c。
后者从该路径准备的采样缓冲取中央区间，按 float 平方、顺序累加后除以区间参数；
这次写入没有原始特征的两次 1/32768 缩放。
因此第88轮中 0.0134213 对 13663494 的比较发生在不同处理阶段，不能当作原始能量公式反例。
这不等于已完整还原覆盖路径的窗口及所有字段。

修正后的观察器有显式 phase_stage 模式：该模式记录 feature4/12 与原始预测的差异，
不把已覆盖字段用于原始公式断言；feature8 仍严格比较。
level、derivative 和有效分类项仍逐帧与原生值直接对照。
模型始终使用自有 PCM 的原始能量预测，不使用被覆盖的原生 feature12。
默认原始阶段的三个字段断言保持不变。

## 验证范围与结果

相位 harness 保留 `0x7d=1`，注入自有谐波；原生 F0 仍是显式输入。
每个原始帧从自有 float32 PCM 计算控制量，按帧身份传到最终相位处理，
Python 独立维护原点、锁定、对齐、差分和修正历史，从零状态比较原生生产结果。
没有把原生相位或包络读回作为下一帧预测状态。

24 组覆盖 6 种谐波/静音情形、256/512 hop、80/220 Hz，分类特征关闭：

| 比较 | 数量 | 最大误差 |
| --- | ---: | ---: |
| 原始帧相位控制量 | 1,692 帧 | 0 |
| 相位原点 | 1,572 帧 | 0 |
| 对齐相位 | 42,840 槽 | 0 |
| ENV 横坐标 / 纵坐标 | 各 45,172 点 | 0 |
| 跨帧修正 | 42,840 槽 | 0 |
| 已定义差分状态 | 42,574 槽 | 0 |

包含 144 次无声推进、1,150 次非零修正值观察。锁定状态及有声计数也逐帧断言。
证据：[89_source_phase_producer.json](evidence/89_source_phase_producer.json)。

```powershell
python voicebank/tools/verify_frm2_phase_pipeline.py --dll 'C:\Program Files\VOCALOID6\Editor\DSE.dll' --source-controls --output '../VOCALOIDPatcher-research-work/frm2/source_phase_89_full.json'
```

启用分类特征的 stable/256/80 样例触发“分类数组非零”，所以 source-controls 入口
明确要求 features=0；原有使用原生特征作输入的48组模式仍保留。
启用特征的生产算法尚未还原，不能把本次24组结果外推到该分支。
原有 stable/256/features=1/80 路径另行复验通过，证明原验证模式仍可运行。

本轮完成控制量到相位生产的直接比较，但谐波为自有注入序列、F0来自原生。
第88轮源PCM提取与479帧联合保存链保持独立证据，不能宣称本次已经将那批完全相同的
自动F0/谐波序列重放进相位生产，也不能据此宣布商业制作预设恢复。
两个改动工具通过语法检查。没有使用 Windows Temp、修改安装 DLL 或启动 Editor。
