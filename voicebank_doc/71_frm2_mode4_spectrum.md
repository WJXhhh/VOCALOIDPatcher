# 模式4频谱准备：时域缓冲直接参与卷积

2026-09-14。目标DSE哈希与文档69、70相同；当前Ghidra程序元数据已重新核对。
本轮把文档70的定位推进到频谱准备环节，未更改DLL或生产默认配置。

## 现场数据与独立重放

复用文档70的三个自有稳态信号，每个取三个时刻，共9份准备PCM。
每份705点，采样率11,025Hz，扩展因子1，窗口kind10。
除PCM外，在原生step返回后读取估计器+a8的513个标量谱值。

先完成整个批量调用并保存结果，再与无观察器的对应完整输出逐帧比较。
三组均完全一致。此后才使用这个已经完成的实验对象的变换缓存，
把捕获PCM单独交给ed230；不在运行中的批量分析内重放或覆盖中间输出。

调用契约来自fb4a0的fb80d–fb855：变换对象位于估计器+8，
PCM位于+190、长度+2c、窗口kind+144、扩展因子+140，输出模式2、居中参数1、
最后一个float参数为+188处的内部采样率。ed230返回半长512及1024个packed数值。

**9份重放的4,617个标量值与现场数据逐项完全一致。**
这确认后续研究的是现场实际经过的频谱准备结果，而非另设条件得到的相似对象。

## 两个候选的数值对照

从ed230反编译和实际对象取得实核卷积关系，并独立实现为`frm2_mode4_spectrum.py`。
核系数、每个bin的核选择以及最初窗系数仍从原生对象读取，作为模型输入；
没有宣称已经独立恢复核生成算法，也没有将这些表保存到仓库。
后续[文档72](72_frm2_mode4_kernels.md)已经取消该依赖：kind10核构造和组选择独立恢复，
55组矩阵全部一致，并重新验证本页9份现场数据。此处保留当时的分阶段证明方法。

当前数据的核宽41、核组数75。对输出bin i、核槽j：

1. 令k=abs(i-center+j)，若k>half则k=N-k，执行一次反射。
2. k=0取packed[0]；k=half取packed[1]；其它位置取packed[2k]和packed[2k+1]。
3. 分别乘对应实核系数、顺序累加实部和虚部，每次乘法、加法按float舍入。
4. 输出DC和Nyquist实值放在packed[0]/[1]，其它bin按实/虚交错。
5. 标量输出首尾为绝对值，中间为实部平方加虚部平方，保留各步float舍入。

比较的两个候选只在卷积输入上不同：

- **时域候选**：PCM乘初始窗，按原生居中/补零规则排成1024个float，直接按上述packed格式卷积。
- **DFT候选**：对同一加窗、居中缓冲先做独立DFT，转换为相同packed约定后，再使用同一组核卷积。

| 对照 | 数值数量 | 最大差 |
| --- | ---: | ---: |
| 时域候选 → 原生packed输出 | 9,216 | 0 |
| 时域候选 → 原生标量输出 | 4,617 | 0 |
| DFT候选 → 原生packed输出 | 9,216 | 各快照40.310399–90.063858 |

DFT候选使用前面窗/FFT研究中的独立实现；Nyquist正确转换到packed[1]，
没有混用现代CCS数组的布局。零误差检查和现场重放一致性均由工具断言。

因此，在本DLL、kind10及当前配置的实际路径中，**卷积输入等价于加窗居中的时域缓冲，
并未先进行通常预期的DFT**。这不是仅依据“反编译没有看到FFT调用”的猜测。
文档70当时保留的这一疑点，现在有直接的数值判别。

## 对自动音高反例的解释及限制

输入PCM的主频仍正确，但ed230结果已不等于“DFT后再执行该卷积”的频谱。
按下游频率轴解释其最大局部峰，会出现高频位置的强峰；例如220Hz样本的一份快照
最强局部峰位置约5383Hz，而最终音高中位数约127.66Hz。
不要将这些位置称作输入信号真实存在的谐波，也不要期待最终F0等于最高峰。

这定位了候选选择之前的一项具体数值偏离，能够解释为何不能把此路径当作正常频谱估计基线。
它尚未证明只补一个FFT就会恢复正确F0：核生成本身仍使用原生数据，候选、清浊及跨帧修正
也未完成独立恢复；文档70中+5c4=4改走另一入口仍无正音高的反例继续保留。
结论不推广到kind15的复核分支、其它配置、其它DLL版本或厂商原始制作环境。
