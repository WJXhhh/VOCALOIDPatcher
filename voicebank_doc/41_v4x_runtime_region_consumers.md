# V4X ART region 的运行时消费证据

2026-09-13，接续文档39、40。本轮从读取器追到帧处理路径，确认四组region
不是仅供保存的元数据；尚未恢复完整选择算法，也没有进行宿主内合成实验。

## 目标与取证范围

复用用户已打开的Ghidra GUI项目，成功查询当前Program元数据并反编译已知读取器：

- Program：`DSE.dll`，项目内标识 `/v6/DSE.dll`；x86 little-endian 64-bit。
- 映像基址 `0x180000000`。
- SHA-256：`7a4965bd377dbc2b08710e807ae1345b67d9fff6579ca0c01a769f744366f5b5`。
- 安装文件的只读SHA-256独立吻合。以下地址只适用于该二进制。

查询仅使用只读元数据、反编译、反汇编、交叉引用。另在安装文件中读取有限虚表
及扫描候选位移字节，再用Ghidra确认；位移字节命中本身不作为语义证据。
没有修改或复制专有代码，没有导入、保存或修改Ghidra项目。

## 从读取到处理的连接

`0x180110b70` 设置ARTp虚表为 `0x180226908`，该虚表 `+0x20` 指向
已知读取器 `0x180110d50`。读取器将每组四整数写入part的alignment vector：
`+0x1d8` 是begin，`+0x1e0`是end，每组16字节。

`0x1801757a0` 使用当前工作项 `+0x20` 的part指针，先装载选中的帧，
随后遍历上述vector，查找满足 `outer_start <= frame_index < outer_end` 的组。
找到的region索引传给 `0x1801722c0` 和 `0x180172e30` 两条有条件启用的处理路径。
交叉引用显示 `0x180165350`、`0x18016a250`、`0x18016a870` 等帧调用路径调用它。

这里确认的是静态控制流与字段连接；不是通过编辑器录制的调用轨迹。

## region奇偶决定当前检查哪一侧

`0x1801757a0` 按region索引奇偶和工作项 `+0x12c` 的方向标志，
在工作项 `+0x10`、`+0x14` 两个音素ID之间选择，然后查询PHDC的 `Silence` 类别。

| region索引 | 方向标志为0 | 方向标志非0 |
| --- | --- | --- |
| 偶数（0、2） | +0x10侧 | +0x14侧 |
| 奇数（1、3） | +0x14侧 | +0x10侧 |

命中Silence且当前帧有bit9时，该分支清除bit9并将F0字段置为无音高哨兵，
再调用帧字段处理函数。表明region的奇偶参与帧级音素分类处理。

不能由此推论每组就是一个独立音素，也不能把方向标志未经核实地命名成UI参数。
四组可以按0/2、1/3分为两种处理侧，但具体声学阶段还没有完整定名。

## 四组素材有独立查找分支及回退

`0x180172e30` 在ART分支中检查原part的vector大小是否为64字节，即四组。
若是，利用工作项 `+0x70` 的字符串序列构造三级查找：

1. `voice/articulation/规范化后的第一个token`；
2. 中间key以 `^` 开头，后接规范化后的第二个token；
3. 再查规范化后的第三个token。

这里的规范化由 `0x1801253b0` 完成，其全部规则本轮没有展开。
如果三级查找失败，或结果没有part（`+0x150 < 1`），退回普通双音素查找。
随后从候选part中按pitch1相关代价选择一个素材。

这比“发现三音素目录”更进一步：四组素材在该处理路径中有专门查找和空素材回退。
但该函数有启用条件和另一声库查询上下文，不能把这条回退推广成所有普通合成入口。
也不能认为任意缺少的双音素key都会自动由图路径补齐。

## 不同region数量之间的映射

同一函数在选定另一个part后比较两边vector长度：

- 长度相同，目标region索引保留源索引；
- 长度不同，非负源索引映射为 `index % 2`。

因此在四组到两组的这条路径中，映射是 `0→0、1→1、2→0、3→1`。
这不是把四组按前两组/后两组合并；也不是按三个音素平均切分。
不能据此声称任意组数的组合都受支持，目标part有效性及调用条件仍须满足。

关键反汇编已交叉核实：`0x180173731–0x1801737af` 读取双方vector，比较长度，
按有符号余2规则调整索引，并取四个区间端点；不是仅凭反编译器变量名判断。

## outer和inner控制分段线性时间映射

源组记为 `[O0,O1)`、`[I0,I1)`，目标组记为 `[P0,P1)`、`[J0,J1)`。
对源组中的整数帧位置x，该路径分别映射三个区域：

| 源位置 | 映射锚点 |
| --- | --- |
| x < I0 | O0→P0，I0→J0 |
| I0 <= x <= I1-1 | I0→J0，I1-1→J1-1 |
| x > I1-1 | I1-1→J1-1，O1-1→P1-1 |

每段使用两锚点间的线性比例。端点要减1是因为保存的是半开区间，
而映射使用实际最后一帧。不能用 `inner_end` 直接当作最后一帧。
源inner只有一帧时，中段直接映射到目标inner起点，避免除零。
映射后按整数帧及相邻帧加载；有小数部分时进入后续帧插值处理。

关键运算已在 `0x1801737b2–0x180173857` 的比较、减1和浮点除乘指令中核对。
这是inner参与时间变换的证据，仍不等于证明inner必然具有某种声学“稳定性”。

另一个辅助消费者 `0x1801b0d60` 用选定region计算左右边缘的实际/标注余量：
标注左余量为 `inner_start-outer_start`，右余量为 `outer_end-inner_end`，
并受两个标志控制计入哪侧。它从 `0x1801b1620` 的工作信息生成路径调用，
不能将该辅助输出独立当成合成时长分配算法。
