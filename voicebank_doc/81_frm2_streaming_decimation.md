# 流式FIR抽取、系数选择与源PCM音高链

2026-09-15，目标元数据重新核对为GUI `/v6/DSE.dll`，SHA256与文档80相同。
本轮全部使用自有信号；原生库、系数表和Ghidra项目只读。

## 滤波器构造是资产选择

`103b00` 根据输入采样率和抽取因子选择固定内置系数表，复制到对象系数缓冲。
这里没有观察到现场设计FIR或从截止频率计算系数的算法。
模型 `frm2_decimator.py` 独立实现选择关系，在哈希固定的本机DLL中读取所选资产，
再与真实构造器的结果逐值比较。仓库只保存地址/长度映射，不保存专有系数向量。

| 输入采样率 | 抽取因子 | 系数数目 |
| --- | --- | --- |
| 11025 | 2 / 4 | 46 / 58 |
| 22050 | 2 / 4 / 8 | 12 / 92 / 106 |
| 44100、48000 | 2 / 4 / 8 / 16 | 12 / 110 / 222 / 579 |

这13种组合均已通过构造器对照。模型对未列组合拒绝处理，未复刻原生可能不完整的分配路径。
这说明受测路径的系数**如何选取**已确认，不表示已经恢复这些滤波器最初的设计参数。
它仍需要合法本机DLL中的外部系数资产，不能称为无DLL依赖的独立实现。

## 流式数值规则

`103f00` 每累计D个源样本产生一个输出：新样本组倒序放在滤波历史开头，
旧历史后移D项；按系数顺序逐项执行 `sum=f32(sum+f32(sample*coefficient))`。
未满D个输入时保留待处理组，不输出、不清空。初始滤波历史为零。
输出个数取决于此前未满组的状态，不能在每次输入块上单独做整除后丢弃余数。

`verify_frm2_decimator.py` 对上述13种组合分别测试128点块、
1/3/7/31/129交替块、2048/19交替块；包含前导静音、脉冲、确定性随机信号和尾部静音。
39组、28,509个输出严格零误差。每次调用均比较整个滤波历史和未满组计数，
并验证模型的分块与一次输入结果相同。系数选择也与构造器严格一致。

## 从源PCM接回完整F0链

`DecimatedSource` 从自有源PCM（尾部按实际请求补零）推进滤波状态，
用原生调度提供的输出计数和环位置映射取出窗口。原生降采样环仅用于逐样本比较，
预测不再从其中读样本。后续窗口提取、去均值、频谱、评分、候选、概率、
历史、五帧修正及谱峰加权重估保持文档80的模型。

36组批量矩阵重新通过：1,764个音高阶段、1,243,620个准备PCM样本严格一致，
最终1,584帧F0全部通过，最大误差仍为8.490215805e-6Hz。
独立滤波器输出也在每个被提取窗口上与实际降采样环严格比较，
未用原生准备PCM或降采样PCM回填模型。

本次完整矩阵显式复用DSE/MKL FFT底层，系数资产显式来自本机DLL；
不能把上述结果称作完全独立FFT或完全独立数值资产。
文档78、80的两个纯Python FFT反例仍保留，本轮没有修改其容差或筛选规则。

## 仍未完成

默认源PCM到最终F0已不再依赖原生中间PCM、功率谱、峰表、候选和历史值。
但仍依赖原生调度（帧时间、环几何、累计输出计数等），以及上述FFT底层和固定系数资产。
整块普通FRM2研究还需要将实际批量谐波跟踪、共振拟合和最终保存接成完整制作链，
并核对未覆盖配置；没有把“F0链通过”当成“FRM2完整生成通过”。
