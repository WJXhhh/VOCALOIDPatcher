# 普通 FRM2：相位插入边界与测试初始状态

2026-09-15。范围仍是“普通 FRM2 的精确数值语义”。

## 本轮修正

相位参考的低频幅度扫描按槽顺序，从第二槽开始，最多检查前十槽；遇到首个大于 1600 Hz 的正频率立即结束，不能跳过去继续收集后面的低频槽。旋转排列暴露了旧模型的错误。依据为 DSE RVA `da730`，独立模型已修正。

相位 ENV 每次插入即排序并覆盖同坐标节点。后续差值累计读取最高的内部节点，排除 x=1 端点；最终左端点复制排序后的首个正坐标节点，右端点复制倒数第二个节点。无有效谐波时两个端点为零。重复、倒序、越过右端点等情形不能按最后插入槽处理。依据为 `d79c4`、`d7ae5` 附近的节点读取、插入接口以及 `61500` 的复位行为。

## 暴露出的测试边界

未明确初始化历史的旧 harness 在 attack/220 Hz 重放中出现不稳定原生结果：参考相位和对齐相位仍为零误差，ENV 却在重复运行时出现不同的极端值，曾到达正负 20000 的容器限值。因此文档94的一次通过不能证明该输入在旧初始条件下可稳定复现。

构造器 `cdde0` 为 context+0xa78 分配 0xaf0 字节（700 个 float），没有初始化；较晚首次激活的槽可能在局部修正路径读取尚未写过的差值历史。现在 harness 在私有对象构造后将这700槽置零，与独立模型的初始状态一致。报告的 `runtime_profile.injected_delta_initialization` 明示此操作。它是受控重放的初始条件，不是修改安装 DLL，也不是恢复了商业制作流程的初始化约束。源F0重放原有的可选音高改写旁路仍然保留，见文档94。

## 验证

9组、783帧覆盖倒序、重复频率、逐帧旋转、右端点、超过右端点、仅右端点、全无效、稀疏和第10帧延迟激活。23,490项对齐相位、23,490项修正、20,860项有效历史差值及17,042个ENV点均为零误差。高于Nyquist的输入只检验数值容器行为，不表示有效音频。

完整源信号回归覆盖36个信号、两种特征模式，共72次重放、3,168帧，95,760个相位ENV点全部零误差。attack/220 Hz另做3次独立进程重复验证，全部通过。[机器可读证据](evidence/95_phase_insertion_and_replay.json)包含全部结果及初始条件。工具为 `voicebank/tools/verify_frm2_phase_insertion.py` 和 `verify_frm2_source_phase_replay.py`；所有PCM及运行输出放在仓库旁的研究目录，没有使用 Windows Temp。
