# 模式4实核构造与频谱输出的独立恢复

2026-09-14，DSE哈希同文档71，重新核对当前Ghidra程序。
本轮取消文档71模型对原生核数组的依赖：预测只使用准备PCM、长度、内部采样率、
扩展因子和窗口类型。原生数组仅用于核对，不进入预测计算。

## kind10、居中路径的核构造

以下每个float中间运算按工具中的f32舍入；N为由输入长度和扩展因子算出的变换长度，
H=N/2。这里只对本轮覆盖的有效尺寸及扩展因子1作通过声明。

- 核宽为`int(f32(f32(factor*40)+1))`，中心为`(width-1)//2`。
- 高频目标窗长为`int(f32(f32(Fs*1024)/44100))`。
- 频点间距为`f32(f32(Fs*0.5)/H)`，转接起止点分别为`floor(f32(200/spacing))`、
  `floor(f32(1000/spacing))`。
- bin位于起点及以前时使用输入窗长，终点以后使用目标窗长，中间按索引线性混合。
  混合结果截零取整，然后`L = L - L%2 + 1`强制为奇数。
- 只在相邻bin的L变化时新增一组核，bin保存其组索引，不按每个bin独立分配。

每组核先由L构造kind10解析窗：四项余弦组合`0.47 - 0.45*cos(a) - 0.01*cos(2a) - 0.01*cos(3a)`，
a步长为2π/(L-1)，各点和累计归一化遵循已有窗函数模型的float规则。
设m=(L-1)/2，将窗的前m点放在N点缓冲末尾，其后m点放在开头，其余为0，最后一个窗点不复制。
实核槽j直接取该缓冲的`2*abs(j-center)`位置，除以扩展因子。
这里同样没有先对窗缓冲执行DFT；独立模型完整保留本DLL的实际数值行为。

输入PCM的初始窗是kind14矩形窗，系数均为f32(2/输入长度)，与上述分组kind10窗不同。
此后按文档71的居中准备、实核卷积及标量打包规则计算。
模型位于`frm2_mode4_spectrum.py`，kind10窗解析公式复用此前独立窗实现，不读取原生查表。

## 矩阵验证

独立原生变换对象覆盖内部采样率8,000/11,025/16,000Hz，以及输入长度257/353/513/705。
每个有效组合使用零、常量、脉冲、固定随机种子信号、自有五谐波信号。

| 核对项 | 比较数 | 结果 |
| --- | ---: | --- |
| 核系数 | 98,195 | 最大差0 |
| packed输出 | 33,280 | 最大差0 |
| 标量输出 | 16,695 | 最大差0 |
| 核组长度、每bin组索引、核宽和中心 | 55组调用 | 全部严格一致 |

系数比较数包含同一配置在不同信号上的重复核对，不代表有98,195个不同核系数。
所有预测均由独立生成的窗、核和组索引驱动；对照时读取的原生数组不替换任何预测输入。

明确排除16,000Hz/257点组合：它将产生371点核窗，而N只有256，超出本模型已经建立的
居中缓冲边界N+1。首次扩展实验由Python边界检查拒绝，随后将该组合记录在证据的排除项，
没有调用原生函数去猜测越界行为。其余11个配置×5信号共55组通过。

原生缓存重建条件检查长度、kind、扩展因子，未包含采样率。因此矩阵每个采样率使用新对象，
不把改变参数却复用旧缓存的行为混入数值规则。本轮没有验证跨采样率缓存复用契约。

## 与真实批量路径再次衔接

文档71捕获的9份现场准备PCM也重新运行：初始窗、75组×41项核以及全部组索引
现在由独立模型生成。9,216个packed输出和4,617个标量输出仍为零误差，
单独重放与现场输出仍严格一致，观察器与无观察器的完整批量结果仍一致。
所以“还需要拿原生核系数作为输入”不再是这条受测路径的缺口。

这恢复的是本DLL实际执行的频谱数值流程，不是修复成另一种预期算法。
候选选择、清浊门限和历史修正仍未独立恢复，模式4的最终音高反例没有被宣布修复；
其它窗口、扩展因子和制作配置也未由这55组验证代替。
