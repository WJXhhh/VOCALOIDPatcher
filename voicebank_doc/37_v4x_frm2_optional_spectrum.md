# V4X FRM2 的可选频谱段（2026-09-12）

> 后续补充：新帧的 VQMp 归属和全库引用一一对应已在[下一轮审计](38_v4x_reference_audit_and_next_steps.md)确认。下文保留本轮当时的证据边界。

## 结论与证据边界

本机 8 套 Miku/Rin V4X 均包含 `0x00000000000e2287` FRM2。
旧解析器只接受中文参考库的 `0xe22b7` VQM 布局，因此在这些帧处报告
unsupported mask；这不是声库损坏。两者相差 `0x30`，即位 4、5。

当前 Ghidra 活动目标 `/v6/DSE.dll` 为 x86-64、小端、映像基址
`0x180000000`。其 SHA-256 与本机安装文件一致：
`7a4965bd377dbc2b08710e807ae1345b67d9fff6579ca0c01a769f744366f5b5`。
以下地址仅适用于该二进制；查询均只读。

- 读取器 `0x1801363a0` 在 `(mask & 0x30) == 0` 时跳过整个频谱段，
  包括 `u32` 计数；并非读取零计数后跳过数组。
- 写入器 `0x180138560` 有对应的跳过分支。
- 现有正弦分量、F0、位 13 特征块、位 18/19 控制字段及两个 ENV 的顺序
  不变。新布局用空 spectrum 元组表示不在文件中的数组，序列化不写计数。
- 本次没有按 DDI 的 VQMp/EpR 引用验证这些帧的树归属，故这里只确认
  VQM 帧布局家族的变体，不由掩码单独推断 EVEC 功能或 Growl 生成算法。

`probe_frm2.py` 仍只接受四个已验证的精确掩码；没有开放任意位组合。
原有 `0xe22b7` 常量和接口保留。

## 实体文件全量验证

`probe_ddb.probe` 检查顶层块、SND 头及边界，`probe_frm2.scan_file` 独立
检查 FRM2 内部数组与 ENV 边界。两路的文件末端及掩码统计逐库一致。

| 文件 stem | 字节 | FRM2 | SND | `0xe2287` |
| --- | ---: | ---: | ---: | ---: |
| MIKU_V4X_Original_EVEC | 2,374,247,876 | 223,384 | 5,848 | 246 |
| MIKU_V4X_Sweet | 599,658,226 | 56,258 | 1,603 | 246 |
| MIKU_V4X_Soft_EVEC | 2,019,891,602 | 191,473 | 4,979 | 246 |
| MIKU_V4X_Dark | 660,424,322 | 62,876 | 1,607 | 246 |
| MIKU_V4X_Solid_EVEC | 2,120,684,428 | 195,903 | 4,580 | 246 |
| RIN_V4X_Warm | 484,848,872 | 44,947 | 1,170 | 246 |
| RIN_V4X_Power_EVEC | 1,503,705,306 | 139,342 | 3,627 | 246 |
| RIN_V4X_Sweet | 508,245,514 | 47,394 | 1,179 | 246 |
| 合计 | 10,271,706,146 | 961,577 | 24,593 | 1,968 |

所有 SND 均为 44,100 Hz、单声道，通过现有 PCM16 长度约束。
本批仅出现 `0x2000e00207`、`0x200`、`0xe2287`，没有 `0xe22b7`。
全部 1,968 个新布局帧均完成 parse→serialize 逐字节比对；另外每库抽查
前三个普通帧和前三个无声帧，共 48 帧，全部一致。没有提取或保存商业 PCM。

每库新布局帧的块长范围均为 5,494–5,774 字节，总长均为 1,385,652 字节。
这只证明尺寸统计一致，本轮未比较跨声库 payload 是否相同。
每库首个新布局帧均测得 350 个正弦分量、feature flags `0x1fffff`、544 字节
特征负载和控制值 `0 / 10 / 2049`。这些是首帧抽样结果，不推广为全部帧常量。

尤其是位 19 控制值仍为 2049，而文件完全没有频谱数组。因此旧中文样本中
它与 `M` 相等只是该批数据的观察，不能用来决定是否读取频谱或重建缺省数组。

## 复现与回归

将 `$ddb` 设为本机实际安装的目标 V4X DDB 路径：

```powershell
python -B voicebank/tools/probe_ddb.py $ddb --json
python -B voicebank/tools/probe_frm2.py $ddb --scan --json
# 示例：MIKU_V4X_Sweet 的首个新布局帧；其它文件不能复用该偏移。
python -B voicebank/tools/probe_frm2.py $ddb 0x23a6fe08 --json
python -B -m unittest discover -s voicebank/tools -p test_probe_frm2.py -v
dotnet build VOCALOIDPatcher.sln -c Debug --nologo -v quiet
```

新增纯合成 fixture 回归覆盖两种 VQM 布局、所有负载截断位置、跨帧越界、
超大数组计数、mask/数组不一致和未支持掩码；5 项测试通过。
完整 Debug 解决方案构建为 0 警告、0 错误。
本机没有旧 V5 实体文件，旧 `0xe22b7` 本轮仅做合成回归，未重跑旧商业样本。

本轮不包含 DDI 引用全集核对、原生重新加载或宿主试听；没有部署或启动编辑器。
后续应继续核对 VQMp 归属及缺省频谱时的合成消费者，再研究位 13 特征的生成规则。
