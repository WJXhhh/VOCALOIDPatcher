# bit13内部8：插值边界、下限及配置来源

2026-10-15，承接[111](111_vqm_bit8_reference_and_pcm_delivery.md)。111明确留下的两处局部问题——内部8端点/插值边界及context参考标量来源——本轮已有数值和来源证据。没有扩大到其它DLL或原商业制作器，没有修改旧证据。

目标仍为同一SHA-256的x86-64 `DSE.dll`：`7a4965bd377dbc2b08710e807ae1345b67d9fff6579ca0c01a769f744366f5b5`，映像基址`0x180000000`。本轮Ghidra实际元数据查询确认`vocaloid`项目的`/v6/DSE.dll`，并成功查询已识别调用者和构造函数。以下均为RVA。

## 一、内部8的端点/插值规则

[472证据](evidence/472_vqm_bit8_interpolation.json)及[验证器](../voicebank/tools/verify_vqm_bit8_interpolation.py)执行原生`0x35843..0x35964`（末端不含），保留对绝对值`0x2880`及Hz→cent `0x2890`的真实调用。输入为自有Frame、Feature、context和明确的局部寄存器值，原DLL指令不改。

令两个端点内部8为`A/B`，权重为`t`。先将A复制到输出；第二端点存在、局部使能非零、且`t>0`时：

```text
D = f32(B - A)
若 abs(D) < threshold：R = f32(f32(D × t) + A)
否则：t < 0.5 时取A；t >= 0.5 时取B
```

**阈值比较是严格小于，达到阈值就选端点；0.5选B。** 没有第二端点、局部使能关闭或`t=0`则保持复制A。以上仅定义这段参考音高计算，不把它改称通用Frame插值器或bit17插值。

473的函数内控制流回溯确认：`RBP+0x74`在这里的直接到达定义只有`0x33201`，来自`0x331F9`加载常量`0x5BFD24`，值为**600cent**。较早`0x321E2`写入的260在这一使用点已经被覆盖。因此472同时测260/600是输入对照；不代表此处真实调用者随机选择两种阈值。

472覆盖8组端点、5种权重、2个阈值、3种使能/端点状态、2种guard、2个context标量及2种输出Frame F0，共**1,920组**。包括260和600的等值，以及600的float32左右邻值。输出参考值和Frame F0均逐位一致，无关对象/字节保持。独立模型分类为复制1,408组、线性192组、A端点80组、B端点240组；这些是模型分类，不冒称程序计数器采样。

## 二、下限判断使用缺失哨兵

同一原生块在插值后还分别调整输出Frame F0和内部8。令`S=context[+0x2E40]`，`L=Hz_to_cent(f32(S×f32(1.1)))`：

```text
若 X > guard 且 L > X，则 X = L。
```

分别对Frame `+0xF0`及Feature `+0x24`执行，写点为`0x35915/0x3595F`。473确认这里的guard低32位为**−FLT_MAX**，不是0：因此零和负cent只要有效，也可进入下限调整，不能简化成“只调整正值”。

来源为`0x31944`从常量加载哨兵、`0x3194D`保存到`RSP+0x58`；到达比较点的寄存器定义均为相同常量或该栈槽的恢复。权重比较前的XMM8为0；中点来自`0x32175`保存的0.5。

472中608组参考值上调、240组Frame F0上调，全部精确。guard=0的另一半输入用于区分两种算式，不认作真实调用者的另一模式。

473回溯限定`0x31830`的8,227条完整解码指令和函数内直接控制流；没有间接跳转。它假定原生调用遵守Win64非易失XMM寄存器约定，只检查直接栈槽写入，**不是跨函数的栈地址逃逸排除证明，也不是完整动态路径覆盖**。

## 三、context参考频率来自配置曲线12

[473证据](evidence/473_vqm_bit8_context_contract.json)及[验证器](../voicebank/tools/verify_vqm_bit8_context_contract.py)补上111未知的赋值边。

| 阶段 | RVA | 数据流 |
| --- | --- | --- |
| 创建渲染上下文 | `0xEB00 → 0x2D1C0` | 原生离线音频入口首次创建context；配置指针后存`context+0x2DE8` |
| 读取配置 | `0x2D93A..0x2D964 → 0x2B050` | 曲线ID12、t=0；该配置的曲线对象位置为`config+0x5D0+12×0xA0` |
| 标量赋值 | `0x2D967` | 将曲线值夹到至少1，写`context+0x2E40` |
| 周期长度 | `0x2D96F..0x2D989` | `floorf(f32(f32(sample_rate/S)+0.5))`写`context+0x2CC8`；采样率来自`+0x2DD4` |
| 后续特征消费 | `0x3591D..0x3595F`、`0x35B28..0x35BF3` | 同一S乘1.1后参与cent下限及内部8参考倍率 |

因此现在可将S称为**来自曲线12的频率下限标量（Hz）**：单位由采样率/周期长度和后续Hz换算共同支持。配置界面的正式名称仍未知；它不是采样率，也没有证据把它等同于当前音符目标F0。

473真实执行构造函数中的`0x2D93A..0x2D98F`（末端不含）。自有配置包含实际原生ENV对象，曲线ID12由真实`0x2B050`读取；用44.1/48kHz及−1000、0、0.5、1、55、110、440、880共**16组**，标量及整数周期全部与独立模型一致，context其它字节保持。该构造算术块没有替换分支条件；块入口寄存器1及0.5由已查构造常量设置。

这验证配置到context的真实计算，**不是完整构造函数调用、商业素材自然产生所有配置的证明或新增PCM对照**。111/471的14次完整原生音频序列继续作为PCM影响证据，本轮不重复它来增加数量。
